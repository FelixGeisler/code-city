= Fixed Metric Acceptance

These closed matrices and examples are inert documentation for reviewing
xref:08-fixed-metric-semantics.adoc[]. They are not executable fixtures, test
scaffolds, analyzer probes, parser or AST assumptions, architecture choices, or
assignments of an enforcement location.

Unless an example says otherwise, its content is already the strict UTF-8,
BOM-removed, LF-normalized content supplied by
xref:06-source-admission-and-limits.adoc[]. A displayed source block that
states an exact byte length has no leading bytes and no final LF after its last
shown source character.

The contract is acceptable only when all of these gates hold:

* every SLOC matrix row has its exact lexical inclusion or exclusion;
* every body-bearing, bodyless, modifier, conditional-top-level, and zero-unit
  row has its stated canonical unit result;
* every included occurrence contributes once, every excluded construct
  contributes zero itself, and nested ownership is exclusive;
* derived counts, complexities, maxima, ties, spans, identities, and ordering
  match the exact examples and canonical-key table;
* all eight suffixes and their ASCII case variants select only the four stated
  syntax families, and every grammar failure has only the accepted atomic
  result;
* reordered admitted modules and repeated evaluation produce the same exact
  canonical facts without excluded fields;
* no example selects analyzer technology, architecture, city behavior, or an
  executable evidence mechanism; and
* `npm run docs:build` succeeds.

`src/low.js` has no final LF and contains:

=== Every included occurrence

`src/all.js` has no final LF and contains exactly one of every included
occurrence, with the `if`/`else if` pair supplying two `if` occurrences and the
six loop spellings supplying six loop occurrences:

[source,javascript]
----
async function all(x, items) {
  if (x) {}
  else if (x) {}
  for (;;) {}
  for (const key in items) {}
  for (const value of items) {}
  for await (const value of items) {}
  while (x) {}
  do {} while (x);
  switch (x) {
    case 1:
      break;
    default:
      break;
  }
  try {} catch {}
  x ? 1 : 0;
  x && x;
  x || x;
  x &&= x;
  x ||= x;
  x ?? x;
  x ??= x;
}
----

The contributions are `2` from `if`, `6` from loops, `1` from the non-default
case, `1` from `catch`, `1` from the runtime conditional, and `6` from the
listed logical/nullish operators and assignments: exactly `17`. `else`,
`switch`, `default`, `try`, and `break` add `0`. Each logical assignment is one
occurrence.

The normalized byte length is `373`. Exact facts are SLOC `24`, unit count `2`,
maximum complexity `18`, and these ordered units:

. `(src/all.js, top-level)`, no span, complexity `1`;
. `(src/all.js, function, 0, 373)`, complexity `18`.

[[required-span-example]]
== Required `src/a.js` span and ownership example

There are no bytes before `function`, no final LF after `}`, and the normalized
source is:

[source,javascript]
----
function f(a = x && y) {
  if (a) return () => a ?? y;
  return a;
}
----

The normalized UTF-8 byte length is exactly `68`, and SLOC is `4`. The exact
ordered facts are unit count `3`, maximum complexity `3`, and:

. `(src/a.js, top-level)`, no span, complexity `1`;
. `(src/a.js, function, 0, 68)`, complexity `3` from parameter `&&` plus its
  own `if`;
. `(src/a.js, arrow, 41, 53)`, complexity `2` from `??`.

The half-open arrow span is exactly the bytes for `() => a ?? y`. Its `??` is
excluded from the parent function's contribution count.

|KEY-06 |Two copies of `(p, function, 5, 20)` |The whole metric stage fails as `Metric processing failed` / `M1-MET-1`; neither copy wins and no facts are published.
|KEY-07 |A body-bearing form with attached decorators or exterior whitespace/comments |Those attached or exterior regions are excluded from its explicit span.
|KEY-08 |A body-bearing form with async, generator, static, private, exported, or other non-decorator modifiers |The modifiers are included in the complete explicit span.
|KEY-09 |A body-bearing form through its implementation body or arrow concise expression |Every token through that body or expression is included; the end remains half-open.
|KEY-10 |Any explicit span |Offsets are zero-based UTF-8 bytes in #442-normalized content, not characters, raw pre-normalization bytes, or source locations from another representation.
|KEY-11 |Keys reached under different parser traversal, locale, concurrency, names, or inferred signatures |The identities and canonical order remain unchanged.
|===

No traversal-generated suffix is permitted in any key.

[[deterministic-facts]]
== Deterministic canonical fact sequence

Consider the same two modules originating in either upstream discovery order:

* `src/a.ts` with empty content; and
* `src/b.js` containing only the empty statement `;`.

In either case #442 supplies the metric stage the same complete admitted
sequence in ascending unsigned-UTF-8 order. Every evaluation, including a
repeated evaluation after either upstream permutation, produces exactly this
canonical sequence:

[source,text]
----
module identity: src/a.ts
SLOC: 0
executable-unit count: 0
maximum complexity: 0
ordered units: []

module identity: src/b.js
SLOC: 1
executable-unit count: 1
maximum complexity: 1
ordered units:
  identity: (src/b.js, top-level)
  kind: top-level
  complexity: 1
----

The `top-level` unit has no span field. `src/a.ts` precedes `src/b.js` by
#442's unsigned-UTF-8 module order. The empty
statement creates `top-level` from syntax alone. Provider order, evaluator
invocation order, concurrency, locale, and repetition change no module, unit,
field, value, or order.
