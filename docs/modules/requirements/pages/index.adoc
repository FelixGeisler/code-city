= Requirements

The requirements module is the authoritative source for Code City product scope
and observable behavior. Architecture documentation explains how accepted
requirements are realized; it does not redefine them.

== M1 baseline

M1 delivers one journey: a user submits one canonical public GitHub repository
URL and receives a deterministic Code City for one automatically selected,
immutable repository revision.

The baseline begins with the input, revision-identity, and user-state contract
from https://github.com/FelixGeisler/code-city/issues/441[#441] and the accepted
source-admission and RA-01 through RA-09 contract from
https://github.com/FelixGeisler/code-city/issues/442[#442]. Decisions for
possible later processing, construction, presentation, and duration limits
remain deferred to their owning issues and the #464 hard gate.

== Reading order

. xref:01-product-scope.adoc[Product Scope] defines the M1 outcome and the
  authoritative non-goals.
. xref:02-stakeholders-and-use-cases.adoc[Stakeholders and Use Cases] describes
  the single user journey and its alternatives.
. xref:03-feature-inventory.adoc[Feature Inventory] shows what is included,
  excluded, or owned by a later M0 contract.
. xref:04-functional-requirements.adoc[Functional Requirements] contains the
  normative URL grammar, immutable-revision identity, and state machine.
. xref:05-acceptance-criteria.adoc[Input and State Acceptance] provides
  documentary Given/When/Then examples for reviewing that contract.
. xref:06-source-admission-and-limits.adoc[Source Admission and Repository Limits]
  contains the closed admission matrix, approved RA-01 through RA-09 inventory,
  bounded classification, and observable category/code rules.
. xref:07-source-admission-and-limit-acceptance.adoc[Source Admission and Limit
  Acceptance] provides documentary scenarios and downstream evidence mapping
  for that contract.

The words *must*, *must not*, *required*, and *only* are normative on these
pages. Examples clarify the normative rules but do not create executable test
fixtures or select an implementation mechanism.
