= Product

== Approved whole-core target

The `CC-CORE-*` references in this module define the approved whole-core target.
They do not claim that the whole target is implemented. Features without
repository and test evidence remain unimplemented. The current application is the transitional browser-only baseline described
below.

The target accepts one public GitHub repository root or explicit branch link,
records one immutable commit on an explicit analysis action, and produces a
deterministic city and investigation for that commit. The Code City server owns source acquisition,
analysis, and the authoritative association of source and results. The browser
owns presentation and investigation. Explicit Save creates an immutable shared
server snapshot; temporary work is not silently saved.

The stable source, metric, and processing requirements are in
xref:source-and-metrics.adoc[Source and Metrics]. City, investigation, failure,
and save requirements are in xref:city-and-failures.adoc[City and Failures].
Accepted xref:architecture:adr/0013-ownership-of-source-acquisition-analysis-and-saved-investigations.adoc[ADR 0013]
fixes the ownership boundary. It does not select a server platform, API, storage
technology, access mechanism, or deployment topology.

== Current implemented baseline

The currently implemented product is a static browser application with no
server runtime or persistence. The following describes current behavior, not
the complete approved target.

[cols="1,3",options="header"]
|===
|Area |Current behavior

|Repository
|One anonymously accessible public GitHub repository

|Revision
|The current head commit of the explicit branch, or of the repository's default
branch when no branch was supplied

|Files
|`.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`, and `.cs`
(ASCII case-insensitive)

|Result
|One deterministic city for the selected commit, with current navigation,
selection, and inspection defined by xref:city-and-failures.adoc[City and
Failures]

|Storage
|Current browser session only; reload clears all current product state
|===

=== Current input

Repository forms:

* `https://github.com/<owner>/<repository>`
* `https://github.com/<owner>/<repository>/tree/<branch-suffix>`

Ignore surrounding spaces, tabs, and line breaks around the repository URL.
Require HTTPS, the literal `github.com` host, valid owner and repository
segments, and exactly one of the forms above. A branch link decodes its complete
nonempty suffix once as one branch name. Reject credentials, a port, query,
fragment, raw backslash, trailing slash, malformed encoding, empty raw or
decoded branch components, and decoded components equal to `.` or `..`. Root
links still reject encoded owner or repository segments and any extra path.
Tags, commit links, blob links, and generic arbitrary refs are not accepted.
* Additional exclusions are optional newline-separated canonical
  repository-relative paths. LF, CRLF, and CR separate lines; empty lines are
  ignored; nonempty lines are neither trimmed nor normalized. Paths must be
  well-formed NFC, preserve ordinary spaces, contain no control characters,
  and satisfy the canonical path rules in xref:source-and-metrics.adoc[Source
  and Metrics]. Exact case-sensitive duplicates are invalid. Accepted paths
  sort by unsigned UTF-8 for the captured attempt.

Only Analyze starts work. Invalid repository or exclusion input starts no
worker and no GitHub request. Editing either field without Analyze starts
nothing and cannot change an active, queued, or completed attempt.

=== Current selected revision

On Analyze, the browser atomically captures the repository, optional explicit
branch, and validated additional exclusions. It resolves the supplied branch
through GitHub's branch namespace or resolves the default-branch head when no
branch was supplied, then processes only the selected immutable commit. It shows
the full commit ID with the result. Commit and raw-source requests use that
commit ID. The recursive-tree request uses the root tree ID validated from
commit evidence. Movement of the branch after selection does not change the
current attempt. A new submission resolves the head again. An unavailable
explicit branch fails without default-branch fallback.

=== Current user-visible behavior

. Before Analyze, the page shows the repository URL and Additional exclusions
  inputs.
. After Analyze, any previous result disappears. The page shows the captured
  fixed and additional effective exclusions as exact inert text, shows that Code
  City is working and offers Cancel.
. On success, the page shows the selected commit ID and one complete city.
  Users can navigate it, identify a hovered building's district in one stable
  contextual row, select any building by keyboard or pointer with persistent
  district context, search canonical module paths by exact case-sensitive
  substring, reveal a matching building, and read its canonical path, full
  district, and exact metric explanation.
. On failure, the page shows a short explanation and no city. It also shows the
  commit ID when one was selected.
. After cancellation, the page shows a cancellation message and no city.

Analyzing another captured repository/exclusion pair starts over. Results from an older or cancelled
submission must never appear. The current implementation has no timeout,
automatic retry, or fallback.

== Current M2 release quality

The city remains the visual focus, controls are intentional, interaction is
predictable, cues do not overpower metric colours, and the inspector is clean,
responsive, and readable. The current interaction and visual-release ownership
are defined once in xref:city-and-failures.adoc[City and Failures].
