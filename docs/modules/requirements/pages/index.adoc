= Product

== Approved whole-core target

The `CC-CORE-*` references in this module define the approved whole-core target.
They do not claim that the whole target is implemented. Features without
repository and test evidence remain unimplemented. The current application at
commit `9bcf7c8` is the browser-only baseline described below.

The target accepts one public GitHub repository, records one immutable default-
branch commit on an explicit analysis action, and produces a deterministic city
and investigation for that commit. The Code City server owns source acquisition,
analysis, and the authoritative association of source and results. The browser
owns presentation and investigation. Explicit Save creates an immutable shared
server snapshot; temporary work is not silently saved.

The stable source, metric, and processing requirements are in
xref:source-and-metrics.adoc[Source and Metrics]. City, investigation, failure,
and save requirements are in xref:city-and-failures.adoc[City and Failures].
Accepted xref:architecture:adr/0013-ownership-of-source-acquisition-analysis-and-saved-investigations.adoc[ADR 0013]
fixes the ownership boundary. It does not select a server platform, API, storage
technology, access mechanism, or deployment topology.

== Current implemented baseline at `9bcf7c8`

The currently implemented product is a static browser application with no
server runtime or persistence. The following describes current behavior, not
the complete approved target.

[cols="1,3",options="header"]
|===
|Area |Current behavior

|Repository
|One anonymously accessible public GitHub repository

|Revision
|The current head commit of the repository's default branch

|Files
|`.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`, and `.cs`
(ASCII case-insensitive)

|Result
|One deterministic city for the selected commit, with current navigation,
selection, and inspection defined by xref:city-and-failures.adoc[City and
Failures]

|Storage
|Current browser session only; reload clears all current product state
|===

=== Current input

Accepted form: `https://github.com/<owner>/<repository>`

* Ignore surrounding spaces, tabs, and line breaks.
* Require HTTPS, the `github.com` host, and exactly two non-empty path segments.
* Reject credentials, a port, query, fragment, trailing slash, encoded path, or
  extra path segment.

Invalid input starts no GitHub request.

=== Current selected revision

On submit, the browser resolves the current head commit of GitHub's default
branch and processes only that immutable commit. It shows the full commit ID
with the result. Movement of the branch after selection does not change the
current attempt. A new submission resolves the head again.

=== Current user-visible behavior

. Before submission, the page shows the repository URL input.
. After submission, any previous result disappears. The page shows that Code
  City is working and offers Cancel.
. On success, the page shows the selected commit ID and one complete city.
  Users can navigate it, identify a hovered building's district in one stable
  contextual row, select any building by keyboard or pointer with persistent
  district context, search canonical module paths by exact case-sensitive
  substring, reveal a matching building, and read its canonical path, full
  district, and exact metric explanation.
. On failure, the page shows a short explanation and no city. It also shows the
  commit ID when one was selected.
. After cancellation, the page shows a cancellation message and no city.

Submitting another repository starts over. Results from an older or cancelled
submission must never appear. The current implementation has no timeout,
automatic retry, or fallback.

== Current M2 release quality

The city remains the visual focus, controls are intentional, interaction is
predictable, cues do not overpower metric colours, and the inspector is clean,
responsive, and readable. The current interaction and visual-release ownership
are defined once in xref:city-and-failures.adoc[City and Failures].
