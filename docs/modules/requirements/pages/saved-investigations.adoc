== Save and reopen

A completed GitHub or local working-tree investigation remains browser-local
until Save. Save publishes one immutable snapshot and changes the address to
`/saved/<id>`. Copy link copies that address. Saving does not reacquire source,
rerun analysis or replace an existing snapshot. A failed Save leaves the current
city/inspection usable; clicking Save again on a saved result copies its link.

Open saved is a read-only picker grouped by input kind and repository/folder
name. GitHub entries show branch/release/default choice, short commit and UTC
saved time. Working-tree entries show capture identity and saved time, never a
fabricated GitHub commit. Different sources, captures and commits coexist under
random IDs; a name or ref is not an overwrite key.

A saved URL restores city, outcomes, metrics, unit/contribution evidence and exact
normalized code without acquisition, filesystem permission, GitHub requests or
analysis-parser initialization. Source drill-down remains available after the
original checkout changes or disappears. Reopening never reopens a local folder
capability. Camera, selection, query and sort start in the normal overview.

Closing the original tab or restarting the host does not remove committed data.
There is no automatic expiry, login, per-user ownership, rename, edit or deletion
UI. The user explicitly selected shared visibility: *everyone who can reach the
host can read saved investigations and their code*. A saved URL is not an
authorization secret. This does not authorize Internet exposure; loopback remains
the default and cross-computer access needs an operator-selected deployment.

== Complete source-once snapshot

The version-3 container retains:

* Tagged input origin: real GitHub URL/ref/commit or local folder display name
  and actual working-tree capture ID, never an absolute filesystem path.
* Fixed/additional exclusions, canonical hierarchy and every per-file outcome.
* Successful raw metrics, unit identities/owned regions, exact complexity and
  decision kind/span/owner contributions in normalized byte coordinates.
* Fixed city geometry, colors, bounds and source/metric associations.
* Exactly one normalized UTF-8 source section for each text-valid file, including
  syntax/metric failures. Unsupported text retains its path/outcome, no payload.
* Build-input fingerprint of production source, pinned parser assets, lockfile
  and standalone builder; format version is separate.

Save does not archive the checkout, dependency/build trees, assets, Git metadata,
original raw duplicates or invalid binary-source payloads. Full drill-down is
retained for all admitted analyzed files; there is no top-N code sampling.

The schema is `src/application/saved-investigation.ts`. Source sections have
lengths and SHA-256 digests. An isolated validator checks strict shape, references,
normalized text/scalar boundaries, hashes and presentation safety. It does not
execute source, compute/certify metrics, verify a claimed build identity or
certify GitHub/local provenance. Hash consistency is not proof that a client
actually used the claimed inputs or analyzer.

Only version 3 payloads are supported under the accepted pre-production policy.
Older payloads fail explicitly with no acquisition, parser fallback, migration,
rewrite, implicit relayout or deletion. Older seven-field receipt metadata stays
readable in inventory so existing files do not block new-format Save/catalog
operations. Old entries are not silently upgraded or claimed to reopen.
Portable export/import is not part of this slice.

== Operation and bounds

Enable persistence with `--data-dir <directory>`, for example:

[source,shell]
----
npm start -- --port 55583 --data-dir /var/lib/code-city
----

Use a dedicated local directory outside `dist/` and source. Relative paths resolve
against host cwd; artifact containment and symlink aliases into it are rejected.
Without usable storage, Save/picker report unavailability and analysis still
works. One host per data directory is supported; no database/dependency is added.

[cols="2,1",options="header"]
|===
|Bound |Value
|Encoded JSON header |16 MiB
|Captured unit/contribution metadata |12 MiB; exhaustion disables Save, not analysis/inspection
|Normalized source |2 MiB/file; 40 MiB total; at most 4,000 admitted files
|Complete upload |192 MiB
|Committed snapshots |1,024
|Charged committed storage |2 GiB, including reserved 16 KiB receipt/entry
|Concurrent writes / binary reads |1 / 4
|Upload/validation or binary-read operation timer |120 seconds
|Validation worker heap |256 MiB old generation; 32 MiB young generation
|===

These are input/operation bounds, not process RAM, disk-latency, power-loss or
DoS guarantees. Anonymous clients cannot establish reliable per-person quotas.
Busy/full writers do not consume read admission or browser analysis capacity;
static assets are independent. Uploads require same-origin POST, exact binary
media type and declared length. Chunked/oversized/invalid bodies are not published.

== Publication and recovery

Entries are `snapshots/<random-id>/{snapshot.ccs,record.json}`. Receipts record UTC
server time, input kind/label/ref, revision or capture ID, byte length and whole
container hash. Upload, isolated validation and synchronization precede same-volume
directory rename. Only committed directories are catalogued; IDs are never
overwritten. Acknowledgment follows publication and the owned cleanup attempt.
A lost response may leave a complete picker-discoverable entry; Save is not an
exactly-once network protocol.

A failed operation removes only its owned staging directory/lock. Failed cleanup
retains the lock to prevent accumulating uncharged bytes. Crash locks block new
writes, not committed reads. With the host stopped, inspect/preserve uncertain
staging and remove only confirmed abandoned work. Never promote partial data.

Back up the whole data directory. Stop the host before backup restoration or
operator deletion. Startup validates receipts, regular files, lengths and bounded
catalog shape; malformed storage fails closed without deleting it. Restore rejects
corruption/unsupported formats. Process-restart durability is tested; filesystem
failure, power loss, network filesystems, TLS ingress and Internet exposure are
not qualified by this delivery.
