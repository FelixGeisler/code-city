= Source and Metrics

== Approved whole-core source and analysis target

The requirements in this section are the approved whole-core target. The
detailed language and metric rules later on this page are the single
authoritative algorithms for the current browser-analysis milestone and the
later whole-core target. The browser implements source acquisition and
analysis in a dedicated worker, complete acquisition before file processing,
supported per-file continuation, and browser-temporary source-result association.
Browser source viewing and saved investigations remain later whole-core
outcomes.

[[CC-CORE-SRC-01]]
=== Public repository input

Accept one anonymously accessible public GitHub repository root URL or explicit
`/tree/<branch-suffix>` branch link. The initial acceptance repository is
`https://github.com/FelixGeisler/code-city`. Private repositories, uploads,
archives, local folders, other providers, tags, commit links, and generic
arbitrary refs are excluded.

[[CC-CORE-SRC-02]]
=== Explicit immutable-revision analysis

Only an explicit Analyze action resolves the then-current tip of
the supplied branch, or the default branch when no branch was supplied, and
records its full immutable commit ID. No selection event, watch, or schedule
starts analysis. Later runs do not alter earlier results.

[[CC-CORE-SRC-03]]
=== Browser-owned acquisition and analysis

A dedicated browser worker acquires and analyzes the complete selected-commit
dataset. The browser owns unsaved sources, results, presentation, and
investigation. The server receives data only on later explicit Save, not on
Analyze or while a tab remains idle. Ownership is fixed by
xref:architecture:adr/0015-browser-analysis-and-server-saved-investigations.adoc[ADR 0015].

[[CC-CORE-SRC-04]]
=== Untrusted source

Repository content is untrusted data. Code City never executes or imports it as
application code. It never runs repository tests, builds, package scripts,
generators, or hooks.

[[CC-CORE-SRC-05]]
=== Path exclusions

Before analysis, exclude these case-sensitive directory segments at any depth:
`node_modules`, `dist`, `build`, `bin`, and `obj`. Additional exclusions are
newline-separated canonical repository-relative paths without glob or regular-
expression syntax; each excludes an exact match and descendants on a `/`
boundary. LF, CRLF, and CR separate lines; empty lines are ignored, but a
nonempty line is neither trimmed nor normalized. Require well-formed NFC and
the canonical path rules, preserve case and ordinary spaces, and reject exact
case-sensitive duplicates before worker creation or provider work. The Analyze
action captures and unsigned-UTF-8-sorts this array. Retain and display the
fixed rules in the order above followed by the captured additional paths.
Do not infer generated or third-party status from content, and do not exclude
`packages` by name.

[[CC-CORE-SRC-06]]
=== Complete acquisition

Before exclusions, suffix filtering, or blob reads, validate every recursive-
tree record's raw and NFC-canonical identity, uniqueness, supported Git kind,
and complete raw ancestry. Every slash-delimited proper raw ancestor must be a
separate directory (`040000`/`tree`) record; never synthesize one. A missing or
non-directory ancestor fails complete acquisition. Failure to establish the
immutable revision or acquire its complete eligible dataset publishes no
partial city. Individual supported files may fail only
after complete acquisition under the per-file policy in
xref:city-and-failures.adoc#target-failures[Target failures].

=== Fixed processing envelope

The initial target retains inclusive limits of 4,000 supported files, 2 MiB of
normalized UTF-8 per file, and 40 MiB in aggregate after exclusions. Exceeding
a limit fails the complete analysis as `Repository exceeds Code City limits`.
Code City does not sample, truncate, retry automatically, or silently apply a
lower limit.

== Approved whole-core metric target

[[CC-CORE-MET-01]]
=== Metric dimensions

Height represents physical SLOC, footprint represents executable-unit count,
and colour represents the maximum cyclomatic complexity of a unit in the file.

[[CC-CORE-MET-02]]
=== Physical SLOC

Count a physical line once when it has non-whitespace source outside comments.
Blank and comment-only lines count zero; declarations and executable source
count; trailing-comment and multiple-statement lines count once; minified one-
line source has SLOC 1. The exact initial per-language contract is defined once
in xref:#authoritative-source-lines[Source lines] and the C# qualification in
xref:#authoritative-csharp-contract[C# metric contract].

[[CC-CORE-MET-03]]
=== Executable units and complexity

Each executable unit starts at complexity 1 and owns its branching
contributions; nested units own their bodies. The exact JS, JSX, TS, TSX, and C#
inclusion, ownership, syntax, and counted-construct contracts are defined once
in xref:#authoritative-syntax[Syntax],
xref:#authoritative-csharp-contract[C# metric contract], and
xref:#authoritative-metrics[Metrics]. Retain each unit's kind, exact source
span, complexity, and owned contribution kinds and spans.

[[CC-CORE-MET-04]]
=== Fixed visual mapping

Fixed, compressed, globally bounded mappings give equal raw values equal visual
meaning across analyses. The formulas, caps, rounding rules, and palette remain
authoritative in xref:city-and-failures.adoc#authoritative-visual-mapping[Visual
mapping]. Visual caps change neither raw values nor processing limits.

[[CC-CORE-MET-05]]
=== Evidence without classification

Raw maximum complexity remains visible. Colour communicates magnitude only and
creates no health, correctness, risk, defect, warning, or pass/fail
classification.

== Authoritative language and metric contract

The suffixes, pinned grammar selection, strict UTF-8, BOM, newline, and NUL
handling, unit ownership, syntax coverage, and metric algorithms below are the
initial target contract and grammar authority. The current milestone applies
these rules in its browser worker and continues supported per-file failures as
`Source text is not supported`, `Syntax could not be analyzed`, or `Metrics
could not be computed`. This does not imply the later recursive presentation,
browser source view, or persistence outcomes. Algorithm evidence is in
`test/base-metrics.test.mjs`, `test/complexity.test.mjs`,
`test/csharp-qualification.test.mjs`, and `test/source-admission.test.mjs`;
shared-core continuation evidence is in `test/project-analysis.test.mjs` and
`test/node-worker-runtime.test.mjs`; actual browser execution is qualified by
`tools/check-standalone-browser.mjs`.

[[authoritative-admission]]
== Admission

[cols="1,3",options="header"]
|===
|Area |Rule

|Path
|Split a repository-relative `/` path into non-empty segments and normalise
each segment to NFC. Preserve case. Reject absolute forms, backslashes,
repeated or trailing separators, `.`/`..`, and control characters.

|Identity
|The canonical path. Exact or NFC collisions fail. Successful identities sort
by unsigned UTF-8 bytes.

|Suffix
|Compare the final suffix ASCII case-insensitively with `.js`, `.jsx`, `.mjs`,
`.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`, or `.cs`.

|Kind and ancestry
|Before filtering, accept only regular blob, directory tree, symbolic-link
blob, and submodule commit records, and require every proper raw ancestor as an
explicit directory-tree record. Missing ancestors and regular files, links,
submodules, or other kinds in an ancestor position fail complete admission.
After complete validation, apply fixed and additional exclusions, then admit
supported regular files and skip directories, links, submodules, and
unsupported suffixes. Apply no additional inferred vendor or generated-content
exclusion.

|Content
|Decode strict UTF-8, remove one leading BOM, reject NUL, convert CRLF and CR
to LF, and perform no other transformation. Empty content is valid.
|===

[[authoritative-processing-envelope]]
== Supported processing envelope

These are Code City limits, not copies of GitHub limits. All maxima are
inclusive and apply only to nonexcluded supported regular files. Directory
records have no product count limit.

[cols="2,1",options="header"]
|===
|Measured value |Maximum

|Admitted modules |4,000
|Normalised UTF-8 in one module |2 MiB
|Normalised UTF-8 across all modules |40 MiB
|===

A repository outside this envelope fails as `Repository exceeds Code City
limits`. It is never sampled, truncated, or partially processed.

After complete inventory and eligible-blob preflight, one browser analysis
attempt may own at most eight raw-source read slots. Pending reads and completed
raw outcomes awaiting canonical consideration both occupy a slot. Reads start
in canonical order, while strict text handling, byte ownership, envelope
checks, failed-file rows, retained modules, and progress remain canonically
ordered. A known raw failure stops further admission; only the unresolved
canonical prefix is retained to determine the same failure precedence as
serial acquisition. Cancellation or terminal failure aborts and settles every
owned read before the attempt returns. With `A` active browser attempts, this
phase can own at most `8 × A` slots; this is neither a memory, provider-capacity,
latency, nor throughput promise.

The standalone status reports measured phase-local completion inside this
fixed envelope. After complete inventory and preflight validation, acquisition
reports `0/N` immediately before the first supported candidate read and then
one completion for each considered candidate, including strict-text failures.
After shared parser initialization succeeds, analysis reports `0/T` immediately
before the first text-valid file and then one completion only after that file's
parser attempt and required release have finished. Parser initialization or
release failure does not fabricate a completion; `T = 0` emits no analysis
counter. These counts do not change source admission, metric, city, failure,
or retained-source behavior. The
xref:city-and-failures.adoc#browser-investigation-workspace[workspace] maps them
to one monotonic work-progress bar, not an elapsed-time estimate.

GitHub independently owns API, rate, response, and tree limits.
Code City does not copy those values into its product contract. A truncated or
otherwise incomplete provider result fails as incomplete source. Internal
buffers and counters are implementation safeguards and must not reduce the
published Code City envelope.

[[authoritative-syntax]]
== Syntax

[cols="2,3",options="header"]
|===
|Suffix |Grammar

|`.js`, `.mjs`, `.cjs`
|JavaScript; reject visible JSX nodes

|`.jsx`
|JavaScript with JSX

|`.ts`, `.mts`, `.cts`
|TypeScript

|`.tsx`
|TSX

|`.cs`
|C#
|===

After complete acquisition, parser errors, missing nodes, or recovery omit the
individual file under `Syntax could not be analyzed`. Shared parser
initialization failure fails the complete analysis. Type checking, name
resolution, linting, and dependency analysis are not performed.

[[authoritative-csharp-contract]]
== C# metric contract

C# and ASCII-case `.cs` variants are supported by the production-selected,
pinned grammar. Its package, asset, runtime, source-commit, inventory, ABI, and
licence pins and qualification evidence are recorded in
`test/fixtures/csharp-candidate.json`, `tools/qualify-csharp-grammar.mjs`, and
`test/csharp-qualification.test.mjs`. The selection defines accepted syntax
without claiming a C# language version.
C# metrics use this fixed contract:

* `S` counts each physical line containing non-whitespace, non-comment C#
  source. Declarations, attributes, metadata, and every preprocessor directive
  count. Comment-looking content in regular, verbatim, interpolated, and raw
  strings remains source. All syntactically present preprocessor branch bodies
  are analysed without symbol evaluation; directive conditions add no unit or
  decision.
* `U` counts one unit for each explicit body of a method, local function,
  constructor, destructor, operator, conversion, accessor (`get`, `set`,
  `init`, `add`, or `remove`), lambda, or anonymous method. Block and expression
  bodies count. An expression-bodied property or indexer is one getter unit.
  Auto accessors, bodyless, signature-only, abstract, extern, and generated
  members, and a primary-constructor header alone, count zero.
* Runtime field, property, and event initializers, top-level statements, and
  primary-constructor base arguments outside explicit bodies share at most one
  file-wide `initialization/top-level` unit. An explicit constructor initializer
  belongs to that constructor. Nested callables own their bodies exclusively,
  although creating one can establish the surrounding initialization unit.
  Attributes, type and signature syntax, parameter defaults, const
  initializers, and enum values establish neither a unit nor runtime ownership.
* Each unit starts at complexity 1. Add one owned point for each `if`, loop,
  switch-statement `case` label, `catch`, conditional expression, and occurrence
  of `&&`, `||`, `??`, or `??=`. Add one for each switch-expression arm except
  an unguarded discard arm (`_ =>`), and one more for each switch-arm `when`
  guard and catch `when` filter. Thus a guarded discard arm and a filtered
  catch each add two points. Multiple `case` labels each count; `default` adds
  zero.
* Patterns, query clauses, attributes, type and signature syntax, parameter
  defaults, const and enum syntax, preprocessor conditions, `else`, `switch`,
  `default`, `try`, `finally`, calls, comparisons, bitwise operators, and
  conditional access add no point themselves. `M` is the maximum unit
  complexity, or zero when there is no unit.

After complete acquisition, any C# parser error, missing node, or recovery
omits that file under `Syntax could not be analyzed`, without exposing a raw
diagnostic, retrying, falling back, or executing source. A metric derivation
failure instead uses `Metrics could not be computed`.

[[authoritative-metrics]]
== Metrics

[[authoritative-source-lines]]
=== Source lines (`S`)

Count a physical line once when it contains non-whitespace, non-comment source.
Blank, line-comment-only, block-comment-only, JSDoc-only,
triple-slash-directive-only, hashbang-only, and JSX-comment-only lines count
zero. Comment-looking text in strings, templates, regular expressions, or JSX
remains source. A final LF adds no line.

=== Executable units (`U`)

Count body-bearing functions, arrows, methods, constructors, getters, setters,
and static blocks. Add exactly one `top-level` unit when value-level syntax
exists outside callable parameter/body, concise-expression, and static-block-body
regions. Comments, type-only syntax, ambient declarations, signatures, and
`export {}` alone do not create that unit.

=== Complexity (`M`)

For each unit:

[source,text]
----
complexity = 1
           + owned if statements
           + owned loops
           + owned non-default case labels
           + owned catch clauses
           + owned runtime ternaries
           + owned &&, ||, ??, &&=, ||=, and ??= occurrences
----

Nested units own their regions exclusively. Parameter defaults belong to their
unit; declaration expressions outside a unit belong to `top-level`. `else`,
`switch`, `default`, `try`, `finally`, optional chaining, comparisons, calls,
and erased TypeScript syntax add zero themselves.

`U` is the unit count. `M` is the maximum unit complexity, or `0` when no unit
exists.
