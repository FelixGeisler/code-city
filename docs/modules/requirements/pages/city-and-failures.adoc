= City and Failures

== Approved whole-core city target

The requirements in this section describe the approved whole-core target, not
the current browser-analysis presentation described later on this page.
The current implementation retains two-segment grouping. Recursive geometry, ordering,
spacing, labels, and picking remain unresolved.

[[CC-CORE-CITY-01]]
=== Recursive repository city

The selected repository root is the city. Every ancestor directory induced by
a successfully analyzed file is represented recursively as a subdivision. The
target does not yet select recursive geometry, ordering, spacing, labels, or
picking behavior.

[[CC-CORE-CITY-02]]
=== One building per successful source file

Every successfully analyzed source file has exactly one building. The initial
core has no type-based split, aggregation, collapse, or replacement of file
buildings.

== Approved whole-core investigation target

[[CC-CORE-INV-01]]
=== Shared file selection

The city remains primary. Selecting a building or file-list result updates one
shared file selection and first shows raw file metrics and units in the order
below. Selection does not open source or move, frame, reveal, reset, or animate
the camera.

[[CC-CORE-INV-02]]
=== Explicit unit drill-down

Explicit unit drill-down shows read-only source corresponding to the analyzed
commit, the unit's exact complexity, and only its owned complexity-contribution
spans. Each contribution exposes its textual kind and source location; colour
is not the only indication.

[[CC-CORE-INV-03]]
=== Searchable and sortable file list

A searchable, sortable list contains every successful file's canonical
repository-relative path and raw metrics. Search is a case-sensitive literal
substring; an empty query shows all successful files. Available sorts are SLOC,
executable-unit count, and maximum unit complexity. Metric sorts are descending
and then unsigned UTF-8 canonical path ascending. Initial order is SLOC
descending.

Unit order is complexity descending, source start byte ascending, end byte
descending, then unit kind ascending. Top-level drill-down shows the complete
normalized file; an explicit unit shows its exact normalized syntax span with
one-based line numbers.

[[CC-CORE-INV-04]]
=== Investigation evidence only

Values, ranking, colour, legend, and highlights are investigation evidence
only. Code City does not generate threshold findings, warnings, grades,
recommendations, AI guidance, or fixes.

[[target-failures]]
== Approved whole-core failure target

[[CC-CORE-FAIL-01]]
=== Per-file continuation

After complete acquisition, an individual supported file with unsupported
source text, unanalyzable syntax, or uncomputable metrics does not abort other
files. Omit its building and never fabricate zero metrics.

[[CC-CORE-FAIL-02]]
=== Sanitized failed-file inventory

Expose every failed file in a separate list, collapsed initially behind a
failed-file count. Expanded rows show inert canonical path text plus one
sanitized category. Invalid UTF-8 or NUL uses
`Source text is not supported`; malformed or recovered syntax uses `Syntax
could not be analyzed`; metric derivation failure uses `Metrics could not be
computed`. Expose no raw parser or provider text, stack, credential, server
path, or active content.

[[CC-CORE-FAIL-03]]
=== Unsupported, excluded, and all-failed outcomes

Unsupported and path-excluded files are neither successful files nor analysis
failures. If every attempted supported file fails, show no city and the
complete failed-file list behind its expandable count.

Revision, complete-tree, blob-integrity or retrieval, processing-envelope,
shared-parser-initialization, persistence-service, and city or presentation
failures are whole-analysis failures. They publish no partial city.

== Approved whole-core temporary and saved analyses

[[CC-CORE-SAVE-01]]
=== Explicit Save

A completed analysis is temporary unless the user explicitly chooses Save.
Analyze neither silently saves nor overwrites.

[[CC-CORE-SAVE-02]]
=== Unsaved lifetime

In the whole-core target, an unsaved analysis has no reopening identifier after
replacement by a new analysis, page reload, navigation away,
or close. Explicit Save supplies a reopening identifier.

The browser-analysis milestone retains temporary source and results only in
browser memory and releases them on replacement, page exit/reload, or
worker loss. Its cleanup policy is defined in
xref:browser-analysis-operating-policy.adoc[Browser Analysis Operating Policy].
Explicit Save and reopening are implemented as defined in
xref:saved-investigations.adoc[Saved Investigations].

[[CC-CORE-SAVE-03]]
=== Immutable saved snapshot

Save creates a new immutable snapshot atomically. It retains repository
identity, full commit, effective exclusions, exact eligible source and
normalized analyzed text needed for inspection, per-file outcomes, hierarchy,
units and contributions, raw metrics, and fixed visualization inputs. Reopen
performs no GitHub acquisition or analysis. Saved snapshots have no automatic
expiry.

Failed Save leaves the temporary investigation usable. Reanalysis never
overwrites a snapshot. The picker groups entries by `<owner>/<repository>`;
rows show requested branch/tag, short commit and saved UTC time. Opening an
entry shows the full commit.

[[CC-CORE-SAVE-04]]
=== Shared inventory and retained source

Every user admitted to the internal Code City website can view the shared
saved-analysis inventory and retained source. This requirement does not select
a login or account system. The initial shared-view product has no login;
xref:saved-investigations.adoc[Saved Investigations] defines bounded storage,
read-only inventory, API operation and operator recovery. Ingress and Internet
deployment remain separate. Stored client metrics
are not server-certified facts and are not recomputed for certification.

Server persistence is the initial Save and reopen implementation. Its storage
technology is selected by
xref:architecture:adr/0016-immutable-investigation-file-store.adoc[ADR 0016]. Portable source-bearing export and import is not
permanently excluded. Whether it is added, whether it shares the server
representation, and its representation, format, and I/O contract remain
unresolved. A downstream API is outside the whole core.

[[authoritative-visual-mapping]]
== Authoritative visual mapping

The current scene and the target mapping use exactly one axis-aligned prism for
each successfully analyzed module. Admission, raw `S`, `U`, and `M`, and source
limits are defined by xref:source-and-metrics.adoc[Source and Metrics]. The six
`M` thresholds remain unchanged; displayed dimensions and base colours are
fixed here.

For every admitted non-negative safe-integer fact:

[source,text]
----
height(S) = 4 + floor(36 * sqrt(min(S, 1000) / 1000) + 0.5)
side(U)   = 3 + floor(15 * (ln(1 + min(U, 100)) / ln(101))^1.5 + 0.5)
width = depth = side(U)
----

Thus displayed height is an integer in `4..40` and displayed width and depth
are the same integer in `3..18`. The height operations are evaluated in the
written order with ECMAScript `Number` arithmetic and no intermediate rounding.
For example, `S=25,50,100,200,600,1000` gives height
`10,12,15,20,32,40`. This is one absolute global scale: equal `S` gives equal
height regardless of repository, district, neighbouring files, or input order.
Values above `S=1000` or `U=100` retain their raw metric value but share the
corresponding capped displayed dimension.

[cols="1,2",options="header"]
|===
|Property |Rule

|Identity |Canonical module path
|Height |`height(S)`
|Width |`side(U)`
|Depth |`side(U)`
|Base colour |The following palette band selected by `M`
|===

[cols="1,1",options="header"]
|===
|Complexity `M` |Base RGBA colour

|0 |`#22C55EFF`
|1 |`#84CC16FF`
|2–3 |`#FACC15FF`
|4–7 |`#F59E0BFF`
|8–15 |`#F97316FF`
|16+ |`#EF4444FF`
|===

The geometry payload stores this exact opaque base RGBA. Face display
transforms do not change band membership or the payload colour.

== Layout

Derive one tagged group identity from each canonical path after removing its
filename. Two or more remaining segments form a directory identity whose
identifier is the first two segments joined with `/`; one remaining segment
forms a directory identity for that segment; no remaining segment forms the
root identity. The root identity is distinct from every directory identity.
Canonical paths and directory identifiers compare by unsigned UTF-8 bytes.
For group ordering, the root identity compares using the bytes of `_root` and
precedes a directory identity named `_root` on an exact tie.

Within each group, sort buildings by descending `side(U)`, then canonical path.
Let building gap be `2`, virtual padding be `3`, and:

[source,text]
----
innerTarget = max(maxSide, ceil(sqrt(sum((side + 2)^2))))
----

Pack in unpadded inner coordinates. Start an empty row with cursor `(0,0)` and
row depth `0`. Before placing a building, open a new row exactly when the
current row is nonempty and `cursorX + side > innerTarget`; set `cursorX=0`,
advance `cursorZ` by the completed row depth plus `2`, and reset row depth.
Place the building minimum at `(cursorX,0,cursorZ)`, advance `cursorX` by
`side+2`, and set row depth to the maximum side in that row. Occupied width and
depth are the maxima of actual building endpoints, with no trailing gap. The
virtual group cell is the occupied rectangle plus padding `3` on every edge;
therefore its width is `occupiedWidth+6`, its depth is `occupiedDepth+6`, and
actual local building `x,z` origins are offset by `3`.

Sort virtual group cells by descending `cellWidth*cellDepth`, then tagged group
identity. Let group gap be `8` and:

[source,text]
----
outerTarget = max(maxCellWidth,
                  ceil(sqrt(sum((cellWidth + 8) * (cellDepth + 8)))))
----

Pack cells with the same row algorithm from `(0,0)`, substituting cell width,
cell depth, `outerTarget`, and gap `8`. A row opens only when nonempty and
`cursorX + nextCellWidth > outerTarget`; row depth is the maximum cell depth.
The world origin of each building is its cell origin plus its padded local
origin.

After packing, translate all actual building minima and every virtual cell by
the same horizontal vector so the minimum actual building `x` and `z` are
exactly `0`. Geometry payload bounds remain computed from actual building boxes
only. Independently retain each translated virtual cell, in outer-pack order,
as one numeric district plate with minimum `(cellMinX,-0.5,cellMinZ)` and
dimensions `(cellWidth,0.5,cellDepth)`. The plate top is exactly `y=0`; group
gap `8` is excluded. `sceneBounds` is the union of all plates and real building
AABBs, and its immutable centre is shared by camera and instance uploads.
Plates are presentation-only and are not payload geometry or pick targets.
Each plate has one aligned controller-only descriptor `{root,identity}`. The root
is `{true,"_root"}`; a real `_root` directory is `{false,"_root"}`. Other
identities are the existing one- or two-segment grouping result. These
descriptors do not enter the numeric presentation, worker, WebGL, hash, or
evidence contracts.

Payload arrays remain in increasing canonical-path index order. Packing writes
one computed position back to that index; it does not reorder identity,
keyboard traversal, selection, inspection, or exact-tie ownership.

== Legacy contextual district row and retained presenter projection

The contextual-row behavior in this subsection belongs to the retained legacy
`createMainController` and semantic-publication path. It remains documented as
historical reference for that implementation, but the active standalone
presentation-session coordinator does not mount it. The active composition
publishes a collapsed file-navigation disclosure above the city and optional
navigation instructions below it.

A committed legacy semantic publication reserves one `20px` normal-flow
contextual row immediately after path search and before the city viewport. Its
single label is initially hidden with empty text. Selected-building district
wins over hovered-building district; without either context the label is hidden
and its text is cleared. The legacy controller derives the display name from
the validated inspection fact by removing the filename and taking the first two
directory segments, one segment when only one exists, or `/` at repository
root. A real `_root` directory is therefore distinct from root.

The legacy row is `aria-hidden`, unfocusable, inline-start aligned, and
`pointer-events:none`. The label is `144px × 20px` when the actual canvas CSS
width is at least `480px`, otherwise `104px × 20px`. It retains `6px` inline
padding, `11px ui-monospace, SFMono-Regular, Consolas, monospace`, weight `650`,
colour `#CBD5E1`, background `rgb(7 17 31 / 0.72)`, radius `3px`, single-line
bidi isolation and ellipsis, and no border, outline, or shadow. The resolved
repository-derived value is assigned only to its one `<bdi dir="auto">` with
`textContent`; it is never an attribute, style, URL, object key, log,
shader/GPU value, observer value, or evidence field. There are no per-district
label nodes, projected label visibility, collision layout, inspector exclusion,
or label listener, observer, frame, retry, renderer, or GPU text.

The city presenter's numeric district-projection contract remains implemented
independently of that legacy row. The active standalone coordinator supplies a
no-op `districtProjection` callback, so camera and resize validation still use
the numeric snapshot but publish no district-row DOM. For each plate, derive
the top-centre anchor and all four top corners directly from its numeric cell at
`y=0`. Subtract the immutable `sceneBounds` centre and project each point with
the exact float32 matrix used by the corresponding draw. For every row
`k=0..3`, with `f=Math.fround`, evaluate:

[source,text]
....
p0=f(m[k]*x); p1=f(m[k+4]*y); p2=f(m[k+8]*z); p3=f(m[k+12]*f(1))
s0=f(p0+p1); s1=f(s0+p2); clip[k]=f(s1+p3)
....

Every relative coordinate must equal its `f` result; every input, product,
sum, clip component, and quotient must be finite. Require `clipW>0` and
`-1 < f(clipZ/clipW) < 1`. Set `ndcX=f(clipX/clipW)` and
`ndcY=f(clipY/clipW)`. A violation fails the complete transaction as
`M1-PRES-1`; lateral values outside `(-1,1)` remain valid and are layout
exclusions. With the positive integer CSS dimensions accepted by the same
draw, use unrounded `Number` operations for:

[source,text]
....
screenX=(ndcX*0.5+0.5)*cssWidth
screenY=(-ndcY*0.5+0.5)*cssHeight
area=(maxCornerX-minCornerX)*(maxCornerY-minCornerY)
....

The closed immutable snapshot contains only `cssWidth`, `cssHeight`, and
ordered `{screenX,screenY,area,lateral}` rows. Stage and commit return their
direct snapshot; commit returns the latest accepted staged-resize snapshot.
Current camera and resize transitions replace camera, view, and snapshot
atomically before the generation- and captured-token-gated
`districtProjection(generation,snapshot)` callback.

Projection continues to update its byte- and key-compatible snapshot on the
existing presenter camera and resize paths. In the active standalone no
snapshot value is consumed for contextual text, visibility, position, or
dimensions.

== Scene and fixed face display

The WebGL clear colour and the matching CSS city host background are
`#07111F`. Each redraw clears once, draws all district plates first, then draws
every building with canonical building instance IDs still starting at zero.
Both instanced `TRIANGLES` draws use one trusted program and shared cube/index
buffers. Required integer `u_passKind` is `0` immediately before the plate draw
and `1` immediately before the building draw. Fixed trusted building-face
display derives normalized RGB channels from the instance base colour as
follows, retaining alpha `1`:

[source,text]
----
+Y:             c' = c + 0.12 * (1 - c)
+X and -X:      c' = 0.82 * c
+Z, -Z, and -Y: c' = 0.62 * c
----

The plate branch never uses building colours; district selection can highlight
the selected platform. Its `+Y` face is
`#182A43FF`, its `+X/-X` faces are `#142237FF`, and its `+Z/-Z` and bottom faces
are `#0F1A2AFF`. Plates are opaque with CCW front faces, back-face culling,
depth `LESS`, and depth writes enabled. The building base colour remains
identifiable through its fixed transforms. There is no configurable lighting,
normal or material input, texture, fog, shadow, blending, polygon offset,
antialiasing promise, outline, or static edge pass.

[[browser-investigation-workspace]]
== Investigation workspace

Initially show the repository URL input and Analyze, with optional additional
exclusions in a closed native disclosure. Analyze hides setup and shows a
compact captured repository/revision bar, actual phase progress, and Cancel.
Do not show Change repository while analysis is active. Once the outcome is
available, Change repository opens or closes setup without losing the current
city or selection; opening it focuses the repository field. Draft edits do not
change the displayed investigation. Analyze submits the edited URL/exclusions
through the existing pipeline. Invalid submission restores setup with its error.
There is no Discard or Reanalyze control. Closing the tab ends its browser-local
investigation; no server analysis/session cleanup action is required.

Use one progress element for the complete attempt. Before candidate admission,
it is indeterminate. Once `N` candidates are known, keep the fixed budget
`2N + 3`: one acquisition and one terminal file-outcome slot per candidate, plus
parser initialization, city construction, and view publication. Acquisition
completion is `X`; after initialization with `T` text-valid files, completion is
`2N + 1 - T + X`; construction begins at `2N + 1`. Unsupported-text outcomes
already resolved by acquisition consume their outcome slots without pretending
they were parsed. Preserve measured phase counts in the label. Only successful
view publication fills the bar. Failure/cancellation ends it without fabricated
completion. This is work progress, not equal-duration work or an ETA.

The city is the primary result view. File navigation and failed-file rows are
native disclosures, closed initially. There is no expandable navigation-help
panel. Use primary drag to orbit, secondary drag to pan, wheel zoom, click/tap
selection, and Reset view; retain the keyboard controls documented below. They use normal
keyboard activation and focus indicators. Expanding or closing these controls
makes no provider request, clears no selection, and does not reset the camera.
An all-files-failed result shows `No files could be analyzed.` and its expandable
failed-file count, but no city or successful-file navigation.

== Successful-file inventory and shared selection

A committed standalone city has one normal-flow native disclosure labelled
`Find file (N files)` (singular for one file). It is closed initially rather
than competing with the city. When expanded, it contains every successful
inspection fact as one semantic list item with a native `button type="button"`. Each button shows the exact
canonical path and raw `S: <value>`, `U: <value>`, and `M: <value>`, and exposes
`aria-pressed="true"` only for the shared selected canonical index.

The section has a native `input type="search"` labelled `Filter by canonical
path` and a native `select` labelled `Sort by` with `Source lines (S)`,
`Executable units (U)`, and `Maximum complexity (M)`. A newly committed result
starts with the exact empty query and S sort. The query is preserved exactly
and matched against canonical paths with case-sensitive ECMAScript `includes`.
There is no trimming, normalization, tokenization, ranking, regular-expression
interpretation, or source-text search. Empty input includes every successful
fact. Zero matches shows exactly `No matching analyzed files.` and no row
buttons while retaining the city and any selection.

The list projection consists only of canonical geometry indices. It sorts the
selected raw metric descending, then canonical path ascending with unsigned
UTF-8 comparison. Filtering and sorting never reorder or rewrite geometry,
inspection, instance buffers, picking identity, or canvas keyboard traversal.
The complete list has no cap below the existing 4,000-module envelope and uses
`max-block-size: min(13.75rem, 40vh)` with native vertical overflow. It remains
in normal flow beside Reset view and above the city; opening it cannot overlay
the city or inspector. Failed files are a separate disclosure below the city,
labelled `N files not analyzed` (singular for one file).

Canonical paths cross provider acquisition and the browser worker message
boundary as successful inspection facts or sanitized
failed-file rows. The inventory query remains browser-local. Filtering, sorting,
and selection introduce no additional provider or HTTP request. In the
interaction layer, successful paths are published only in analyzed-list rows and
the selected inspector, and failed paths only in the separate failed-file
list, using inert `<bdi dir="auto">` nodes assigned through `textContent`.
Inventory interaction derives no path- or query-based attributes, IDs, classes,
styles, URLs, object keys, logs, WebGL values, telemetry, or release evidence and
sends no source payload. Ordinary native editing, select, scrolling, button
activation, and Tab order apply. The controls are not autofocused and add no
custom keyboard shortcuts.

The standalone presentation-session coordinator owns the presenter, inventory,
and safe metric inspector for one generation. Control and row callbacks carry
current generation, publication identity, exact query snapshot, exact sort
snapshot, and canonical index. A stale mismatch is inert. A malformed callback
that is otherwise current, or a current DOM, listener, presenter, or publication
failure, clears the complete successful presentation as `M1-PRES-1` and
disposes its presenter once through an idempotent boundary.

List activation changes only the shared canonical-index selection. It preserves
hover, leaves focus on the native row button, updates the same building and
metric inspector, and does not call camera reveal, canvas focus, Reset, camera
framing, or animation. Selecting an already selected row retains selection.
City pointer activation and Arrow/Home/End keyboard selection use the same
canonical indices; those keys do not follow current list order. Unmodified
Escape and empty city activation clear selection and the inspector.

Filtering or sorting preserves selection, hover, inspector content, camera
matrices, target, magnification, geometry, and instance-buffer order. A selected
row filtered out remains selected and is pressed when it re-enters the
projection. Reset preserves query, sort, selection, and inspector while keeping
its existing transient-hover clear and exact overview behavior.

Query, sort, hover, selection, inventory, inspector, and presenter ownership are
current-session only. Analyze start, invalid submission, cancellation,
replacement, failure, session loss, `pagehide`, and disposal clear
them. A new success starts empty-query/S-sort/no-selection. An all-files-failed
result publishes no successful inventory, city, or inspector and retains the
complete separate failed-file list.

== District selection

A visible platform selects its district; a nearer building wins, including an
exact tie. Use the existing closed-box nearest-hit kernel for both geometries.
A file inspector's district button provides the same selection through a native,
keyboard-accessible control. District and file selection are mutually exclusive;
empty city activation or Escape with canvas focus clears either. Existing
Arrow/Home/End file traversal remains canonical and switches back to a file.

Selecting a district highlights its platform and retains ordinary colours for
its buildings while dimming other buildings. It shows the district path,
analyzed-file count, summed source lines, summed executable units, and maximum
unit complexity among successful members. Membership uses the existing one-/two-
segment grouping, not a new hierarchy. Repository root `/` is distinct from a
real `_root` directory. Integer totals remain exact even above the safe Number
sum range. Failed/excluded files do not enter these aggregates.

Hover, query, sorting, Reset, and resize preserve district selection.
If host layout changes before the resize observer updates the canvas bitmap,
selection updates remain valid. The observer draws the latest visual state
with the resized bitmap/camera; a pending ordinary resize is not a presentation
failure and must not discard the city. A new file
selection clears it. Selection changes no geometry, immutable buffers, camera,
provider request, metric result, or worker data contract. Old-generation and
removed-inspector callbacks are inert.

== Camera and controls

The perspective camera uses world `+Y` as up. For azimuth `a`, elevation `e`,
and target-to-camera direction:

[source,text]
....
D(a,e) = (cos(e)cos(a), sin(e), cos(e)sin(a))
R(a)   = (sin(a), 0, -cos(a))
V      = D × R
R × V  = D
....

The camera looks along `-D`. Camera reset, resize, orbit, pan, zoom, matrices,
and strict W/depth admission use plate-inclusive `sceneBounds`. Overview uses
target `T=C`, where `C` is the immutable `sceneBounds` centre, and the existing
M1 vectors:

[source,text]
....
D = (1, 1, 1) / sqrt(3)
R = (1, 0, -1) / sqrt(2)
V = (-1, 2, -1) / sqrt(6)
a0 = 45°
e0 = asin(1/sqrt(3))
....

Initial load and Reset use those vector constants, not a trigonometric
reconstruction. `A/D` subtract/add `15°` azimuth. `W/S` add/subtract `7.5°`
elevation. A primary-pointer horizontal delta `dx` adds
`2π·dx/cssWidth`; vertical delta `dy = clientY - lastY` adds
`π·dy/cssHeight`, so dragging upward lowers elevation and dragging downward
raises it. Azimuth is normalised to `[0,2π)` and elevation is clamped
inclusively to `15°..75°`.

At overview, the vertical field of view is `45°`. Define its half-angle
`theta=22.5°`, sphere padding `p=1.18`, and current positive aspect `aspect`.
Magnification `z` is `1` at overview, is clamped to `[1/64,64]`, and is lens
zoom rather than camera dolly. Its effective vertical field of view is:

[source,text]
....
verticalFov(z) = 2·atan(tan(theta)/z)
....

Wheel-up and `+` multiply `z` by `1.25`; wheel-down and `-` divide it. Zoom
retains target and orientation and changes projection slopes without moving
the camera or changing near/far for an otherwise unchanged state. This is a
deliberate difference from archived v1 OrbitControls dolly: it preserves the
current zoom actions and full `[1/64,64]` range without permitting the camera
to pass through the city or introducing a collision/minimum-distance policy.

For validated bounds lengths `L=(Lx,Ly,Lz)`, define the v1 sphere fit and the
current orientation extent:

[source,text]
....
r = hypot(Lx,Ly,Lz)/2
alpha = min(theta, atan(aspect·tan(theta)))
d0 = p·r/sin(alpha)
E = (Lx·abs(Dx) + Ly·abs(Dy) + Lz·abs(Dz))/2
....

There is no minimum-radius fallback. Every admitted city has
`Lx>=3`, `Ly>=4`, and `Lz>=3`, so `r>=sqrt(34)/2>1`.

For every state, let `Delta=C-T`, `delta=dot(Delta,D)`, and:

[source,text]
....
distance = abs(delta)+d0
s0 = distance-delta
camera = T+distance·D
closest = s0-E
farthest = s0+E
near = closest/2
far = farthest+closest/2
verticalSlope = tan(theta)/z
horizontalSlope = aspect·verticalSlope
....

`distance` is the target-to-camera distance and `s0` is the bounds-centre
camera depth. Since `E<=r`, `p>1`, and `sin(alpha)<1`,
`closest>=d0-r>0`. At `T=C` and `z=1`, the complete bounds sphere is inside
the padded frustum for every allowed orientation. Clipping is depth
containment only: pan or zoom may intentionally move a corner outside the
lateral clip interval.

Resize retains target, orientation, and magnification and recomputes aspect,
`r`, `alpha`, `d0`, `E`, distance, planes, slopes, pan spans, matrix, and ray.
Reset restores `T=C`, the exact overview basis, and `z=1`.

Pointer pan uses the target-plane half-spans:

[source,text]
....
verticalHalf = distance·verticalSlope
horizontalHalf = distance·horizontalSlope
T' = T - R·(2·horizontalHalf·dx/cssWidth)
       + V·(2·verticalHalf·dy/cssHeight)
....

Keyboard pan retains its current directions and moves one tenth of the
corresponding full target-plane span: `Shift+A/D` subtract/add
`R·(2·horizontalHalf/10)` and `Shift+S/W` subtract/add
`V·(2·verticalHalf/10)`.

Every instance minimum is uploaded once as `origin-C`; navigation changes only
`T`. Let:

[source,text]
....
fx = 1/horizontalSlope
fy = 1/verticalSlope
dr = dot(Delta,R)
dv = dot(Delta,V)
A = (far+near)/(far-near)
B = 2·far·near/(far-near)
....

For immutable bounds-centre-relative point `q` (the uploaded `origin-C` plus
the unit-cube vertex contribution), the perspective transform is:

[source,text]
....
clipX = fx·(dot(q,R)+dr)
clipY = fy·(dot(q,V)+dv)
clipW = s0-dot(q,D)
clipZ = A·clipW-B
....

Let `f(value)=Math.fround(value)`. Evaluate every formula above first as
ECMAScript `Number` operations, with finite checks and no intervening `f`.
Convert each final matrix component exactly at the shown `f` call. The matrix
passed to `uniformMatrix4fv(location, false, matrix)` is column-major:

[source,text]
....
m = [
  f(fx·Rx), f(fy·Vx), f(-A·Dx), f(-Dx),
  f(fx·Ry), f(fy·Vy), f(-A·Dy), f(-Dy),
  f(fx·Rz), f(fy·Vz), f(-A·Dz), f(-Dz),
  f(fx·dr), f(fy·dv), f(A·s0-B), f(s0)
]
....

For every exact bounds corner relative to `C`, compute
`pointDepth=s0-dot(q,D)` without float32 rounding and require
`near < pointDepth && pointDepth < far`; this also requires exact homogeneous
`w` to be positive.

The deterministic CPU strict-depth oracle uses the same float32 matrix and the
existing bounds-centre-relative float32 corner endpoints. For bounds
`[minX,minY,minZ,maxX,maxY,maxZ]`, define `x0=f(minX-Cx)`,
`x1=f(maxX-Cx)`, and likewise `y0`, `y1`, `z0`, and `z1`. Evaluate corners in
this exact order:

[source,text]
....
(x0,y0,z0), (x1,y0,z0), (x0,y1,z0), (x1,y1,z0),
(x0,y0,z1), (x1,y0,z1), (x0,y1,z1), (x1,y1,z1)
....

For each `(x,y,z)`, evaluate the clip-Z and clip-W rows separately. Products,
sums, division, and rounding are distinct operations with this exact left
association:

[source,text]
....
zp0 = f(m[2]  * x)
zp1 = f(m[6]  * y)
zp2 = f(m[10] * z)
zp3 = f(m[14] * f(1))
zs0 = f(zp0 + zp1)
zs1 = f(zs0 + zp2)
clipZ = f(zs1 + zp3)

wp0 = f(m[3]  * x)
wp1 = f(m[7]  * y)
wp2 = f(m[11] * z)
wp3 = f(m[15] * f(1))
ws0 = f(wp0 + wp1)
ws1 = f(ws0 + wp2)
clipW = f(ws1 + wp3)

depth = f(clipZ / clipW)
....

Every proposed target component, input, intermediate, matrix component,
product, sum, `clipZ`, `clipW`, quotient, and depth must be finite. Require
`near>0`, `far>near`, every exact `pointDepth>0`, every float32 `clipW>0`, and
exactly `-1 < depth && depth < 1` for every corner. There is no epsilon,
projection fallback, retry, or partial camera-state commit. Any violation
rejects the complete transition atomically as *Presentation failed* /
`M1-PRES-1`.

The oracle is a deterministic CPU admission rule over float32 uniform and
corner inputs, not a claim of bit-identical WebGL/GLSL operation ordering or
GPU depth. Dimensions and all `origin-C` endpoints remain exact `float32` under
every camera transition. There is no animation, inertia, auto-rotation, focus
flight, retry, or persisted camera state.

== Input, focus, and interruption

* The borderless, untransformed canvas is focusable, has a visible focus
  indicator and accessible name, and has adjacent keyboard instructions.
  Ordinary Tab order remains native. Pointer press focuses the canvas. A
  visible native Reset button performs Reset with ordinary button semantics.
* Recognised `keydown` values execute once per event, including `repeat`, and
  call `preventDefault`; `keyup` is inert. With no Ctrl/Alt/Meta, lowercase
  `w/a/s/d` without Shift orbits, uppercase `W/A/S/D` with Shift pans, and
  `+`, `-`, and `0` zoom or reset. Unmodified ArrowRight/ArrowDown,
  ArrowLeft/ArrowUp, Home, End, and Escape control selection. Other keys and
  modifier combinations are inert and retain browser behaviour. Events are
  not propagation-stopped.
* An unmodified wheel over the active canvas uses only the sign of `deltaY`:
  negative zooms in, positive zooms out, and zero is inert. A recognised wheel
  calls `preventDefault`. Ctrl/Alt/Meta/Shift wheel and scrolling outside the
  canvas remain browser-owned.
* Only one primary (`button=0`) or secondary (`button=2`) pointer gesture is
  active. A recognised press prevents default, focuses, and captures that
  pointer. Any exact `clientX/clientY` inequality from the press, with no
  threshold, makes it a drag. Primary deltas orbit and secondary deltas pan.
  A stationary unmodified primary release activates at its release position;
  modified primary and every secondary release do not activate. Other buttons
  and pointers are inert.
* Matching pointer-up ends the gesture and releases capture exactly once.
  `pointercancel`, unexpected `lostpointercapture`, window blur, a hidden
  document, replacement, failure, context loss, or `pagehide` cancels without
  activation. Canvas `contextmenu` is prevented; context menus elsewhere are
  unchanged. Interruption never synthesises a click or camera delta.

The presenter alone maps DOM input and owns suppression. Its only outbound
semantic events are:

[source,text]
----
hoverIndex(generation, index | null)
activationIndex(generation, index | null)
selectionAction(generation, next | previous | first | last | clear)
districtProjection(generation, numericSnapshot)
----

The controller receives no DOM event. It generation-gates semantic events and
owns traversal, hover, selection, and inspector state.

== Selection, picking, and hover

Right/Down choose the next canonical index; Left/Up choose the previous;
Home/End choose first/last; Escape clears. Traversal does not wrap and retains
a boundary selection. With no selection, forward starts first and backward
starts last. No building is selected initially. Camera actions, resize, and
Reset preserve selection.

Pointer coordinates use the canvas content rectangle:

[source,text]
----
xCss = clientX - rect.left
yCss = clientY - rect.top
x = xCss·canvas.width/rect.width
y = yCss·canvas.height/rect.height
----

Rectangle and backing dimensions must be finite and positive. Closed ranges
`[0,width] × [0,height]` are inside; outside is a miss. The perspective ray uses normalized device coordinates and the current lens
slopes:

[source,text]
....
nx = 2·x/canvas.width - 1
ny = 1 - 2·y/canvas.height
origin = camera
direction = -D + nx·horizontalSlope·R + ny·verticalSlope·V
....

The direction is intentionally unnormalised. Every candidate for one pick uses
the same ray parameter, so nearest ordering and exact distance ties remain
unchanged without an additional rounding step.

The active composition tests real building AABBs and platform boxes. A nearer
building wins, including an exact building/platform tie. An exposed platform
selects its district; empty space between platforms clears selection. The
retained legacy composition without a district callback remains building-only.

Each box uses an inclusive ray/AABB slab test. A direction component
exactly zero is parallel: it misses only when the origin is outside that axis's
closed bounds and otherwise imposes no interval. Nonparallel divisions must be
finite. Faces and edges hit because interval comparisons use `<=`. Accept only
finite `tEnter >= 0`; the smallest `tEnter` wins, with lower canonical index
only for exact (`===`) distance equality. There is no epsilon, rounded tie, GPU
readback, BVH, worker hop, or hidden capacity below 4,000 buildings.

Activation picks synchronously at release. Empty activation clears selection.
Hover never selects: movement inside retains only the latest position and runs
at most one pick in the next animation frame. Gesture start clears hover.
Gesture start and every accepted camera action, wheel, resize, and Reset
invalidate queued work, forget retained pointer coordinates, and clear hover.
Gesture end or cancel never queues hover. Only a fresh eligible pointer
movement can queue a pick, with at most the existing one animation frame. The
retained legacy presenter's search-reveal capability is not invoked by the
active standalone coordinator.
Pointer leave clears and invalidates hover. Replacement rejects work from old
sessions.

== Surface focus

Let `c` be the ordinary face RGB after the fixed face transform above. Surface
focus is applied after that transform with dim multiplier `D = 0.70`, hover
amount `H = 0.15`, and alpha fixed at `1`:

[cols="2,2,4",options="header"]
|===
|Selection |Hover |Displayed RGB for instance `i`

|None |Not `i` |`c`
|None |`i` |`mix(c, white, H)`
|`i` |None or `i` |`c`
|Another instance |None |`D * c`
|`s`, with different `h` |`i = h` |`mix(D * c, c, H)`
|`s`, with different `h` |Every other non-selected `i` |`D * c`
|===

Selection wins and retains ordinary face colours. A different hovered building
lifts only toward its own ordinary colour. The trusted fill shader receives required integer uniforms `u_passKind`,
`u_hoverIndex`, and `u_selectionIndex` on every redraw. `-1` is null; nonnegative
selection values identify buildings. In the district-capable composition,
`-districtIndex-2` identifies a validated plate and `u_selectionBounds` supplies
its target-relative X/Z minimum and width/depth. The shader tests each building
origin against that box and highlights the selected platform with the existing
`0.15` highlight mix. No path or group name enters a shader value. A session has exactly one program,
two VAOs, and four immutable buffers: shared cube, shared index, building
instances at `28N` bytes, and plate instances at `24G` bytes. Exact uploads are
`420 + 28N + 24G <= 208420` bytes for `1 <= G <= N <= 4000`. Each redraw has
exactly the plate and building draws above. There is no line cue, buffer
sub-upload, production readback, animation, or change to metric RGBA or real
AABBs. The same CPU picking kernel also handles platform boxes.

== Atomic lifecycle

A successful worker outcome contains one aligned, source-free city with
geometry and inspection facts. The controller validates it once and creates
non-aliasing geometry, inspection, and immutable numeric-presentation snapshots.
The latter contains only plate minima/dimensions, `sceneBounds`, and centre; it
has no group identity, path, label, anchor, projection, callback, or observer
field. The standalone presentation-session coordinator stages inventory and inspector
content, attaches the fixed city host for dimension validation, stages and
commits the presenter, applies the empty visual state, and commits the canvas in
one synchronous publication transaction. Geometry, facts, revision, native
query/sort controls and listeners, sorted canonical-index rows, canvas,
inspector container, empty query, S sort, hover, and selection become current
together. A failed transaction removes every candidate/current successful node
and presenter resource before publishing `M1-PRES-1`.

[cols="2,3,3,2",options="header"]
|===
|Trigger |Facts, semantic state, and inspector |Presenter work |Result

|Initial success
|Commit one current snapshot with empty hover and selection
|Commit staged canvas at exact overview
|One complete city

|Filter edit or clear
|Replace only the exact query and filtered, selected-sort projection; preserve selection and inspector
|No presenter call
|Current city or `M1-PRES-1`

|Sort change
|Replace only the selected sort and filtered projection; preserve canonical identity, selection, and inspector
|No presenter call
|Current city or `M1-PRES-1`

|Inventory-row activation
|Validate generation/publication/query/sort/index, retain query and sort, then update pressed row and inspector
|Set visual selection only; preserve hover and camera; do not reveal or focus
|Coherent current city or `M1-PRES-1`

|Camera action
|Preserve facts, query, sort, projected rows, selection, and inspector; clear transient hover without retained-coordinate recompute
|Validate proposed state, redraw, update the numeric district snapshot, atomically accept, then invoke the active coordinator's no-op projection callback

publication, and presenter owners. It invalidates inventory state and frame
work, releases pointer capture, removes query, sort, row, Reset, context-loss,
lifecycle, and resize listeners, deletes the one fill program, two VAOs, and
four buffers, clears both instance staging arrays, numeric projection
snapshots/callbacks, inventory and inspector nodes, camera, and visual state,
and removes the canvas. After actual context loss, cleanup makes no WebGL
deletion or restoration call but still releases every JavaScript owner and
reference.

== Failures and privacy

Show exactly one category and, where assigned, one stable code. Never show raw
source, path, parser, provider, or renderer diagnostics.

[cols="2,2",options="header"]
|===
|Category |Code

|Invalid input |None
|Repository unavailable for anonymous access |None
|Revision unavailable |None
|Provider/resolution failure |None
|No supported modules |`ADM-06` or `ADM-07`
|Source admission failed |`M1-ADM-1`, `M1-ADM-3`, or `M1-ADM-4`
|Repository exceeds Code City limits |None
|Metric processing failed |`M1-MET-1`
|City construction failed |`M1-CITY-1`
|Presentation failed |`M1-PRES-1`
|===

An outer `SUCCESS` missing its own `city` key or having invalid outer keys,
type, generation, or revision uses the existing uncoded protocol-failure path.
A present city with missing or invalid geometry or inspection fails the complete
attempt as `M1-CITY-1`. Every failure after a validated city exists,
including semantic staging, publication, dimensions, camera, matrix, picking,
listeners, visual update, WebGL, context loss, or teardown, is `M1-PRES-1`.
Stale generations, sessions, tokens, callbacks, and frame epochs only clean up.
There is no new category, raw diagnostic, retry, fallback, restoration, or
partial city.

Canonical paths pass through provider acquisition and the browser worker
presentation message: successful paths are inspection facts and
sanitized failures are failed-file rows. Browser publication places those paths
only in inert `<bdi dir="auto">` nodes assigned through `textContent` in the
analyzed list, selected inspector, and separate `Not analyzed files` list. The
inventory query remains browser-local, and filtering, sorting, or selection adds
no provider or HTTP call. Interaction derives no path- or query-based attribute,
object key, URL, log, WebGL value, telemetry, or evidence payload and sends no
source payload. Only explicit unit activation sends bounded source text to
its read-only inspector, as specified in xref:unit-inspection.adoc[Unit Source
Inspection]. Source never becomes HTML, executable code, asset URLs or WebGL
values. Provider locators/diagnostics, parser internals, credentials and
telemetry remain excluded from file interaction and release evidence. Packaged-browser
evidence compares controlled synthetic fixture values and emits only scenario,
count, and numeric rendering summaries; it does not emit source bodies.

== Whole-core non-goals

The approved whole core excludes:

* automatic camera movement after initialization;
* favorites, bookmarks, or account features added for them;
* history exploration, tag management, commit links, generic arbitrary refs,
  watching, or scheduling; explicit branch/release inputs and saved snapshots
  are supported.
* private repositories, non-GitHub providers, uploads, archives, or local
  folders;
* source editing or automated fixes;
* dependency analysis;
* threshold findings, warnings, grades, or recommendations;
* AI guidance;
* telemetry;
* configurable metric or visual mappings; and
* a downstream API.

Portable source-bearing export and import is deliberately absent from this
non-goal list because its representation, format, and I/O contract remain
unresolved.

== Current baseline boundaries

The current implementation has browser-owned acquisition and analysis in a
dedicated Web Worker. After complete acquisition, supported per-file failures
continue as `Source text is not supported`, `Syntax could not be analyzed`, or
`Metrics could not be computed`; successful files form the city. The worker
retains the normalized source association locally and sends the main context
validated city data and sanitized failure rows. The asset host owns no analysis
session, unsaved source/result dataset, or analysis capacity. Only explicit
Save uploads complete snapshots to the separate file store.

The browser exposes every successful fact through the browser-local
searchable and three-way sortable inventory behind Find file, with one shared
canonical-index selection across rows, buildings, and the raw file-metric inspector. The active
composition mounts no contextual district row and no persistent complexity
legend. Selection, filtering, and sorting do not invoke search reveal, move or
focus the camera, or alter the presenter's independent orbit, pan, zoom, resize,
and Reset navigation. This implements only the file-level portions of
CC-CORE-INV-01 and CC-CORE-INV-03. The retained legacy semantic row, legend,
and search-reveal capabilities are historical implementation references, not
current standalone behavior.

The current milestone implements read-only unit source and owned contribution
inspection for fresh and saved investigations. It has no source editing,
portable interchange, or recursive hierarchy.
Two-segment geometry and camera navigation remain unchanged; picking also
supports district platforms. The inventory changes no admission, syntax, metric formula, source
limit, provider, privacy, failure-category, retry, fallback, or canonical city
keyboard traversal policy and adds no GPU readback, BVH, alternate publication
path, projection toggle, or camera-collision policy.
