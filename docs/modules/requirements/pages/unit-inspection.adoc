= Unit Source Inspection

The approved investigation behavior and ordering are defined in
xref:city-and-failures.adoc#CC-CORE-INV-01[Shared File Selection] through
xref:city-and-failures.adoc#CC-CORE-INV-04[Investigation Evidence Only].

== Current interaction

Selecting a building or file-list row shows raw file metrics and executable
units. It does not open source or move the camera. Unit rows identify kind,
normalized source range and exact recorded complexity. Kind labels use readable
names: `Arrow function` for JS/TS arrows, `Lambda expression` for C# lambdas,
and `Top-level code` for the file-level unit. A zero-unit file says
`No executable units.`; no synthetic unit or complexity is invented.

Activating a unit explicitly opens a native read-only source dialog. An
explicit callable shows its exact normalized syntax span; top-level shows the
whole normalized file. The header's complexity and range describe the whole unit;
the separate `Shown source` range describes the currently rendered page. Source
has one-based line numbers. Locations use
one-based Unicode scalar columns, with tabs counting as one column; range ends
are exclusive. This is normalized analyzed text, not an editable copy or a
promise of original CRLF/BOM presentation.

Source uses pinned Shiki 4.5.0 grammars for JS/JSX, TS/TSX and C#, selected only
from the admitted file suffix, with one bundled `github-dark` theme and the
standard Oniguruma regex engine, with its WASM bytes bundled in the worker. Coloring keeps whole-file lexical context across unit
and page boundaries, including multiline comments, templates and interpolated
strings. It is a reading aid, not semantic validation or type checking. No language
detection, repository-controlled grammar or theme, CDN or runtime asset fetch is
used. The existing WASM permission also covers the highlighting engine. See xref:architecture:adr/0017-offline-shiki-source-highlighting.adoc[ADR 0017].

Opening source shows syntax coloring without ownership highlights. Selecting a
contribution from the list underlines only that record's exact span within the
shown page, with a distinct background that preserves syntax colors. Other owned
spans, including overlapping records, are not added to the highlight. The source
status names the selected kind and full end-exclusive range; the current list row
is visually and accessibly identified. Selecting another contribution replaces
this highlight. Manual Previous/Next source navigation, changing units, closing
or disposing the view clears it. List scope and pagination do not select a new
contribution or change the current highlight.
The contribution list defaults to `Shown source`: include only this unit's recorded
spans intersecting the rendered source window, using half-open normalized byte
ranges. Show the visible-scope total separately from the whole-unit total. A record
ending at the page start or starting at its exclusive end is not in that page.
Spans continuing outside the page keep their exact full locations and say so.

`Whole unit` explicitly lists all owned contributions, still in bounded pages.
Activating a native contribution-location button shows source starting at that
record's retained start byte, returns to `Shown source`, scrolls the source dialog
to its top and focuses the code. This also works when the location was selected
from far down a long contribution list.
Previous source returns through navigation history. This moves only the source
window, not the city camera, selection or geometry. It performs no provider read,
parsing or metric computation. Selecting a different record with the same source
start rerenders the existing page without another source request. Highlight
boundaries use the recorded Unicode scalar locations, not UTF-16 or byte columns;
a span extending beyond the page is clipped for display, not changed in evidence.
Nested units' contribution records are not added to the parent's list. A unit of complexity one has no branching
contributions. No finding, threshold, recommendation, or source edit is added.

The city remains the default view. Close source or Escape returns to the unit
control. Source navigation does not orbit, pan, zoom, reveal, rebuild geometry,
or change file/district selection. A changed file, district, cleared selection,
replacement, or page exit disposes the old inspection view. Late replies cannot
reopen or populate it. Inspection errors stay local to the inspector and do not
discard the completed city or prevent Save. Grammar, initialization or tokenization
failure preserves exact plain source, paging and selected-contribution underlines,
with `Syntax coloring unavailable.` shown locally. There is no automatic coloring
retry or fallback lexer.

== Bounded presentation, complete evidence

Unit and contribution lists use 32-row pages. Source pages contain at most
8,192 UTF-8 bytes and 80 line feeds and never split a Unicode scalar. A long
single line can continue on the next page at the displayed column. Previous and
Next expose the complete span; these windows do not truncate, sample or change
analysis inputs, unit counts, metrics or saved snapshots.

Original analysis retains packed unit/observation tables, finalized complexities
and recorded decision-owner runs independently of the Save-only capture budget.
Only the currently inspected file is indexed for presentation. The worker sends
bounded unit/location metadata on file selection and source text only after
explicit unit activation. Shiki initializes asynchronously in the existing browser
worker on explicit source opening; it does not initialize the analysis parser,
compute metrics or change saved evidence. The five bundled grammars are
self-contained in the pinned release. Complete-file tokenization precedes page
clipping, with no line-length or time-budget truncation of lexical context. Token
spans are ordered, non-overlapping, scalar-aligned and bounded by the source page;
only fixed, vetted theme-palette indices cross the inspection boundary. Theme
font decorations are not applied: underlines remain reserved for the selected
owned contribution.
The UI creates inert text/span/mark nodes, never HTML, imports, asset URLs or
executable code from source.

Fresh and reopened investigations use the same presentation reader. A reopened
xref:saved-investigations.adoc[snapshot] supplies its stored unit and
contribution facts; no migration, GitHub acquisition, parser initialization or
metric reanalysis is required. Inspection sends no request to the server and
does not save automatically. It uses local generation, revision, file and
request identities, source-page cursor and contribution scope to reject stale or
mismatched replies. Changing source clears old contribution rows while loading;
late replies and detached location buttons cannot populate or navigate another
page or unit. At most one pending
request per inspection operation is retained. The browser's actual heap and
latency remain device-dependent, not input-envelope guarantees.
