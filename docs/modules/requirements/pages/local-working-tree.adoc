= Local Working-Tree Analysis

Status:: Implemented

== Scope and custody

Internal ADO checkouts and local working trees are the real use case. Select a
folder on the user's computer, then explicitly Analyze the files on disk,
including uncommitted edits. Public GitHub remains supported. Direct ADO
credentials/acquisition, Git tracking/ignore interpretation, native agents,
server filesystem APIs, watchers and repository execution are not introduced.

The browser owns read-only acquisition, parsing, metrics, city and inspection.
Before explicit Save no local source, paths, names, hashes, metrics or results
leave the browser. Fixed application/parser asset loads are permitted. Use only
synthetic fixtures for implementation and qualification; do not open internal
repositories or transmit private material to a coding assistant.

== Folder access and inclusion

Use the browser's read-only directory picker in a secure desktop Chromium
context. Unsupported environments show a local unsupported message and keep
GitHub input usable. Denied/cancelled selection leaves an existing completed
investigation unchanged. Selection alone never starts analysis or persistence.
Do not fall back to recursively enumerating a complete FileList: multi-gigabyte
checkouts require pruning excluded directories before descending into them.

Include supported-suffix regular files, whether tracked, untracked or ignored,
after the xref:automatic-exclusions.adoc[automatic catalogue, exact-root include
exceptions and captured manual exclusions]. Prune excluded directories before
entering them or reading their files. Do not read or interpret
.gitignore or Git metadata. Skip .git files/directories at every depth with a
case-insensitive local metadata rule. Nested checkouts and already populated
submodule directories are ordinary physical contents after exclusions. Never
fetch missing submodules or follow a link outside the selected root.

Validate native relative paths/NFC collisions and preserve canonical unsigned
UTF-8 ordering. Enumerate without recursion on the JavaScript call stack. An
unreadable directory or eligible file, permission loss, disappearance or reported
modification fails the whole capture; do not publish a partial city or retry
automatically. Unsupported source text remains a recorded per-file outcome.

Qualification must exercise real directory APIs, links/junctions, access failures
and browser/OS support. Do not claim a mocked handle proves native selection, or
ship an unqualified fallback when the selected mechanism fails its boundary.

== Bounded, non-atomic capture

Keep the existing 4,000 admitted files, 2,097,152 normalized UTF-8 bytes/file,
41,943,040 normalized bytes/attempt and bounded raw-read guards. Up to eight
owned reads may overlap; consume in canonical order and stop/drain on the same
whole-attempt failures. Reuse normalization, supported per-file continuation,
parser/metric definitions, cancellation and stale-publication suppression.

A working tree is not an immutable Git commit or atomic filesystem snapshot.
Identify the actual eligible captured bytes with a versioned SHA-256 manifest of
canonical paths, raw lengths/digests and inclusion policy/exclusions, including
unsupported-text outcomes. The root's display name is not content identity.
A fresh Analyze enumerates the folder again; files created after an enumeration
are not magically part of that captured set. Never manufacture a GitHub URL,
Git commit, remote blob identity or provenance certification claim.

Show the local folder name and `Working-tree capture` identity, not `Commit`.
Before the capture ID exists, correlate progress by local session/generation;
afterwards use the actual content identity. No invented percentage, latency,
physical-memory or whole-checkout-capacity promise is added. Explicit Cancel
terminates the read-only local worker, including during native enumeration/getFile
operations that cannot reliably be aborted; canonical failures drain their owned
read window. Replacement and late
responses cannot restore an older investigation.

== Shared source-bearing Save

The user explicitly requires full code drill-down for every admitted analyzed
file, not a top-N sample. Save results plus one copy of the normalized analyzed
source. Do not archive the checkout, repository metadata, dependencies, build
outputs, assets, original raw duplicates or unsupported binary source payloads.
All input methods use this source-once rule. The normalized-source budget remains
40 MiB; metadata, geometry and container budgets remain separately bounded.

Save is explicit. The user chose no login: everyone who can access the Code City
instance can read saved investigations and their retained code. State that shared
visibility in the local UI. This does not authorize new network exposure, TLS
configuration, Internet hosting, automatic upload or access to internal repos.

The version-4 snapshot records tagged GitHub/local origin, capture/revision
identity, applied recorded exclusion policy, hierarchy, outcomes, metrics, units/contribution ownership
and normalized byte locations, fixed presentation evidence and one hashed
normalized source section per retained text file. Successful files and valid
text with syntax/metric failures retain their normalized text; unsupported text
retains its path/outcome without raw payload. Reopen restores the same city and
full code inspection without acquisition or metric reanalysis.

Version 2 source-payload snapshots are unsupported by the new reader, consistent
with the accepted pre-production policy. Preserve stored files: no migration,
rewrite, implicit relayout or deletion. Older receipt metadata may remain visible
in the picker; unsupported snapshot opens fail locally and must not brick new
Save/catalog operations. Snapshot validation is structural/hash/boundary/presentation
validation in the isolated worker, not metric or provider certification.

== Qualification

Prove local folder selection through acquisition, Analyze/Cancel/replacement,
city, complete file/unit/contribution inspection, explicit shared Save, host
restart and fresh-context source-bearing reopen. Cover uncommitted edits,
excluded huge subtrees never entered, limits, canonical ordering, path failures,
read/change/delete/permission failures and source identity changes. Observe page
and worker requests: local analysis and inspection emit no repository data or
GitHub/ADO traffic; only explicit Save uploads the bounded source-once snapshot.
Preserve existing GitHub, deterministic presentation, no-camera selection,
package/reproducibility and shutdown regressions. Report browser/OS qualification
limits honestly; do not treat serving smoke checks as universal hardware evidence.
