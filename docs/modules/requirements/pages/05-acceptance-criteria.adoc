= Acceptance Criteria

These Given/When/Then scenarios are inert documentation examples for the input,
revision, and state contract. They define reviewable behavior but are not
executable fixtures, test scaffolds, provider stubs, or a choice of test
technology. Source-admission and limit scenarios are in
xref:07-source-admission-and-limit-acceptance.adoc[]. Fixed metric matrices and
examples are in xref:09-fixed-metric-acceptance.adoc[]. Fixed city, layout,
presentation-lifecycle, and post-`Success` failure examples are in
xref:11-fixed-city-layout-and-presentation-acceptance.adoc[].

The input/revision/state contract is acceptable only when all scenarios below
agree with xref:04-functional-requirements.adoc[] and all of these gates hold:

* a reader can classify an input, determine the selected immutable identity,
  and determine every observable state without an implementation assumption;
* no scenario introduces credentials, a revision selector, a second input,
  persistence, configuration, or a stale/partial city;
* a human explicitly accepts the exact documentation revision containing the
  product choices; and
* `npm run docs:build` succeeds.

A passing build alone is not product acceptance.

== Documentary identities

The scenarios use these illustrative full commit IDs:

[source,text]
----
revision-a = 1111111111111111111111111111111111111111
revision-b = 2222222222222222222222222222222222222222
revision-c = 0123456789abcdef0123456789abcdef01234567
----

No scenario depends on the illustrative repositories existing on GitHub.
Provider conditions are part of each documentary Given clause.

== Initial state

[source,gherkin]
----
Scenario: A fresh session is empty
  Given no Code City session state is retained
  When the user opens or reloads Code City
  Then the state is Initial
  And the one URL input is empty and editable
  And submit is available
  And no status, revision identity, history, or city is visible
----

[source,gherkin]
----
Scenario: Typing creates a draft without leaving Initial
  Given Code City is Initial with an empty URL input
  When the user types "https://github.com/acme/city" without invoking submit
  Then the state remains Initial
  And the input contains that URL as an unsubmitted draft
  And submit remains available
  And no loading, cancellation, success, or failure status appears
  And no provider interaction, revision identity, or city appears
----

== Accepted input and successful identity

[source,gherkin]
----
Scenario: Edge whitespace and repository letter case normalize deterministically
  Given GitHub makes a public repository available anonymously
  And its canonical repository URL is "https://github.com/OctoOrg/city-demo"
  And its default branch tip at resolution is revision-c
  When the user submits "https://github.com/octoorg/CITY-demo"
       with two U+0020 characters before it and one U+0009 character after it
  Then only those edge-whitespace characters are removed
  And the accepted attempt enters Loading with no city
  And provider interaction contains no user or service credential
  And after resolution the shown result identity is
       ("https://github.com/OctoOrg/city-demo", revision-c)
  And the full lowercase commit ID, not a branch or abbreviated ID, is shown
  And after every M1 stage succeeds one complete city appears with that identity
  And the input contains "https://github.com/OctoOrg/city-demo"
----

== Immutable selection

[source,gherkin]
----
Scenario: Default branch movement cannot change an existing attempt
  Given a public repository's GitHub-designated default branch points to revision-a
  When a syntactically accepted submission resolves the repository
  And the default branch later moves to revision-b
  Then the current attempt remains pinned to revision-a
  And any successful city is labelled with revision-a
  When the user submits the same canonical repository URL again
  Then the replacement is a new attempt
  And that new attempt may select revision-b
----

[source,gherkin]
----
Scenario: An empty public repository has no fallback revision
  Given a repository is publicly available anonymously
  And GitHub identifies no default-branch tip commit for it
  When the user submits its canonical-form URL
  Then the state becomes Failure with category Revision unavailable
  And no main, master, tag, prior revision, or prior city is substituted
  And no commit identity or city is shown
----

== Invalid and non-canonical input

Each value in this table is rejected rather than repaired:

[cols="3,3",options="header"]
|===
|Submitted value after edge trimming |Reason

|`http://github.com/acme/city`
|The scheme is not exact lowercase `https`.

|`https://www.github.com/acme/city`
|The host is not exact lowercase `github.com`.

|`https://github.com/acme/city/`
|A trailing slash creates a non-canonical path.

|`https://github.com/acme/city.git`
|The clone suffix is excluded.

|`git@github.com:acme/city.git`
|SSH/scp clone syntax is not a web URL in the grammar.

|`https://github.com/acme/city/tree/main`
|The URL has extra path segments and attempts to identify a branch.

|`https://github.com/acme/city?tab=readme`
|Queries are excluded.

|`https://github.com/acme/city#readme`
|Fragments are excluded.

|`https://github.com/acme/repo%2Fother`
|Percent encoding is not decoded or accepted.

|`https://github.com/acme--team/city`
|The owner contains adjacent hyphens.

|`https://github.com/acme/city https://github.com/acme/other`
|The value contains a second input and internal whitespace.
|===

[source,gherkin]
----
Scenario: Invalid replacement cannot leave a stale city
  Given Success currently shows a complete city for revision-a
  When the user submits any invalid/non-canonical value from the table
  Then the prior city and revision-a identity are invalidated
  And no provider interaction occurs for the invalid value
  And the state is Failure with the canonical form explained
  And no city or commit identity is visible
----

[source,gherkin]
----
Scenario: Editing a failed submission does not clear its status
  Given the state is Failure for a submitted "https://github.com/acme/city.git"
  And the invalid/non-canonical explanation describes that failed submission
  When the user edits the input to "https://github.com/acme/city"
       without invoking submit
  Then the edited URL is preserved as an unsubmitted draft
  And the state remains Failure
  And the explanation remains associated with the failed ".git" submission
  And no loading status, cancel action, provider interaction, identity, or city appears
----

== Anonymous unavailable repository

[source,gherkin]
----
Scenario Outline: Anonymous unavailability does not reveal repository existence
  Given a syntactically accepted canonical-form URL
  And anonymous GitHub access reports <condition>
  When the user submits the URL
  Then the state is Failure with category Repository unavailable for anonymous access
  And the normalized URL remains editable
  And no credential prompt, private-repository confirmation, commit identity, or city appears

  Examples:
    | condition     |
    | not found     |
    | private       |
    | access denied |
----

== Provider or resolution failure

[source,gherkin]
----
Scenario Outline: Provider failure has no fallback result
  Given Success currently shows a complete city for revision-a
  And the replacement URL has accepted syntax
  When anonymous resolution encounters <condition>
  Then the old city and revision-a identity are absent
  And the state is Failure with category Provider/resolution failure
  And the replacement URL remains available for explicit resubmission
  And no automatic retry, credential prompt, invented revision, or fallback city occurs

  Examples:
    | condition                 |
    | network interruption      |
    | anonymous rate limit      |
    | provider unavailable      |
    | invalid identity evidence |
----

== Replacement and latest-attempt ownership

[source,gherkin]
----
Scenario Outline: A loading outcome preserves a post-submission draft
  Given "https://github.com/acme/repository-a" is the current Loading attempt
  When the user edits the input to "https://github.com/acme/repository-b"
       without invoking submit
  Then repository B is an unsubmitted draft
  And repository A remains the current attempt with loading status and cancel available
  When the repository A attempt <outcome>
  Then the state becomes <state>
  And the input still contains the unsubmitted repository B draft
  And every visible status, identity, or city describes repository A, not repository B

  Examples:
    | outcome                                    | state   |
    | completes successfully at revision-a       | Success |
    | has a provider/resolution failure           | Failure |
----

[source,gherkin]
----
Scenario: Only the latest replacement may publish
  Given Success shows repository A at revision-a
  When the user submits an accepted URL for repository B
  Then repository A's city and identity disappear immediately
  And repository B is Loading with no city
  When the user submits an accepted URL for repository C before B completes
  Then B becomes ineligible to publish
  And repository C is the only current attempt
  When a late success for B arrives
  Then the visible state does not change
  And no city for B appears
  When C completes successfully at revision-c
  Then exactly one complete city for repository C at revision-c appears
----

[source,gherkin]
----
Scenario: A failed replacement cannot restore the previous city
  Given Success shows repository A at revision-a
  When a replacement for repository B begins
  And a later M1 stage for B fails after revision-b was selected
  Then the state is Failure and identifies repository B at revision-b
  And neither repository A's old city nor a partial city for B is visible
----

== Cancellation

[source,gherkin]
----
Scenario: Cancelling loading is final for that attempt
  Given an accepted submission is Loading
  And its identity has resolved to revision-b
  When the user invokes cancel
  Then the state is Cancelled
  And the current input draft remains editable
  And the loading status, cancel action, revision-b identity, and every city are absent
  When any late success or failure for the cancelled attempt arrives
  Then the visible state remains Cancelled
  And no city or new status appears
----

[source,gherkin]
----
Scenario: Editing during loading and cancellation changes only the draft
  Given repository A is the current Loading attempt
  When the user edits the input to a URL for repository B without invoking submit
  Then repository A remains Loading with its loading status and cancel action
  And repository B is only an unsubmitted draft
  When the user invokes cancel
  Then the state is Cancelled
  And the repository B draft is preserved
  And the neutral cancellation confirmation is visible
  When the user edits the input to a URL for repository C without invoking submit
  Then the state remains Cancelled with the same cancellation confirmation
  And repository C is the preserved unsubmitted draft
  When any late outcome for repository A arrives
  Then the repository C draft and Cancelled state remain unchanged
  And no revision identity, city, or new status appears
----

== No partial publication

[source,gherkin]
----
Scenario Outline: An unfinished journey never exposes a partial city
  Given the current attempt has no complete city
  When <event> occurs before every required M1 stage succeeds
  Then no building, partial scene, unlabelled city, or prior city is visible

  Examples:
    | event                         |
    | processing remains in flight |
    | source admission fails        |
    | a resource limit fails        |
    | metric processing fails       |
    | city construction fails       |
    | presentation fails            |
----

The detailed source-admission and approved repository/intake-limit causes,
codes, and wording are in xref:06-source-admission-and-limits.adoc[] under
https://github.com/FelixGeisler/code-city/issues/442[#442]. Fixed metric rules
and their inert review examples are in xref:08-fixed-metric-semantics.adoc[] and
xref:09-fixed-metric-acceptance.adoc[] under
https://github.com/FelixGeisler/code-city/issues/443[#443]. Fixed city and
presentation rules and their inert review examples are in
xref:10-fixed-city-layout-and-presentation.adoc[] and
xref:11-fixed-city-layout-and-presentation-acceptance.adoc[] under
https://github.com/FelixGeisler/code-city/issues/444[#444]. These scenarios fix
the common observable state invariant without redefining those contracts.

== Post-success presentation failure

[source,gherkin]
----
Scenario Outline: The current published presentation cannot remain Success after it fails
  Given Success shows one complete city for the current canonical repository URL and full commit ID
  And the input contains its current draft, which may be a post-submit edit
  When <failure> occurs for the current published presentation
  Then the state synchronously becomes Failure
  And the category is "Presentation failed"
  And the code is "M1-PRES-1"
  And the complete city and canvas are removed
  And the presentation is disposed
  And the current canonical repository URL, full commit ID, and input draft remain
  And no earlier city, replacement, retry, alternate renderer, or fallback appears
  When the user edits the input without submitting
  Then the same Failure remains and only the unsubmitted draft changes

  Examples:
    | failure                                  |
    | its WebGL context is lost                |
    | its required passive-resize render fails |
----

[source,gherkin]
----
Scenario: A stale presentation callback cannot change current visible state
  Given an older candidate or presentation is no longer publication-eligible
  When its queued WebGL context-loss or resize callback runs
  Then it performs only local idempotent disposal
  And the current input draft, state, status, identity, and city do not change
----

Only resubmit or reload leaves the post-`Success` `Failure`; editing alone does
not. Detailed classification, drawing-buffer, resize, context-loss, and cleanup
examples are in
xref:11-fixed-city-layout-and-presentation-acceptance.adoc[].

== Excluded controls and retention

[source,gherkin]
----
Scenario: M1 has one input and no credentials or configuration
  Given Code City is in any stable state
  Then the only user-supplied value is the repository URL
  And there is no credential, owner, repository, branch, tag, commit, source,
      building, metric, layout, palette, limit, history, save, share, or export control
  And the selected full commit ID, when shown, is read-only output
----

[source,gherkin]
----
Scenario: Reload does not restore state
  Given any input draft, attempt, result, failure, or cancellation exists in the current session
  When the user reloads Code City
  Then the state is Initial
  And the input is empty
  And no prior identity, status, city, recent repository, or history is restored
----
