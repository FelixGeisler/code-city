= Runtime View

== Asset-host startup

The CLI accepts port, optional bind/canonical host and `--data-dir`, validates the exact
version-1 package manifest, and verifies the length and SHA-256 digest of every
public record before listening. It preloads only those verified asset bytes
and prints `READY`. Startup does not validate private implementation bytes;
the offline package audit verifies complete public/private manifest closure and
every recorded byte before publication.

There is no application analysis session, worker reservation, retained source
budget, or analysis route. Native SIGINT/SIGTERM close the listener and static
connections, abort/settle owned storage work and validation workers, then print
`SHUTDOWN`. Host shutdown does not discard an already
loaded browser-owned completed view.

== Analyze

. The main context validates input and captured exclusions and assigns a local
  generation. It creates a dedicated browser worker only for valid Analyze.
. GitHub input resolves an immutable revision and validates complete inventory.
  Local input transfers the read-only directory capability, prunes exclusions
  before descent and hashes actual captured bytes/settings. Bounded acquisition
  windows retain unconsumed reads and consume canonically; failure ordering and
  settlement remain requirement-owned. Local progress precedes final capture ID;
  no dummy commit is emitted.
. The same application sequence initializes the pinned parser once, processes
  supported files with per-file continuation, reports completion after cleanup,
  and constructs the deterministic city.
. The worker retains normalized source for text-valid files and bounded
  unit/contribution evidence for explicit source-once Save. Packed unit tables,
  finalized complexities, observations and decision-owner runs support inspection
  independently of the Save budget. Unsupported binary text has no persisted
  source section. Capture-budget exhaustion disables saving, not analysis or
  unit inspection. It publishes presentation data and failure rows to the UI.
. The main context validates event shape, local identity, generation, revision,
  monotonic phase counts, and city payload before presentation. Inventory,
  inspector, and existing presenter commit as one local publication.

The worker emits real `0/N` and `0/T`, subsequent considered/cleaned-up counts,
and initialization/construction stage events. The controller maps these onto
xref:requirements:city-and-failures.adoc#browser-investigation-workspace[one monotonic work budget];
only successful presentation completes the bar. No HTTP progress stream,
server write queue, clock-driven percentage, or ETA exists.

== Stop, replacement, and loss

Before cancellation or replacement can publish another result, the old attempt
is ineligible. During provider activity, STOP aborts its signal and the source
window settles all owned reads; the cancellation/terminal acknowledgement
permits worker release. Local read-only directory work owns no provider request
or write; its worker is terminated immediately because native enumeration/getFile
promises cannot reliably be aborted. After acquisition, termination does not wait for a busy
synchronous parser to receive a message. No browser worker-exit event is assumed.

Only the newest queued local replacement creates another worker. Old messages
cannot publish. Cancel after a terminal result is a no-op. There is no separate
Discard UI action or server investigation to release. Page exit terminates owned
work, and worker errors revoke
the corresponding local investigation. Another tab is unaffected.

== Unit inspection

File selection asks the completed worker for a bounded unit page. The worker
indexes only the selected file's retained facts and normalized byte/line mapping.
Explicit unit activation requests a source window and a page of recorded owned
contributions. This does not initialize a parser, reacquire source, recompute
metrics or send HTTP requests. Saved investigations adapt their version-4
stored tuples to the same reader. Explicit source opening also lazily initializes
Shiki's bundled Oniguruma highlighting engine in this worker; it emits validated
palette-indexed text spans, not HTML. This is distinct from the analysis parser.

The transport retains at most one pending read per operation kind and validates
result shape, revision, path, source-page cursor, contribution scope and request
identity. Contribution locations carry retained byte cursors for local source
navigation. The view additionally gates asynchronous replies by source-page and
file/dialog lifetime. The shell forwards source-edit and picker-initiation intent
to the unit view's cancellation epoch; programmatic saved-setting restoration
does not dispatch those user-edit events. The presentation keeps selected-details
ownership separate from lookup visibility: lookup temporarily hides the details
surface without disposing its selected content or native top-layer dialog. The
covered canvas is temporarily inert while lookup owns the focus surface; toolbar
controls remain available. Toolbar hints dismiss on document capture but consume
Escape only when its target is the visible hint's button; other owners retain
their native or bubbling Escape handling. Rollback removes that capture listener.
The setup form stacks above tools/hints, which in turn stack above lookup; these
layers do not participate in canvas sizing. Native dialogs retain the top layer.
Whole-unit row callbacks are bound to their list page and
unit lifetime, not to the source page reached by selecting them. In-page selection
reuses rendered evidence; an out-of-page whole-unit source read leaves the list
and its row elements intact. Replacement disposes the dialog
and rejects outstanding reads. A queued native close notification cannot clear
a newly reopened dialog. The source view creates inert text/mark nodes, clips the
one selected contribution's scalar-column span to the rendered page, and preserves
the presenter's selection, camera and buffers. Explicit contribution activation
bounds scroll adjustments to the source section, stacked body and code pane, in
that order, before focusing code with native auto-scrolling suppressed. This
accounts for wrapped guidance and retained source-section offsets without moving
the sibling contribution region or list. This transient highlight does not
change the retained evidence, inspection protocol or saved format. Product paging and
location rules are owned by
xref:requirements:unit-inspection.adoc[Unit Source Inspection].

== Save and reopen

. Save exports the completed worker-owned snapshot; no acquisition or parser
  invocation occurs. The worker uploads directly to the same-origin host.
. The store reserves its single write, streams into an owned staging directory,
  and validates structure, source hashes/byte references and presentation in
  an isolated native worker. It never computes metrics from source.
. After file synchronization and atomic directory rename, the host returns an
  immutable ID and receipt. Failure leaves the browser result usable; an
  interrupted staging directory is never catalogued.
. A `/saved/<id>` page loads receipt and container into a new browser worker.
  It verifies hashes and version, restores retained source/evidence and
  publishes the recorded city. GitHub and parser initialization are not used.

The header binds the validated current origin/revision to the project-name
native title; it has no separate identity disclosure/output. Clear and cancel
remove the binding; correlated post-selection failures retain it. Save/reopen
shows plain Saved status with UTC time in its native title and hides Save;
result publication preserves that saved state. The canonical address stays in
browser history, with no clipboard API path. Replacement clears status/time
and saved state using the existing UI epoch guard; stale Save completion or
failure cannot alter the replacement's controls or history.

The picker reads only receipt metadata and groups by input kind and
repository/folder; refs/commits and local captures coexist under random IDs. Capacity, corruption and operator recovery are owned
by xref:requirements:saved-investigations.adoc[Saved Investigations].

== Qualification

`npm run dev -- --port <port>` builds under `build/development/` and starts the
same asset host, with no HMR or WebSocket and no write to canonical `dist/`.

Installed-Chrome/CDP evidence uses the actual packaged UI, worker, parser and
GitHub gateway. A nonshipped provider intercepts fixed GitHub requests with real
CORS and integrity checks. Explicit message-delivery gates exercise real phase
counts in the UI; they do not fabricate progress. Evidence covers independent
idle/completed tabs, four grammars, source limits, slow-first acquisition,
provider/parser cancellation, replacement, page loss, no server analysis commands, and
a healthy 4,000-file / 40 MiB normalized-source attempt. Tests are not device,
latency, or total-memory guarantees.

Evidence also saves the maximum envelope, preserves the scene on failed Save,
restarts the host, and reopens in a fresh browser context with provider access
blocked and no parser-asset requests. Inspection evidence covers nested owners,
Unicode byte/column mapping, inert HTML-like text, dense long-line paging,
keyboard/mobile source dialogs and fresh/saved operation without network or
camera changes. Recursive presentation remains a later outcome.
