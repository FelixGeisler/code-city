= 6. Runtime View

This view records only the execution-context ownership, generic handoffs,
publication gate, and lifecycle cleanup accepted in
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002].
xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR 0004]
accepts the future `/code-city/` static package and separate same-origin
ES-module worker used by this topology; it does not make that package current
repository behavior. Vite development and preview servers are local tools, not
runtime nodes.
xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR
0005] accepts the exact anonymous revision-resolution REST boundary.
xref:adr/0006-bounded-selected-revision-retrieval-via-github-tree-and-raw-content.adoc[ADR
0006] accepts the exact selected-revision retrieval/admission boundary. Neither
decision makes product traffic current. Outside those decisions, this view does
not select a message or port schema, broader worker lifecycle or bridge
cancellation primitive, parser, analyzer, renderer, or full accepted-mechanism
flow. That synthesis remains with
https://github.com/FelixGeisler/code-city/issues/463[#463].

----

Code City has one UI/presentation main context and at most one same-origin
dedicated processing worker context. It has no additional application runtime
context. The UI makes no provider or repository request. Pages receives no
product data, and no Code City backend, relay, proxy, serverless function,
server runtime, database, queue, service credential, server-side product state,
product persistence, application-managed persistent cache, or second retrieval
path exists.

The only logical trust crossings are *User → UI main context* and *Public
GitHub → processing worker*. Same-origin UI-to-worker communication is not a
trust crossing, Pages introduces no product-data trust boundary, and no user or
service credential crosses any boundary.

The UI/worker split is an execution and lifecycle boundary, not an
operating-system-process guarantee, security sandbox, trust crossing, component
count, package boundary, or source-dependency rule.

== Runtime responsibilities

[cols="3,8",options="header"]
|===
|Context |Accepted ownership

|UI/presentation main context
|Input draft, permitted normalization, canonical grammar validation before
worker dispatch or provider interaction; current-attempt identity and
observable states; replacement and cancellation precedence; canonical URL
updates that preserve post-submission edits; the sole publication-eligibility
gate; presentation adaptation and failure; inert building identities;
presentation-resource cleanup; atomic publication of the complete city and
selected identity; rejection of stale, replaced, cancelled, partial, or late
output; current-session retention and empty reload reset.

|Processing worker
|Direct anonymous repository resolution; canonical identity validation;
one-time immutable-revision selection and pinning; ADR 0006's sequential
selected-commit, recursive-root-tree, and canonical raw retrieval; the sole
admission path and actual-data limit enforcement; deterministic ordering and
metrics; pure renderer-neutral city construction; transient confinement of
provider records, paths, source, admitted modules, counters, metrics, and
construction intermediates; globally one retrieval/admission request and one
raw/hash workspace; stage termination and downstream suppression; attempt
cancellation, latest-only replacement settlement, and application-owned cleanup
under ADRs 0005 and 0006; release of transient processing references.
|===

Repository data remains inert and is never executed, evaluated, imported, or
dynamically loaded. ADR 0005 fixes at most two native Fetch GETs, strict
case-only resolution evidence, immutable-SHA pinning, inclusive 4 MiB bodies,
and application-controlled cleanup. ADR 0006 then fixes two capped REST GETs,
no more than `5,000` sequential raw GETs, bounded own-field/prototype-safe
projection, exact Git blob comparison, one `4,194,317`-byte raw/hash workspace,
and complete cleanup before another request or replacement. Neither ADR makes
a malicious-provider, atomic-provider-state, latency, or compatibility
warranty. UI rejection of a late result remains authoritative. Any
still-deferred downstream worker-side product limit is enforced only after its
owner accepts its exact value and semantics; browser memory, request behavior,
and renderer capacity create no undeclared product limit.

parser/analyzer objects, and canonical metric intermediates never cross into

canonical building identities cross only as inert model keys.

== Current-attempt and publication sequence

The following is a topology-level ownership sequence, not #463's later
mechanism/port synthesis:

. On submit, the UI makes the new submission the only current attempt and
  immediately revokes every prior attempt's publication eligibility before
  validating the new value.
. The UI performs the permitted normalization and canonical grammar validation.
  Invalid input ends in the accepted failure state without worker dispatch or
  provider interaction.
. For accepted syntax, the UI enters `Loading` and hands only the current
  normalized submission to the worker. The worker owns the direct anonymous
  provider and processing stages.
. The worker may hand back the selected canonical repository/revision tuple
  while processing continues. The UI applies it only to the current eligible
  attempt and never overwrites a draft edited after submission.
. Each worker stage either supplies its complete input to the next worker stage
  or terminates the attempt. No admitted set, metric facts, or partial scene is
  published to presentation.
. A complete canonical scene crosses to the UI only after all worker stages
  succeed. The UI owns renderer adaptation and presentation failure.
. The UI's sole publication-eligibility gate admits only the current complete
  result. It atomically publishes the complete city with the selected identity,
  or publishes no city. Every stale, replaced, cancelled, partial, or late
  result is rejected.

== Selected-revision retrieval/admission sequence

Within step 5, ADR 0006 fixes this worker-side order:

. Consume only ADR 0005's canonical owner/repository URL and selected full
  lowercase commit. Never resolve another ref.
. Use the single global request slot for the selected-commit REST GET; validate
  the normalized selected identity and project its full root-tree identity.
. Use that slot for the exact recursive-root-tree REST GET. Enforce the 4 MiB
  and 8 MiB REST caps, complete-inventory rule, own-field primitive projection,
  #442 entry/path/metadata horizons, and candidate-SHA projection. Provider
  tree representations are gone before raw retrieval.
. In canonical unsigned-UTF-8 candidate order, use the same slot for at most one
  raw GET per candidate and at most `5,000` per journey. While the content
  horizon remains open, validate the expected blob SHA, stream into the single
  global workspace, apply RA-04/RA-05, compare exact Git blob identity, then
  strictly decode and normalize once only after agreement.
. Return one complete ordered admitted-module set or one accepted terminal
  result. A failure cancels unread work where feasible, cleans application-owned
  state, starts no later request or stage, and publishes no admitted set.

Each REST/raw request, tree projection, hash, decode, and normalization phase
uses ADR 0006's explicit eligibility checks and release order. Globally no
replacement or other attempt starts retrieval/admission work until the old
request, read/cancel operations, non-abortable JSON/digest/decode work, reader
lock, workspace, inventory, and unpublished output have settled and been
cleaned. Submissions waiting during settlement coalesce to the latest only.

== Replacement, cancellation, failure, and cleanup

=== Replacement or cancellation

. The UI immediately revokes the old attempt's publication eligibility and
  clears identity, city, and presentation state as the accepted state contract
  requires. Cancellation preserves the editable draft; replacement installs
  the new submission before its validation result.
. Generic lifecycle control may tell the worker that the attempt is no longer
  current. This view selects no bridge message, port, or broader lifecycle
  primitive; ADRs 0005 and 0006 require the current-attempt `AbortSignal` for
  their exact resolution and retrieval Fetches.
. The worker stops feasible network and processing work where the accepted
  mechanisms permit it, suppresses every downstream stage, and releases
  transient references for the old attempt. ADRs 0005 and 0006 require signal
  abort, feasible active-reader cancellation, handled settlement and
  rejections, reader-lock release in `finally`, post-non-abortable eligibility
  checks, complete application-owned cleanup, and suppression of every later
  request or stage. ADR 0006 also prevents replacement overlap and starts only
  the latest submission after old settlement.
. Any tied or late identity, failure, or scene outcome is ignored. UI
  ineligibility remains authoritative even if underlying work completes.

=== Stage or presentation failure

. A worker-stage failure terminates that stage, suppresses all downstream work,
  and releases its transient processing references.
. The worker may return only the one terminal failure outcome. The UI applies
  it only for the current eligible attempt; no stale or partial city is
  published.
. If adaptation of a complete canonical scene fails, the UI owns presentation
  failure and cleanup of every incomplete presentation resource.

After a successful complete-scene handoff, worker processing intermediates do
not become retained product state and are released. Reload discards all
application-managed session state and starts a fresh empty session.

Cleanup has no accepted latency or secure-erasure promise. Cancellation and
replacement revoke publication eligibility immediately but promise no
computation or network stop time. A stalled old settlement may delay replacement
provider work without creating an RA-10/RA-11 timing failure. This view does
not redefine provider, browser, operating-system, network, or platform caching
or garbage-collection internals.

== Feasibility and deferred synthesis

ADR 0005 records https://github.com/FelixGeisler/code-city/issues/448[#448]'s
dated documentary/read-only feasibility for the exact
anonymous resolution calls from production origin
`https://felixgeisler.github.io`, including CORS/preflight and exposed response
evidence, the fixed API version, strict redirect and identity handling, body
bounds, rate behavior, cancellation, and application-controlled release. Its
observations are point-in-time evidence, not service, CORS, size, concurrency,
cleanup, compatibility, security, or privacy warranties. #453 revalidates the
pin and endpoint contract before implementation, and #460 renews hosted-origin
evidence on the final head.

ADR 0006 records #449's dated documentary/read-only selected-revision
feasibility for exact-origin REST/tree and simple raw GETs, immutable-SHA bytes,
Git blob and LFS behavior, Web Crypto, and the codeload rejection. The evidence
is point-in-time only. #454 revalidates before implementation and #460 renews
hosted final-head REST/raw evidence. On ADR 0005 or ADR 0006's stop condition,
implementation stops; #449 is reopened for retrieval drift and
https://github.com/FelixGeisler/code-city/issues/446[#446] is reopened when
topology feasibility is affected. No proxy, relay, backend, serverless
function, credential, persistent cache, opaque unbounded response,
automatic-retry workaround, second retrieval path, or other fallback may be
introduced silently.

The minimum blocks, conceptual ports, bridge boundary, and exclusive ownership
are accepted in
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003].
ADR 0004 is authoritative for the accepted shell/build, base, worker-output,
and core-mechanism constraints. #452 owns their initial implementation, #459
their successful-path integration, and #460 their renewed final-head production
evidence; no dependency, source, configuration, or production artifact exists
yet.

Parser/analyzer and renderer mechanisms, message and port schemas, concrete
source mapping, broader worker and bridge primitives, Pages workflow and route,
and the complete cross-mechanism success/failure/replacement/cancellation
synthesis remain with their stated owners in #450 through #460 and #463.
xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] remains authoritative
for the outer source-dependency boundary, ADR 0005 for resolution, and ADR 0006
for selected-revision retrieval/admission.
