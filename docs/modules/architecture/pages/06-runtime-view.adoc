= 6. Runtime View

This view is the authoritative implementation-independent synthesis of the
accepted M1 runtime flow. It links ADR 0002's execution placement and ADR
0003's exact ports and ownership to ADR 0005 resolution, ADR 0006 retrieval and
admission, ADR 0007 static syntax and phase-aware lifecycle, and ADR 0008
presentation. ADR 0004 supplies only the accepted conceptual `/code-city/`
static package and separate same-origin ES-module worker; Vite development and
preview servers are local tools, not runtime nodes. ADR 0009 fixes the active
M1 branch, sole new-main Pages publisher, and final app-over-docs placement
without adding another runtime node or changing this flow.

The matrices were accepted through
https://github.com/FelixGeisler/code-city/issues/463[#463]. They add no product
behavior, implementation, general message or port schema, transport or
cancellation primitive, worker-creation policy, dependency, traffic, parser
operation, rendering, package, or deployment mechanism.

Code City has one UI/presentation main context and at most one same-origin
dedicated processing worker context. It has no additional application runtime
context. The UI makes no provider or repository request. Pages receives no
product data, and no Code City backend, relay, proxy, serverless function,
server runtime, database, queue, service credential, server-side product state,
product persistence, application-managed persistent cache, or second retrieval
path exists.

The only logical trust crossings are *User → UI main context* and *Public
GitHub → processing worker*. Same-origin UI-to-worker communication is not a
trust crossing, Pages introduces no product-data trust boundary, and no user or
service credential crosses any boundary.

The UI/worker split is an execution and lifecycle boundary, not an
operating-system-process guarantee, security sandbox, trust crossing, component
count, package boundary, or source-dependency rule.

== Publication placement and current state

ADR 0009 accepts an identity-preserving transition from the active M1 `v2` line
to default `main`, with the prior v1 `main` retained as locked `v1`. Only that
new M1 `main` may publish Pages. The final application replaces the frozen
legacy hosted documentation; it is not co-hosted with documentation and gains
no second route, origin, publisher, or runtime context.

This documentation does not claim that transition, workflow, or deployment has
occurred. #464 owns the separate administrative branch/protection/environment
read-back gate. #452 owns exact non-deploying build, CI, and first-party Pages
workflow realization. #460 alone explicitly dispatches the final reviewed
main-line artifact and proves the guarded merge commit, complete manifest, and
production-origin bytes. Exact YAML, event and gate, action versions, artifact
root, source map, emitted filenames, and test mechanism remain deferred to
#452.

This placement table does not collapse ADR 0003's block or port ownership.
Adapters, capabilities, coordinators, bridge halves, and presentation retain
the exact owners identified in the matrices below.

Repository data remains inert and is never executed, evaluated, imported, or
dynamically loaded. ADR 0005 fixes at most two native Fetch GETs, strict
case-only resolution evidence, immutable-SHA pinning, inclusive 4 MiB bodies,
and application-controlled cleanup. ADR 0006 then fixes two capped REST GETs,
no more than `5,000` sequential raw GETs, bounded own-field/prototype-safe
projection, exact Git blob comparison, one `4,194,317`-byte raw/hash workspace,
and complete cleanup before another provider request for a replacement.
Neither ADR makes
a malicious-provider, atomic-provider-state, latency, or compatibility
warranty. UI rejection of a late result remains authoritative. SP-01 through
SP-04 are unnecessary: the complete RA-07/RA-08/RA-09 envelope reaches static
analysis and elapsed analysis time creates no outcome. Browser memory, parser
capacity, request behavior, and renderer capacity create no undeclared product
limit.

== End-to-end runtime synthesis

The following matrices link the accepted contracts and mechanisms without
selecting an executable interface, message schema, transport primitive, worker-
creation policy, or new behavior. Canonical internal artifacts are visible
here to the documentation reader through their producer, consumer, and
placement; admitted modules, metric facts, canonical scenes, and building
identities are not additional user-visible product output. The matrices add no
port, block, owner, admission path, classifier, or orchestrator. The city
constructor remains authoritative for the canonical model; defensive
presentation validation is not a second constructor or classifier. The UI
attempt coordinator alone owns visible state and the publication gate.

If no worker handle exists when cancellation or replacement occurs, the UI
result still applies and no termination event is fabricated. Worker-context
creation timing remains unselected: eager, lazy, and optional idle creation are
neither required nor forbidden. Dispatch and provider start are syntax-gated
instead: accepted normalized input may be dispatched only through a usable
handle; invalid input dispatches nothing and starts no provider request. Any
old usable handle is cleared before any new usable handle; for accepted
replacement, the new usable handle precedes dispatch and the first new provider
request.

The receipt gate remains live while a pre-receipt stop or settlement path is
pending. A matching `PROVIDER_DRAINED_STATIC_ENTERED` receipt attests provider
settlement/global-gate release and immediately switches that generation to the
post-receipt hard path. The bridge does not wait for `ATTEMPT_DRAINED`: it hard-
terminates, clears the old usable handle, then conditionally dispatches only
accepted latest input through a new usable handle before its first provider
request; invalid latest input remains undispatched.

The matrix creates no cancellation, settlement, worker-termination, cleanup,
network-stop, computation-stop, garbage-collection, secure-erasure, or
physical-process timing promise.
