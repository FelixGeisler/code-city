= 6. Runtime View

image::runtime.svg[Successful repository-to-city runtime flow]

== Successful attempt

. Revoke publication rights, dispose any previous presentation, and start one
worker generation.
. Resolve the default-branch head and retrieve one complete admitted source set.
. Release every GitHub request, reader, provider object, raw buffer, and hash
workspace.
. Parse and measure one module at a time, then build one complete city.
. Return one generation-tagged, source-free presentation model.
. Validate and stage WebGL resources before publishing the current result.

Each stage receives one complete predecessor result or does not run. A failure
suppresses later stages and publishes no partial city.

== Worker lifecycle

The main bridge owns one concrete worker handle. New submissions are coalesced
to the latest while an old generation closes.

[cols="2,4,4",options="header"]
|===
|Observed phase |Cancellation or replacement |Completion

|Provider active
|Revoke publication, send Stop, abort and settle GitHub work, release provider
resources, receive `ATTEMPT_DRAINED`, then terminate and clear the worker
|After complete admission and provider cleanup, the worker sends
`PROVIDER_DRAINED_STATIC_ENTERED`

|Static analysis
|After receipt of `PROVIDER_DRAINED_STATIC_ENTERED`, revoke publication,
terminate the worker immediately, and clear its handle
|Send one terminal outcome followed by `ATTEMPT_DRAINED`; then terminate and
clear the worker

|No worker
|Create one worker only for the latest pending submission
|Remain idle until another submission
|===

A provider-phase terminal failure releases provider resources before sending
its outcome and `ATTEMPT_DRAINED`. A replacement worker starts only after the
previous handle is clear. Every message carries the bridge-generated
generation. Stale messages are ignored;
a malformed current-generation message, worker startup failure, crash, or
`messageerror` fails that attempt. Listener and transport cleanup is exactly
once.

The UI coordinator applies the same generation gate to resize and context-loss
callbacks. A disposed presentation session can neither remove nor fail a newer
city.

== Resource lifetime

[cols="2,5",options="header"]
|===
|Phase |Reachable application data

|Provider
|Bounded projected tree evidence, one active request, one raw/hash workspace,
and the accumulating normalised module set. Parser and WebGL resources do not
exist.

|Static
|No provider resource remains. The complete normalised set is bounded by the
published envelope. Fixed parser runtime and loaded grammar modules may remain
for the worker lifetime; only one source module, parser, tree, cursor, and
observation stream is active. Each processed source is released before the
next module.

|Handoff
|Source and parser values are gone. Only the selected commit, terminal outcome,
and bounded presentation model may cross to the main context.

|Presentation
|One detached candidate is staged. Publication replaces and disposes the old
session atomically.

|Terminal
|Owned listeners, references, buffers, parser handles, WebGL resources, and the
worker realm are released at their owning boundary.
|===

There is no automatic retry, fallback parser, fallback renderer, partial city,
or timeout outcome.
