= 6. Runtime View

This view records only the execution-context ownership, generic handoffs,
publication gate, and lifecycle cleanup accepted in
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002].
xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR 0004]
accepts the future `/code-city/` static package and separate same-origin
ES-module worker used by this topology; it does not make that package current
repository behavior. Vite development and preview servers are local tools, not
runtime nodes.
xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR
0005] accepts the exact anonymous revision-resolution REST boundary.
xref:adr/0006-bounded-selected-revision-retrieval-via-github-tree-and-raw-content.adoc[ADR
0006] accepts the exact selected-revision retrieval/admission boundary.
xref:adr/0007-static-syntax-with-pinned-tree-sitter-webassembly-grammars.adoc[ADR
0007] accepts exact static-syntax assets and behavior, the provider/static phase
barrier, two bridge-only lifecycle attestations, and ordinary versus hard-stop

xref:adr/0008-browser-native-webgl2-instanced-city-presentation.adoc[ADR 0008]
accepts exact UI-edge presentation staging, rendering, resize, context-loss,

----

Code City has one UI/presentation main context and at most one same-origin
dedicated processing worker context. It has no additional application runtime
context. The UI makes no provider or repository request. Pages receives no
product data, and no Code City backend, relay, proxy, serverless function,
server runtime, database, queue, service credential, server-side product state,
product persistence, application-managed persistent cache, or second retrieval
path exists.

The only logical trust crossings are *User → UI main context* and *Public
GitHub → processing worker*. Same-origin UI-to-worker communication is not a
trust crossing, Pages introduces no product-data trust boundary, and no user or
service credential crosses any boundary.

The UI/worker split is an execution and lifecycle boundary, not an
operating-system-process guarantee, security sandbox, trust crossing, component
count, package boundary, or source-dependency rule.

== Current-attempt and publication sequence

The following is a topology-level ownership sequence, not #463's later
mechanism/port synthesis:

. On submit, the UI makes the new submission the only current attempt and
  immediately revokes every prior attempt's publication eligibility before
  validating the new value.
. The UI performs the permitted normalization and canonical grammar validation.
  Invalid input ends in the accepted failure state without worker dispatch or
  provider interaction.
. For accepted syntax, the UI enters `Loading` and hands only the current
  normalized submission to the worker. The worker owns the direct anonymous
  provider and processing stages.
. The worker may hand back the selected canonical repository/revision tuple
  while processing continues. The UI applies it only to the current eligible
  attempt and never overwrites a draft edited after submission.
. Each worker stage either supplies its complete input to the next worker stage
  or terminates the attempt. No admitted set, metric facts, or partial scene is
  published to presentation.
. A complete canonical scene crosses to the UI only after all worker stages
  succeed. The presentation adapter defensively validates it before WebGL and
  owns only ADR 0008 adaptation/failure/cleanup; the bridge does not classify.
. The UI's sole publication-eligibility gate admits only the current fully
  staged result. After observer setup, the mandatory final detached host reread
  and any required redraw, and a final eligibility check, it synchronously
  publishes canvas, complete city, and selected identity in one no-yield
  commit, or publishes no city. Every stale, replaced, cancelled, partial, or
  late result is rejected.

== Selected-revision retrieval/admission sequence

Within step 5, ADR 0006 fixes this worker-side order:

. Consume only ADR 0005's canonical owner/repository URL and selected full
  lowercase commit. Never resolve another ref.
. Use the single global request slot for the selected-commit REST GET; validate
  the normalized selected identity and project its full root-tree identity.
. Use that slot for the exact recursive-root-tree REST GET. Enforce the 4 MiB
  and 8 MiB REST caps, complete-inventory rule, own-field primitive projection,
  #442 entry/path/metadata horizons, and candidate-SHA projection. Provider
  tree representations are gone before raw retrieval.
. In canonical unsigned-UTF-8 candidate order, use the same slot for at most one
  raw GET per candidate and at most `5,000` per journey. While the content
  horizon remains open, validate the expected blob SHA, stream into the single
  global workspace, apply RA-04/RA-05, compare exact Git blob identity, then
  strictly decode and normalize once only after agreement.
. Return one complete ordered admitted-module set or one accepted terminal
  result. A failure cancels unread work where feasible, cleans application-owned
  state, starts no later request or stage, and publishes no admitted set.

Each REST/raw request, tree projection, hash, decode, and normalization phase
uses ADR 0006's explicit eligibility checks and release order. Globally no
replacement or other attempt starts retrieval/admission work until the old
request, read/cancel operations, non-abortable JSON/digest/decode work, reader
lock, workspace, inventory, and unpublished output have settled and been
cleaned. Submissions waiting during settlement coalesce to the latest only.

== Provider-to-static phase sequence

Every worker generation begins provider-capable. No dynamic parser-runtime
import, grammar or runtime asset fetch/load, `Parser.init`, parse, or traversal
may begin in that phase. After successful admission the worker retains only the
core-owned complete admitted-module handoff; settles every ADR 0005/0006 fetch,
read, abort, reader cancellation, rejection, JSON parse, Web Crypto, strict
decode, and normalization; releases reader locks; clears every response,
reader, chunk, provider object, inventory, hash view, digest, workspace, and
provider transient; releases the global request and workspace gates; and makes
provider restart impossible for that generation.

The worker then posts `PROVIDER_DRAINED_STATIC_ENTERED`. Unless terminated, it
does not wait for acknowledgement before its first static operation. The
following orders are mandatory:

[source,text]
----
provider settlement/global-gate release < post PROVIDER_DRAINED_STATIC_ENTERED
post PROVIDER_DRAINED_STATIC_ENTERED < every parser/runtime/asset operation, if any
----

Matching receipt by the main bridge makes the generation hard-termination-
safe. Receipt can race ahead of the worker's first static operation.

Before matching receipt, cancellation or replacement follows only this order:

[source,text]
----
revoke < provider settlement < lock/global-gate release < ATTEMPT_DRAINED < terminate old < clear handle < create new < first new provider request
----

The main bridge posts lifecycle stop and must not terminate early. The pipeline
suppresses downstream work, provider adapters settle and release their exact
resources in `finally`, the pipeline clears admitted modules and unpublished
output, and then posts `ATTEMPT_DRAINED`. The bridge marks the generation
closing, terminates exactly once, releases listeners/transport references,
clears its sole handle, and only then creates the latest coalesced replacement.
Pending settlement may delay replacement without limit or timing outcome.

After matching receipt, cancellation or replacement uses the static path even
when a lifecycle-stop message is queued but unhandled:

[source,text]
----
provider settlement/global-gate release < post PROVIDER_DRAINED_STATIC_ENTERED < bridge receipt < hard terminate < clear handle < create replacement
----

The UI first revokes publication eligibility. The main bridge then terminates
the sole worker without parser acknowledgement, clears its handle, and only
then creates the latest replacement. Zero static operations before hard
termination is valid; otherwise termination may occur during runtime loading,
parsing, or traversal. No cooperative parser-stop, progress callback, immediate
computation-stop, or browser teardown-latency claim exists.

On an ordinary terminal path, the worker deletes the applicable cursor, tree,
and parser; clears source, endpoint, slice, projection, metric, admitted-module,
and other core references; posts only one source-free terminal outcome or one
complete canonical scene; then posts `ATTEMPT_DRAINED`. The bridge applies or
rejects the business payload through the publication gate and, after matching
drain receipt, terminates exactly once and clears its handle. Realm-held
language modules are released by that termination.

Hard static termination may prevent JavaScript `finally` and parser deletion.
Evidence must not claim delete-spy observation on that path. Realm termination
releases static resources without timing, secure-erasure, garbage-collection,
physical-browser, or operating-system-process teardown claims. Provider work
never relies on hard termination. Observable no-overlap means at most one
bridge-owned usable worker handle, parser set, provider slot, and raw/hash
workspace, not physical teardown.

== Presentation staging and continued-validity sequence

ADR 0008 fixes the following UI-main order after the complete-scene handoff:

. Validate every required own data field and bounded collection, complete
  unique `1..4,000` building set, exact canonical geometry/palette/order/bounds/
  view, prototype-safe identity handling, and current generation. A defect or
  validation throw creates no WebGL and propagates `M1-CITY-1` unchanged.
. Project source-freely into the one 28-byte-stride instance representation and
  check generation eligibility before renderer staging.
. Read positive integer host dimensions; create one detached matching canvas;
  immediately register one `{ passive: true, once: true }`
  `webglcontextlost` listener; request only ADR 0008's exact `webgl2` context;
  read and verify drawing-buffer equality; then compile the two fixed shaders,
  allocate/upload the one program/VAO/three buffers, restore fixed state, and
  issue the one instanced draw while detached.
. After synchronous operations, check throws, `getError`, context loss,
  drawing-buffer equality, and generation eligibility.
. Construct one `ResizeObserver` with an asynchronous generation-guarded
  callback and successfully `observe(host)` while detached. Failure is
  `M1-PRES-1`; disconnect and idempotently dispose. Publication cannot precede
  this step.
. Without yielding, reread host dimensions immediately before commit. If
  changed, set both backing dimensions exactly, reread and verify both drawing-
  buffer properties, recompute only aspect projection/viewport, restore state,
  clear, and issue exactly one detached draw. Recheck operations and current
  eligibility.
. In one synchronous no-yield UI-coordinator commit, publish canvas, current
  identity, and `Success`.

No timer, animation frame, microtask yield, retry, debounce, or network
operation enters the commit. Synchronous WebGL work need not be preemptible;
post-operation eligibility prevents stale publication.

The asynchronous observer cannot publish. For a changed positive integer host
size it reuses canvas, context, program, VAO, and buffers; sets backing size
exactly; reads and verifies host/backing/drawing-buffer equality; recomputes
only aspect-dependent matrix/viewport; reapplies all fixed state; clears; and
draws once. It does not rebuild/reupload buffers, reorder, animate, time,
debounce, or retry. Unchanged dimensions do not draw; platform batching means
only the latest reported size is promised.

The once/passive loss listener never calls `preventDefault`; no restoration
listener/path or loss extension exists. Candidate loss fails without
publication. Current published loss, or non-positive/non-integer size,
observer callback throw, drawing-buffer mismatch, WebGL error/loss, or failed
required resize draw after `Success`, synchronously makes the UI coordinator
commit `Presentation failed` / `M1-PRES-1`. It retains current tuple and draft,
removes city/canvas, disposes, and remains failed until resubmit or reload.
Stale callbacks dispose locally and cannot change visible state.

== Replacement, cancellation, failure, and cleanup

=== Replacement or cancellation

. The UI immediately revokes the old attempt's publication eligibility and
  clears identity, city, and presentation state as the accepted state contract
  requires. Cancellation preserves the editable draft; replacement installs
  the new submission before its validation result and coalesces to the latest.
. The main bridge selects the pre-receipt or post-receipt path solely from its
  matching `PROVIDER_DRAINED_STATIC_ENTERED` receipt gate. Its sole worker-
  generation handle and hard-stop gate are transport-resource ownership, not a
  second orchestrator.
. The selected path follows the exact phase order above. Pre-receipt provider
  operations settle cooperatively through `ATTEMPT_DRAINED`; post-receipt
  static work is hard-terminated without acknowledgement. Handle clearing
  always precedes replacement creation.
. Any tied or late identity, failure, scene, or lifecycle message is ignored.
  UI ineligibility remains authoritative even if underlying work completes.

=== Stage or presentation failure

. A worker-stage failure suppresses all downstream work and enters the ordinary
  terminal cleanup path above.
. The worker may return only the one terminal failure outcome, followed by
  `ATTEMPT_DRAINED`. The UI applies the outcome only for the current eligible
  attempt; no stale or partial city is published.
. If adaptation of an already-valid complete canonical scene fails, the
  presentation adapter reports `M1-PRES-1` and cleans every incomplete
  resource; the UI coordinator alone commits visible failure. A model defect
  remains `M1-CITY-1` before WebGL.
. If the current presentation fails after `Success`, the same ownership removes
  city/canvas, retains tuple and draft, and commits the persistent
  post-`Success` failure without retry or fallback.

After a successful complete-scene handoff, worker processing intermediates do
not become retained product state and are released before `ATTEMPT_DRAINED`.
Reload discards all application-managed session state and starts a fresh empty
session.

Presentation cleanup disconnects its observer, removes loss listener and
canvas, deletes each live shader/program/buffer/VAO exactly once, and clears
adapter-owned typed data and references. If context is already lost it claims
no driver release. Cleanup has no accepted latency or secure-erasure promise.
Cancellation and replacement revoke publication eligibility immediately but
promise no computation, network-stop, browser-teardown, or physical-process timing. A stalled old provider settlement may delay
replacement without creating an RA
or SP timing failure. This view does not redefine provider, browser, operating-
system, network, platform caching, or garbage-collection internals.
