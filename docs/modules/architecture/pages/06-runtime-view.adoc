= Runtime View

== Startup

The generated CLI parses all operator arguments before listening. `--host`
defaults to loopback. `--port` and all five capacities are required. A
non-loopback host requires a canonical host. The runtime validates the exact
version-1 package manifest, then verifies the length and SHA-256 digest of every
public record before listening. It preloads only those verified public bytes,
binds the native HTTP server, derives its canonical origin, and prints one
`READY` line. Startup does not read or hash private server or parser records;
the offline package audit verifies complete public/private manifest closure and
every recorded byte before publication.

== Analyze lifecycle

. The browser opens one persistent same-origin session response.
. Analyze consumes one strictly increasing generation. The server fully reads,
  decodes, and validates the command before changing lifecycle state.
. Replacement joins and releases prior work. Capacity is reserved atomically
  before worker creation.
. The worker selects an immutable revision, validates the complete source
  inventory, reports acquisition `0/N` immediately before the first candidate
  read and completion after each considered candidate, initializes the parser
  once, reports analysis `0/T` immediately before the first text-valid project
  call and completion only after each parser attempt's required cleanup,
  continues supported per-file failures, and reports city construction only
  when the existing construction seam is invoked.
. The parent validates correlation, bounded consecutive counts, fixed totals,
  stage order, and successful terminal reconciliation, then keeps the complete
  result provisional until the worker exits normally.
. The session writes mandatory lifecycle events through the existing path and
  may write source-free progress only for the eligible current attempt while
  no frame or response bytes are pending. The browser validates session,
  generation, revision, stage order, and monotonic phase-local counts before
  changing displayed state.
. For success, one browser-local presentation-session coordinator stages the
  native successful-file inventory and safe inspector, stages and commits the
  existing presenter, and publishes one current generation. Query and sort
  callbacks are gated by publication identity and exact snapshots; row and city
  activation share canonical geometry indices. Any current semantic or
  presenter failure removes the complete successful presentation as
  `M1-PRES-1`.

Successful and all-files-failed results retain their exact normalized source
association in process memory for every successfully analyzed file and every
file that reached a syntax or metric failure. Source text rejected as
unsupported is not retained. The current source-result association remains
until Discard, replacement, detected session loss, or graceful shutdown. Both
results expose Discard. The browser receives no source.

== Cancellation, replacement, loss, and shutdown

Cancel and Discard invalidate work, terminate and join an active worker, release
ownership, and then emit their control event. Replacement emits no synthetic
terminal event. Stale completion cannot restore discarded state.

Optional progress is omitted before serialization and write when a blocked
frame exists, `writableNeedDrain` is true, or `writableLength` is nonzero. It is
never queued, replaced by a latest-value slot, replayed, retried, timed, or
throttled. Later progress may resume after `drain` and an empty response queue.
When an attempted progress or mandatory frame makes `res.write` return false,
the runtime retains that exact first blocked frame and waits for `drain`; the
blocked write alone does not cause session loss. The session, any retained
source, and their admission capacity remain owned while it waits. A mandatory
event or mutating command while the frame is blocked initiates joined session
loss without another write.
Request abort, response close/error, owning-socket close, unrepresentable
browser input, or an advanced command/protocol failure also loses the
browser-owned temporary session. There is no reconnect or recovery.

SIGINT and SIGTERM stop admission, invalidate work, join workers, discard
retained state, close responses, and complete only with zero live sessions,
active attempts, and retained source bytes.

== Package and browser execution

The canonical artifact is `dist/`. `npm start -- <flags>` executes
`dist/server/standalone.mjs`. `npm run dev -- <flags>` builds an independent
artifact under `build/development/` and executes the same generated entry; it
has no HMR or WebSocket behavior and does not write `dist/`.

Installed-Chrome/CDP evidence drives the actual packaged browser, server,
worker, parser assets, and same-origin protocol with deterministic nonshipped
provider and parser barriers. It covers real `0/N` and `0/T` while the first
file is held, later nonzero acquisition and analysis counts, exact native
`value`/`max` and indeterminate resets, event-before-acknowledgement ordering,
terminal clearing, stale suppression, a healthy-reading 4,000-file attempt,
and the visible five-file successful inventory,
literal filter behavior, all three raw-metric sorts, row/city/inspector
canonical-index identity, unchanged camera matrices and instance-buffer upload
count across selection/filter/sort, mixed and all-failed publication, cleanup,
continuation, replacement, cancellation, discard, loss, capacity, page loss,
private-file `404`, and exact browser network closure without live GitHub. The
harness returns only booleans, counts, and numeric rendering proof; it does not
emit repository paths, queries, source, or inspection payloads.

== Deferred outcomes

Save/reopen, source view, authentication, private repositories, Internet
service, calibrated deployment values, and Raspberry Pi qualification are not
part of this runtime.
