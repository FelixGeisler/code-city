= Context and Scope

== Current system context

image::context.svg[Code City current context and accepted unimplemented target boundary]

A user supplies a public GitHub repository URL and optional exact path
exclusions to a static application served by GitHub Pages. The browser obtains
package assets from Pages and repository metadata and source from GitHub. No
Code City server participates in the current analysis.

[cols="1,2,2",options="header"]
|===
|Party |Sends to Code City |Receives from Code City

|User
|Repository URL, additional exclusions, explicit Analyze/Cancel and interaction
commands
|Status, selected commit, effective exclusions, city, path search, metric
inspection, and browser-session interaction

|GitHub Pages
|Static package bytes
|Package requests made by the browser

|Public GitHub
|Anonymous fixed-route requests for revision, commit, recursive tree, and raw
file content
|Provider responses; no credentials or repository writes
|===

=== Current trust boundaries

The shipped package is trusted only after build and package verification.
GitHub responses, repository paths, source bytes, worker messages, and browser
input cross validation boundaries. Provider projection in `src/edge/` removes
unneeded response shape but does not make data trusted. The application and
domain layers still validate immutable identities, complete raw ancestry,
canonical paths, kinds, content, and the source-free city payload before
publication.

Repository text reaches parsers as data. Canonical paths reach only inert UI
text and validated controller facts; source does not cross back from the worker
in the current result. The exact current failure and privacy rules are owned by
xref:requirements:city-and-failures.adoc[City and Failures].

== Accepted target context

The accepted target inserts a Code City server as the authority for acquisition,
analysis, retained source-result association, and saved investigations. The
browser becomes the presentation and investigation client, including exact
analyzed-source viewing. This is a responsibility boundary only: there is no
implemented server and no selected transport, API, storage, access mechanism,
or deployment topology.

The target trust boundaries for retained source, users, and server operations
cannot be drawn until those unresolved choices are approved.
