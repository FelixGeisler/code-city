= 3. Context and Scope

This view preserves the accepted logical system context and realizes only the
runtime, delivery, trust, transient-data, and cleanup placement accepted in
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002].
The internal strata, minimum blocks, conceptual ports, bridge boundary, and
ownership mapping are accepted in
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003].
The future framework-free TypeScript and Vite static-package contract is
accepted in
xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR 0004],
but its dependencies, source, configuration, package, and evidence do not exist
yet.
xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR
0005] accepts the bounded anonymous revision-resolution mechanism.
xref:adr/0006-bounded-selected-revision-retrieval-via-github-tree-and-raw-content.adoc[ADR
0006] accepts bounded immutable selected-revision retrieval and sole admission
through GitHub tree and raw content.
xref:adr/0007-static-syntax-with-pinned-tree-sitter-webassembly-grammars.adoc[ADR
0007] accepts the exact worker-side Tree-sitter runtime/grammars, static-syntax
projection, full-envelope no-SP disposition, and provider-drained/static-phase
lifecycle. These are documented decisions, not implemented traffic or parser
behavior. General message and port schemas and the full accepted-mechanism
runtime synthesis remain with their owning issues.

== Local terms

logical system boundary:: The boundary around all accepted Code City behavior.
It identifies what belongs to Code City independently of its internal source
or component structure.

logical trust crossing:: An inbound handoff from an external role to Code City
at which the received values remain untrusted. It is not an operating-system
process boundary, security sandbox, or source-dependency arrow.

production delivery target:: The public HTTPS GitHub Pages site
`https://felixgeisler.github.io/code-city/`, whose exact origin is
`https://felixgeisler.github.io`.

processing data:: Inert provider and repository data and derived intermediates
used only while producing the current attempt's outcome. It is neither a
persisted product/history record nor presentation output.

The browser contains no other Code City application runtime context. The
processing context is an execution and lifecycle boundary, not an
operating-system-process guarantee, security sandbox, logical trust crossing,
component count, package boundary, or source-dependency rule. The UI makes no
provider or repository request.

There is no Code City backend, relay, proxy, serverless function, server
runtime, database, queue, service credential, server-side product state,
product persistence, application-managed persistent cache, or second retrieval
path.

== Logical trust crossings

[cols="3,5,7",options="header"]
|===
|Crossing |Inbound values |Trust and authority

|User to UI main context
|The URL draft, submitted value, and lifecycle actions.
|All inbound values remain untrusted. Canonical grammar validation occurs in
the UI before worker dispatch or provider interaction. No user or service
credential crosses the boundary. See
xref:requirements:04-functional-requirements.adoc#anonymous-access[Anonymous
public access] and
xref:requirements:06-source-admission-and-limits.adoc#untrusted-source[M1-ADM-0].

|Public GitHub to processing worker
|Resolution evidence, selected commit and root-tree envelopes, projected entry
metadata and paths, raw entry bytes, and source.
|All inbound values remain untrusted and inert, and no credential crosses the
boundary. GitHub supplies only evidence admitted by ADRs 0005 and 0006: strict
own-field primitive projection prevents provider objects and prototype keys
from becoming application control state, and expected Git blob identity is
checked before source decoding. The hash is consistency evidence, not a
malicious-provider or collision-resistance warranty. Repository data is never
executed, evaluated, imported, or dynamically loaded.
|===

The only logical trust crossings are *User → UI main context* and *Public
GitHub → processing worker*. Same-origin UI-to-worker communication is not a
trust crossing. The Pages delivery node introduces no
product-data trust boundary, and no credential is requested, read, retained,
or transmitted.

== Data placement and lifecycle

[cols="3,7,6",options="header"]
|===
|Placement |Contents and lifecycle |Ownership and evidence

|GitHub Pages delivery node
|Static UI and worker artifacts only; no repository payload, source, derived
fact, city/scene data, attempt state, or credential.
|Initial static-package inspection belongs to
https://github.com/FelixGeisler/code-city/issues/452[#452]; renewed final-head
inspection belongs to https://github.com/FelixGeisler/code-city/issues/460[#460].

|UI main context: current-session state
|Input draft, stable state and status, selected repository/revision tuple where
permitted, and the complete city only in `Success`. Replacement,
cancellation, failure, success, and reload clear or retain these exactly as the
accepted state contract specifies. Reload starts empty and restores nothing.
|The UI owns current-attempt identity, state transitions, the sole
publication-eligibility gate, and current-session retention. Integrated
evidence belongs to https://github.com/FelixGeisler/code-city/issues/459[#459]
and https://github.com/FelixGeisler/code-city/issues/460[#460].

|Processing worker: transient current-attempt data
|Bounded resolution evidence; one capped retrieval REST transformation; no more
than `10,001` primitive projected inventory records; one globally exclusive
`4,194,317`-byte raw/hash workspace plus ADR 0006's bounded phase temporaries;
paths, raw and normalized source, admitted modules, counters, canonical metric
facts, one parser/tree/cursor set, and city-construction intermediates. Before
ADR 0007's static-entry post, every provider operation, lock, gate, workspace,
provider object, and provider transient is settled and gone. During static
processing only fixed same-origin runtime/grammar assets may be loaded; no
provider operation can restart. None becomes persisted or server-side product
state.
|The worker owns the sole admission path, one-request/one-workspace global
serialization, processing-stage suppression and core-reference release.
Provider adapters own ADR 0005/0006 settlement; the parser adapter owns
ordinary parser deletion; the main bridge owns the sole worker handle and hard
static termination. Focused stage evidence belongs to #453 through #457;
hosted renewal belongs to #460.

|UI presentation boundary
|One complete canonical scene may arrive without source or analysis objects.
Building identities remain inert model keys. The UI adapts only the complete
model and publishes the complete city and selected identity atomically when
the attempt remains eligible.
|UI presentation adaptation, failure, incomplete-resource cleanup, and rejection
of stale, replaced, cancelled, partial, or late output belong to #458 through
#460.
|===

Replacement or cancellation immediately revokes the old attempt's publication
eligibility in the UI and clears its identity, city, and presentation state.
Before the main bridge receives matching `PROVIDER_DRAINED_STATIC_ENTERED`, it
must not terminate the worker: provider work settles, gates and references are
released, the worker posts `ATTEMPT_DRAINED`, and only then may the bridge
terminate, clear its handle, and create the latest replacement. After matching
static-entry receipt, the bridge hard-terminates and clears the sole worker
before replacement without waiting for parser acknowledgement; zero static
operations before termination is valid. Ordinary terminal paths delete cursor,
tree, and parser, release core references, post the one business result and
`ATTEMPT_DRAINED`, then terminate. Late outcomes remain rejected.

This placement makes no cleanup-latency, secure-erasure, garbage-collection,
physical browser teardown, or operating-system-process teardown promise.
Provider work never relies on hard termination.
