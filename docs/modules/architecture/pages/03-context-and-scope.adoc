= 3. Context and Scope

This page completes references, authority, terminology, and ownership links for
the accepted logical context. The substantive runtime and deployment synthesis
is in xref:06-runtime-view.adoc[Runtime View] and
xref:07-deployment-view.adoc[Deployment View]; it is not duplicated here.

  trust/context baseline and terminology;
* https://github.com/FelixGeisler/code-city/issues/446[M0-07 — #446] owns the
  runtime/deployment topology recorded by
  xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002]

* https://github.com/FelixGeisler/code-city/issues/462[M0-08 — #462] owns the

  xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003];

The product contracts remain solely in requirements #441 through #444.
xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] remains authoritative for
source dependencies. ADR 0004 accepts the framework-free TypeScript/Vite
static-package contract; ADR 0005 accepts anonymous immutable-revision
resolution; ADR 0006 accepts bounded selected-revision retrieval and sole
admission; ADR 0007 accepts static syntax and phase-aware lifecycle; ADR 0008
accepts source-free WebGL2 presentation; and ADR 0009 accepts the M1 main-line,
sole-publisher, and app-over-docs cutover. All nine ADRs are `Accepted`. They
are documented decisions, not current M1 source, dependencies, product traffic,
parser behavior, rendering, package, executable workflow, branch
administration, or deployment behavior.

== Local terms

logical system boundary:: The boundary around all accepted Code City behavior.
It identifies what belongs to Code City independently of its internal source
or component structure.

logical trust crossing:: An inbound handoff from an external role to Code City
at which the received values remain untrusted. It is not an operating-system
process boundary, security sandbox, or source-dependency arrow.

production delivery target:: The public HTTPS GitHub Pages site
`https://felixgeisler.github.io/code-city/`, whose exact origin is
`https://felixgeisler.github.io`.

active M1 line:: The same M1 history named `v2` before ADR 0009's
administrative cutover and default `main` afterward.

archived v1 line:: The prior v1 history named `main` before the cutover and
locked `v1` afterward. It is comparison evidence, not an integration or
publication line.

processing data:: Inert provider and repository data and derived intermediates
used only while producing the current attempt's outcome. It is neither a
persisted product/history record nor presentation output.

execution/lifecycle context:: A browser execution placement and lifecycle
scope. The UI main context and processing worker context are not processes,
packages, components, security sandboxes, trust boundaries, or source-
dependency boundaries.

visible canonical internal artifact:: An artifact whose producer, consumer,
and placement are visible to the documentation reader. Admitted modules,
metric facts, canonical scenes, and building identities are not additional
user-visible product output.

Source-dependency arrows, runtime calls, runtime messages, deployment
placement, and logical trust crossings remain distinct.

|  User  | <-------------------------------> ||      Code City      || <-------------------------------> | Public GitHub |
+--------+                                    || logical system       ||                                   +---------------+
                                              || boundary             ||

The horizontal arrows denote logical interactions, not components, ports,
APIs, runtime calls, network routes, or source dependencies. Public GitHub
remains the sole external information system. GitHub Pages is the accepted
static delivery node, not another repository-information system or a
product-data trust crossing.

The browser contains no other Code City application runtime context. The
processing context is an execution and lifecycle boundary, not an
operating-system-process guarantee, security sandbox, logical trust crossing,
component count, package boundary, or source-dependency rule. The UI makes no
provider or repository request.

There is no Code City backend, relay, proxy, serverless function, server
runtime, database, queue, service credential, server-side product state,
product persistence, application-managed persistent cache, or second retrieval
path.

== Logical trust crossings

[cols="3,5,7",options="header"]
|===
|Crossing |Inbound values |Trust and authority

|User to UI main context
|The URL draft, submitted value, and lifecycle actions.
|All inbound values remain untrusted. Canonical grammar validation occurs in
the UI before worker dispatch or provider interaction. No user or service
credential crosses the boundary. See
xref:requirements:04-functional-requirements.adoc#anonymous-access[Anonymous
public access] and
xref:requirements:06-source-admission-and-limits.adoc#untrusted-source[M1-ADM-0].

|Public GitHub to processing worker
|Resolution evidence, selected commit and root-tree envelopes, projected entry
metadata and paths, raw entry bytes, and source.
|All inbound values remain untrusted and inert, and no credential crosses the
boundary. Public GitHub is authoritative only for validated canonical
repository spelling and designated default-tip evidence. GitHub supplies only
evidence admitted by ADRs 0005 and 0006: strict own-field primitive projection
prevents provider objects and prototype keys
from becoming application control state, and expected Git blob identity is
checked before source decoding. The hash is consistency evidence, not a
malicious-provider or collision-resistance warranty. Repository data is never
executed, evaluated, imported, or dynamically loaded.
|===

The only logical trust crossings are *User → UI main context* and *Public
GitHub → processing worker*. Same-origin UI-to-worker communication is not a
trust crossing. The Pages delivery node introduces no
product-data trust boundary, and no credential is requested, read, retained,
or transmitted.

Replacement, cancellation, ordinary completion, presentation cleanup, the
live static-entry-receipt race, and late-outcome handling follow the
xref:06-runtime-view.adoc#runtime-lifecycle-matrix[lifecycle matrix]. That
matrix is authoritative for the accepted order, including the
immediate switch from a pending pre-receipt stop to hard termination when the
main bridge receives the matching static-entry attestation. The context view
adds no duplicate sequence, cleanup timing, secure-erasure, driver-release,
garbage-collection, physical-browser, or operating-system-process promise.
Provider work never relies on hard termination.
