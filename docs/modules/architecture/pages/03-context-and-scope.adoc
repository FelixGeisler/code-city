= 3. Context and Scope

This view preserves the accepted logical system context and realizes only the
runtime, delivery, trust, transient-data, and cleanup placement accepted in
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002].
Provider mechanisms, internal blocks and ports, handoff schemas, and the full
accepted-mechanism runtime synthesis remain deferred to their owning issues.

== Local terms

logical system boundary:: The boundary around all accepted Code City behavior.
It identifies what belongs to Code City independently of its internal source
or component structure.

logical trust crossing:: An inbound handoff from an external role to Code City
at which the received values remain untrusted. It is not an operating-system
process boundary, security sandbox, or source-dependency arrow.

production delivery target:: The public HTTPS GitHub Pages site
`https://felixgeisler.github.io/code-city/`, whose exact origin is
`https://felixgeisler.github.io`.

processing data:: Inert provider and repository data and derived intermediates
used only while producing the current attempt's outcome. It is neither a
persisted product/history record nor presentation output.

----
+--------+       accepted user journey       +=======================+       two distinct exchanges       +---------------+
|  User  | <-------------------------------> ||      Code City      || <-------------------------------> | Public GitHub |
+--------+                                    || logical system       ||                                   +---------------+
                                              || boundary             ||
                                              +=======================+
                                                          :
                                                          : opened through trusted static artifacts from
                                                          v
                                    +----------------------------------------------------+
                                    | GitHub Pages:                                      |
                                    | https://felixgeisler.github.io/code-city/          |

The horizontal arrows denote logical interactions, not components, ports,
APIs, runtime calls, network routes, or source dependencies. Public GitHub
remains the sole external information system. GitHub Pages is the accepted
static delivery node, not another repository-information system or a
product-data trust crossing.

The browser contains no other Code City application runtime context. The
processing context is an execution and lifecycle boundary, not an
operating-system-process guarantee, security sandbox, logical trust crossing,
component count, package boundary, or source-dependency rule. The UI makes no
provider or repository request.

There is no Code City backend, relay, proxy, serverless function, server
runtime, database, queue, service credential, server-side product state,
product persistence, application-managed persistent cache, or second retrieval
path.

== Logical trust crossings

[cols="3,5,7",options="header"]
|===
|Crossing |Inbound values |Trust and authority

|User to UI main context
|The URL draft, submitted value, and lifecycle actions.
|All inbound values remain untrusted. Canonical grammar validation occurs in
the UI before worker dispatch or provider interaction. No user or service
credential crosses the boundary. See
xref:requirements:04-functional-requirements.adoc#anonymous-access[Anonymous
public access] and
xref:requirements:06-source-admission-and-limits.adoc#untrusted-source[M1-ADM-0].

|Public GitHub to processing worker
|Resolution evidence, repository metadata, paths, entry content, and source.
|All inbound values remain untrusted and inert, and no credential crosses the
boundary. GitHub is authoritative only for canonical repository spelling and
its designated default-branch tip, subject to #448's later accepted identity
validation. Repository data is never executed, evaluated, imported, or
dynamically loaded.
|===

The only logical trust crossings are *User → UI main context* and *Public
GitHub → processing worker*. Same-origin UI-to-worker communication is not a
trust crossing. The Pages delivery node introduces no
product-data trust boundary, and no credential is requested, read, retained,
or transmitted.

== Data placement and lifecycle

[cols="3,7,6",options="header"]
|===
|Placement |Contents and lifecycle |Ownership and evidence

|GitHub Pages delivery node
|Static UI and worker artifacts only; no repository payload, source, derived
fact, city/scene data, attempt state, or credential.
|Static-package inspection belongs to
https://github.com/FelixGeisler/code-city/issues/452[#452].

|UI main context: current-session state
|Input draft, stable state and status, selected repository/revision tuple where
permitted, and the complete city only in `Success`. Replacement,
cancellation, failure, success, and reload clear or retain these exactly as the
accepted state contract specifies. Reload starts empty and restores nothing.
|The UI owns current-attempt identity, state transitions, the sole
publication-eligibility gate, and current-session retention. Integrated
evidence belongs to https://github.com/FelixGeisler/code-city/issues/459[#459]
and https://github.com/FelixGeisler/code-city/issues/460[#460].

|Processing worker: transient current-attempt data
|Provider records, branch evidence, paths, raw and normalized source, admitted
modules, counters, canonical metric facts, parser/analyzer objects, and city
construction intermediates. They remain confined to the current attempt and do
not become persisted or server-side product state.
|The worker owns the sole admission path, processing-stage termination,
downstream suppression, feasible work cancellation, and release of transient
processing references. Stage evidence belongs to #453 through #457.

|UI presentation boundary
|One complete canonical scene may arrive without source or analysis objects.
Building identities remain inert model keys. The UI adapts only the complete
model and publishes the complete city and selected identity atomically when
the attempt remains eligible.
|UI presentation adaptation, failure, incomplete-resource cleanup, and rejection
of stale, replaced, cancelled, partial, or late output belong to #458 through
#460.
|===

Replacement or cancellation immediately revokes the old attempt's publication
eligibility in the UI and clears its identity, city, and presentation state.
The worker stops feasible work, suppresses downstream stages, and releases
transient references; a late outcome is ignored. Any stage failure stops
subsequent work. After successful complete-scene handoff, worker intermediates
are released rather than retained as product state.

This placement makes no cleanup-latency or secure-erasure promise and does not
redefine provider, browser, operating-system, network, or platform caching or
garbage-collection internals.

== Decision boundary

xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002]
is authoritative for the placement above and its feasibility stop rule.
xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] remains independently
authoritative for source dependencies.

The following remain deferred: shell/build and Pages mechanism in
https://github.com/FelixGeisler/code-city/issues/447[#447]; GitHub origins and
resolution/retrieval mechanisms in #448 and #449; analyzer and renderer
technology and deferred limits in #450 and #451; internal blocks, conceptual
ports, and ownership mapping in
https://github.com/FelixGeisler/code-city/issues/462[#462]; and the complete
accepted-mechanism/port runtime synthesis in
https://github.com/FelixGeisler/code-city/issues/463[#463]. This view selects no
endpoint, API, redirect/request policy, shell, parser, analyzer, renderer,
package, schema, port, worker lifecycle or cancellation primitive, Pages
workflow, route, threshold, or fallback.
