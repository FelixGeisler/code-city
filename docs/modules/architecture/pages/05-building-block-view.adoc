[[data-boundaries]]
== Data boundaries

The browser sends raw repository URL and exclusion text only to same-origin
command routes. It receives session identifiers, generations, revision IDs,
source-free cities with aligned geometry and inspection facts, sanitized
failed-file rows, and lifecycle events. The browser-local coordinator derives
only filtered/sorted canonical-index projections and current selection from
those facts. It never receives source, unit detail, parser trees, provider
payloads, or raw diagnostics.

The parent sends validated attempt commands into one worker, validates exact
correlation, stage order, consecutive worker-side counts, fixed totals, and
successful terminal reconciliation, and accepts a terminal result only after
normal joined exit. Progress records contain only attempt/session correlation,
revision, stage, and bounded counts; they contain no source, path, provider,
diagnostic, timing, or telemetry value.
Parser runtime and grammar bytes are private artifact records loaded from file
URLs by the worker. The HTTP perimeter exposes only `public/index.html`,
`public/browser.css`, and `public/browser.js`. The browser bundle imports no
legacy main controller or browser processing worker and introduces no storage,
route, DTO, protocol, runtime, or dependency.

== Ownership and cleanup

The session runtime atomically owns live-session, active-attempt, body-reader,
command-byte, and retained-source capacity. Replacement and control operations
make work ineligible before termination and join. Session loss and shutdown use
the same idempotent cleanup boundary. Successful current source/result state is
released by Discard, replacement, loss, or shutdown.

Tests alone substitute deterministic providers and join barriers through
nonshipped module hooks. Generated runtime bytes contain no fixture, provider,
or fault selector.
