= 5. Building Block View

This view documents only the minimum logical responsibilities and conceptual
collaborations accepted in
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003].
They fit the source strategy in xref:04-solution-strategy.adoc[Solution
Strategy] and the placement in
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002].
They are exclusive responsibility boundaries, not package or component counts,
and do not prescribe interfaces or schemas. The GitHub resolution adapter is
constrained by
xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR
0005], and the GitHub retrieval adapter and retrieval/admission collaboration
are constrained by
xref:adr/0006-bounded-selected-revision-retrieval-via-github-tree-and-raw-content.adoc[ADR
0006]. The decisions are documented but not yet implemented.

== Minimum logical blocks

[cols="3,4,8",options="header"]
|===
|Block |Stratum and placement |Exclusive responsibility

|UI attempt coordinator
|Application, UI main
|Uses the domain validation policy; owns the draft, current attempt,
observable state, identity retention, replacement and cancellation precedence,
sole publication gate, and session reset.

|Worker pipeline coordinator
|Application, worker
|Owns the resolution → admission → metrics → city sequence, stage termination,
downstream suppression, feasible cancellation coordination, and release of
core transients.

|Revision resolution
|Application plus domain identity policy, worker
|Produces the canonical repository and one immutable revision and owns
resolution classification. It performs no source retrieval.

|Retrieval/admission
|Application plus domain admission policy, worker
|Is the sole owner of `M1-ADM`/RA classification and admitted-module creation
and order. It produces one complete admitted set or a failure.

|Static metrics
|Application plus domain metric policy, worker
|Consumes only admitted modules and produces complete canonical metric facts
or `M1-MET-1`.

|City construction
|Pure domain, worker
|Transforms complete metric facts into one complete canonical scene or
`M1-CITY-1`. It has no acquisition, analyzer, parser, bridge, or renderer
dependency.

|UI surface adapter
|Edge, UI main
|Adapts user actions and displays state and status without owning business
state.

|Presentation adapter
|Edge, UI main
|Realizes the presentation port in
https://github.com/FelixGeisler/code-city/issues/458[#458] using the technology
selected by https://github.com/FelixGeisler/code-city/issues/451[#451]: adapts
a complete scene to the renderer, treats identities as inert, detects
`M1-PRES-1`, and cleans presentation resources.

|UI-worker bridge
|Edge, both contexts
|Correlates and transports lifecycle commands and source-free outcomes. It
performs no validation, orchestration, classification, or admission.

|GitHub resolution adapter
|Edge, worker
|Realizes the resolution-evidence port in
https://github.com/FelixGeisler/code-city/issues/453[#453] using ADR 0005's
exact bounded native-Fetch metadata and omitted-`sha` commit-list calls. It
validates and projects only primitive evidence, owns its response-stream
resources, and retrieves no source.

|GitHub retrieval adapter
|Edge, worker
|Realizes ADR 0006's exact selected-commit and recursive-root-tree REST GETs,
own-field bounded primitive projection, canonical immutable-commit raw GETs,
stream caps, raw/hash workspace, Web Crypto Git-blob comparison, and physical
request/reader/response/hash cleanup for
https://github.com/FelixGeisler/code-city/issues/454[#454]. It supplies records
and bytes only and performs no independent admission, classification, retry,
or fallback.

|Parser adapter
|Edge, worker
|Translates parser-specific grammar and syntax into core-owned semantic
observations. It owns no metric policy and performs no execution, import, or
provider access.
|===

Resolution and retrieval are distinct. Retrieval/admission alone validates the
selected-revision evidence, applies every admission horizon, and creates or
readmits one complete ordered module set. The retrieval adapter cannot bypass
that owner. Analysis consumes admitted modules rather than retrieval
implementation. Parser-specific objects remain edge-side. City construction is
pure domain, and presentation receives only a complete, source-free canonical
scene.

Driving and driven labels describe conceptual roles, not executable
interfaces, package boundaries, or component counts. Contracts stay with their
application or domain semantic owners; no contracts layer exists.

== UI-worker bridge boundary

The bridge may transport only:

* toward the worker, one normalized, syntactically accepted submission and
  lifecycle control; and
* toward the UI, selected identity, one terminal failure, or one complete
  canonical scene.

Raw or normalized repository source or content, admitted modules, parser
objects, metric intermediates, and partial scenes never cross the bridge.
Building identities may cross only as inert model keys. Runtime messages may
move in both directions but grant no source dependency and create no trust
crossing. Exact message and port schemas remain with #453 through #460.

== Exclusive outcome and lifecycle ownership

[cols="4,5,7",options="header"]
|===
|Concern |Sole owner |Boundary

|Visible state and publication
|UI attempt coordinator
|The UI surface displays state but does not own it. The coordinator is the sole
publication-eligibility gate.

|Input-failure classification
|Domain validation policy
|The policy returns the classification before worker dispatch. No edge block
classifies or reclassifies it.

|Visible input-failure transition
|UI attempt coordinator
|The coordinator alone commits `Failure` before worker dispatch.

|Resolution outcome
|Revision-resolution capability
|The resolution adapter supplies only ADR 0005's validated primitive evidence;
it neither constructs the tuple nor reclassifies an outcome.

|Admission and RA outcome
|Retrieval/admission capability
|No other block creates or readmits admitted modules. It returns one complete
ordered set or one accepted terminal result. The retrieval adapter supplies
only ADR 0006's bounded selected-revision records, expected identities, and
bytes.

|Metric failure
|Static-metrics capability
|The parser adapter supplies semantic syntax observations only.

|Construction failure
|City constructor
|It consumes complete canonical metric facts and has no edge dependency.

|Presentation-failure detection and resource cleanup
|Presentation adapter
|The adapter reports the outcome and cleans only its presentation resources.

|Visible presentation-failure transition
|UI attempt coordinator
|Only the coordinator commits visible `Failure`.

|Worker sequencing and suppression
|Worker pipeline coordinator
|A stage capability returns its terminal outcome; the pipeline suppresses
later stages and releases core transients.

|Bridge transport
|UI-worker bridge
|It transports outcomes unchanged and never validates, classifies, admits, or
reclassifies them.
|===

An outcome from the worker is applied only while its attempt remains
publication-eligible.

Cancellation and cleanup are partitioned exactly once:

. The UI attempt coordinator immediately revokes publication eligibility,
  wins ties, and clears identity, city, and presentation state while preserving
  the draft required by #441.
. The worker pipeline coordinator coordinates feasible stopping, suppresses
  downstream stages, and releases core transient references.
. Each provider or parser adapter releases only the physical resources it
  owns.
. The UI-worker bridge releases transport references.
. The presentation adapter disposes incomplete or replaced presentation
  resources.

For resolution, ADR 0005 refines the adapter part of step 3: each status-`200`
response has the inclusive 4 MiB stream bound, reader-lock release in
`finally`, and ordered removal of application-owned chunk, text, parsed-object,
response, and reader reachability before request two or return. Cancellation
or replacement aborts the attempt signal, requests feasible body cancellation,
settles cleanup, and suppresses later work. Only a validated primitive
projection may remain reachable.

For retrieval, ADR 0006 further refines step 3. Across all attempts the adapter
holds at most one retrieval/admission provider request and one exact
`4,194,317`-byte raw/hash workspace. It removes each capped REST transformation
before the next request, the provider tree before raw retrieval, and each
raw/hash/decoded temporary before another request. It releases reader locks in
`finally`, handles abort/cancel/read/digest settlement, checks eligibility after
non-abortable phases, and cleans projected inventory and unpublished output.
Replacement work is latest-only and cannot start until old operations,
non-abortable work, locks, and application-owned cleanup settle.

Late output is harmless because the UI publication gate remains authoritative.
Reload discards all application-managed session state. No cleanup latency,
secure erasure, platform-cache behavior, or garbage-collection behavior is
promised.
