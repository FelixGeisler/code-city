== Current data boundaries

`START` carries a validated repository reference with an optional explicit
branch, a generation, and the atomically captured, sorted additional exclusions
into the worker. GitHub edge adapters project bounded provider evidence. After
branch or default-head selection, commit and raw-source requests use the
selected immutable commit ID. Commit evidence supplies a validated same-width
root tree ID for the recursive-tree request. Application and domain preparation
must validate the complete inventory before it is trusted or used for filtering
and reads.

Normalized source exists only inside the worker pipeline. Files are fetched and
normalized sequentially; syntax and metric processing starts after the complete
admitted set exists and then releases each source as it is processed. City
construction produces canonical-order geometry and inspection facts. The
worker transfers only geometry buffers and the aligned `{canonicalPath, S, U,
M}` inspection facts. It transfers no source body, parser tree, provider object,
or diagnostic.

The controller independently validates exact protocol shape, geometry,
inspection alignment, deterministic presentation projection, and safe values.
Only that validated, source-free city can reach semantic publication and the
presenter.

== Inactive shared application core

`source-retrieval` now also exposes a raw-source acquisition path that owns
inventory completion, pre-read candidate validation, text normalization,
normalized limits, failed text rows, and retained bytes. `project-analysis`
owns one shared parser initialization, per-file syntax and metric continuation,
projection release, successful-fact city construction, and canonical union and
source invariants. The GitHub edge supplies verified raw bytes through an
additive capability; its existing decoded-source facade remains compatible.

These blocks are not reachable from the current worker, protocol, controller,
or browser entry. A later Node worker integration owns their transfer and
boundary validation. No service, endpoint, session, Save/reopen, source-view,
private-source, deployment, or device block exists yet.

== Accepted target boundary

The target replaces the worker's authoritative acquisition and analysis role
with server authority. The server also owns retained analyzed source and saved
investigations; the browser owns presentation and investigation. This boundary
requires server capability but does not define components, services, endpoints,
stores, processes, or topology. Those details remain unresolved.
