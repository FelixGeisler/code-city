= Risks and Technical Debt

== Current implementation risks

[cols="2,3,2",options="header"]
|===
|Risk or debt |Current consequence |Existing containment

|Browser and anonymous-provider coupling
|Availability, CORS, rate limits, and browser resource capacity can prevent an
analysis.
|Bounded requests, explicit failures, fixed processing envelope, no automatic
retry, and complete-attempt rollback.

|Whole-attempt file failure
|One supported file's retrieval, text, syntax, or metric failure prevents all
otherwise valid files from producing a city.
|The failure is explicit and source-free; no partial result is presented. The
accepted target replaces this with per-file continuation after complete
acquisition.

|Source-free result
|Current inspection cannot show exact source or unit/contribution evidence.
|The browser exposes only aligned paths and raw file metrics. Target retained
source and drill-down remain unimplemented.

|Shallow city grouping
|Current city construction groups by at most the first two directory segments,
not the accepted recursive repository hierarchy.
|The behavior is deterministic and documented as current only. Recursive
presentation details remain unresolved.

|Current camera coupling
|Path-search activation selects and moves the camera, contrary to the target's
selection-without-camera-movement behavior.
|Other selection paths remain explicit and generation-gated. Target interaction
is not claimed as implemented.

|No persistence
|Reload, navigation, replacement, or close loses the browser-session analysis.
|The UI makes no save claim. Explicit immutable Save/reopen is accepted but
unimplemented.
|===

== Target delivery gap

The largest architectural gap is the move from browser-owned acquisition and
analysis to server authority with retained source-result association and saved
investigations. That gap includes per-file continuation, recursive hierarchy,
unit facts and source drill-down, a sortable complete file inventory, explicit
Save/reopen, and target camera behavior.

These are accepted product outcomes, not evidence that a backend exists. Server,
API, storage, access/security, retention operations, deletion, backup, ingress,
deployment, recursive layout, and portable interchange remain unresolved. They
must be decided before implementation that depends on them; this reset does not
turn them into a plan.
