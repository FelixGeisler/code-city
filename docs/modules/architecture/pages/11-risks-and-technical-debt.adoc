= Risks and Technical Debt

== Current implementation risks

[cols="2,3,2",options="header"]
|===
|Risk or debt |Current consequence |Existing containment

|Service dependency on anonymous public GitHub
|Provider availability, rate limits, or incomplete evidence can prevent
complete acquisition.
|The Node service uses fixed anonymous routes, bounded requests, exact evidence
validation, explicit failures, the fixed processing envelope, and no automatic
retry.

|Whole-analysis acquisition and shared-parser failures
|Revision, complete-tree, blob-integrity or retrieval, processing-envelope, or
shared-parser-initialization failure prevents a city.
|These boundaries fail closed before publication. After complete acquisition,
supported source-text, syntax, and metric failures continue per file with the
three sanitized categories defined by the requirements.

|Source-free browser result
|The server retains the exact analyzed source-result association in process
memory, but current browser inspection cannot show source or unit/contribution
evidence.
|The browser receives only aligned paths, raw file metrics, and sanitized
failed-file rows. Browser source view and drill-down remain future whole-core
outcomes.

|Shallow city grouping
|Current city construction groups by at most the first two directory segments,
not the accepted recursive repository hierarchy.
|The behavior is deterministic and documented as current only. Recursive
presentation details remain unresolved.

|Current camera coupling
|Path-search activation selects and moves the camera, contrary to the target's
selection-without-camera-movement behavior.
|Other selection paths remain explicit and generation-gated. Target interaction
is not claimed as implemented.

|No persistence
|Reload, navigation, replacement, or close loses the browser-session analysis.
|The UI makes no save claim. Explicit immutable Save/reopen is accepted but
unimplemented.
|===

== Later whole-core delivery gaps

Standalone M5 has completed the move to server-owned acquisition and analysis,
temporary retained source-result association, and per-file continuation. The
remaining accepted whole-core outcomes are recursive hierarchy, source and
unit/contribution drill-down, a sortable complete file inventory, explicit
Save/reopen, and target camera behavior.

API, storage, access/security, retention operations, deletion, backup, ingress,
deployment, recursive layout, and portable interchange remain unresolved.
These are future outcomes or design gaps, not claims about current standalone
behavior, and must be decided before implementation depends on them.
