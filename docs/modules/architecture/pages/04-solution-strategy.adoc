= Solution Strategy

== Current strategy

The current implementation uses one explicit, generation-scoped pipeline:

. The main controller atomically captures and validates repository input and
  additional exclusions.
. One worker resolves the explicit branch head, or the default-branch head when
  no branch was supplied, to an immutable commit.
. The worker obtains commit evidence for that selected commit, validates its root
  tree ID, and requests recursive-tree evidence by that root tree ID. Edge
  projection checks provider response shape and completeness. Domain admission
  then validates all raw and canonical identities, kinds, uniqueness, and
  complete raw ancestry before exclusions, suffix filtering, or blob reads.
. Eligible contents are fetched, integrity-checked, decoded, normalized, and
  admitted sequentially. Only after complete source retrieval does static
  syntax and metric processing proceed sequentially.
. Domain code constructs deterministic city geometry and aligned inspection
  facts. The worker transfers one source-free result.
. The controller validates the complete result, stages WebGL presentation and
  semantic content, and commits them as one current city.

A failure in any current file's retrieval, admission, syntax, or metric work
fails the whole attempt. The current implementation does not apply the target's
per-file continuation policy.

The dependency direction keeps domain rules independent of browser and provider
APIs; application services coordinate capabilities; edge adapters own GitHub,
worker, DOM, parser, and WebGL integration. Detailed
admission, metric, city, camera, and failure algorithms remain with
xref:requirements:source-and-metrics.adoc[Source and Metrics],
xref:requirements:city-and-failures.adoc[City and Failures], and their executable
owners in `src/domain/`, `src/application/`, and `src/edge/`.

== Inactive continuation core

An additive application core is prepared for later Node worker integration. Its
raw GitHub capability verifies the bounded Git blob before text handling. The
acquisition service then continues unsupported text files while retaining exact
normalized bytes for text-valid files. One initialized parser capability
continues syntax and metric failures per file, releases each successful
projection once, and constructs a city from successful facts only. It returns
canonical failed-file and retained-source rows with the city or `null` when no
fact succeeds.

This core is not wired to the browser worker, protocol, controller, or entry
point. The active browser behavior above remains fail-fast and source-free. The
separate inactive native-HTTP perimeter does not invoke this core. No session
runtime, dedicated Node worker integration, package cutover, Save or source
view, private-source support, deployment, or device qualification is
implemented by this preparation.

== Accepted target strategy

The target keeps the deterministic product rules but moves source acquisition
and analysis authority to a server. The server retains the exact analyzed source
with its results and optional immutable saved investigations. The browser owns
city presentation, file and unit investigation, and on-demand source viewing.

Per-file continuation, recursive hierarchy, complete sortable inventory,
source/unit drill-down, explicit Save/reopen, and no-camera-movement selection
are target outcomes. Their approved behavior is in the requirements. Their
server, transport, storage, access, deployment, and recursive-presentation
mechanisms remain unresolved and are not proposed here.
