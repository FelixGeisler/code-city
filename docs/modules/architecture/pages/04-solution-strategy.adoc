= 4. Solution Strategy

[cols="1,3",options="header"]
|===
|Strategy |Approach

|Stable input
|Resolve the repository's default branch once and process its immutable commit

|Independent core
|Keep validation, admission, metrics, city construction, and state policy free
of browser and provider APIs

|Bounded processing
|Run retrieval and static analysis as one ordered worker pipeline with explicit
limits

|Direct provider access
|Use anonymous GitHub REST and raw-content requests; no backend or credential

|Fixed syntax
|Use pinned Tree-sitter WebAssembly grammars and fail on incomplete syntax

|Fixed presentation
|Build a renderer-neutral city, then present it with browser-native WebGL2

|Atomic publication
|Only the current attempt may replace the visible state; failures publish no
partial city
|===

The architecture prefers explicit, single-purpose parts over extension points,
fallbacks, plugins, or configurable pipelines.
