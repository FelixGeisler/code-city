= Deployment View

== Current deployed topology

image::deployment.svg[Current static GitHub Pages deployment with browser main context and one worker]

GitHub Pages serves one verified static package under the Code City base path.
A user's browser runs the package in two execution contexts: the main context
for controller, semantic UI, and WebGL2 presentation, and one module worker for
GitHub acquisition, parsing, metrics, and city construction. Both are browser
code from the same package. Public GitHub remains an external provider.

There is no Node.js application process in production. Node.js, npm, Vite, and
Antora remain build and verification tools. The inactive continuation core,
worker, native-HTTP perimeter, and session runtime are neither connected to the
active browser pipeline nor selected by `npm start`. They are packaged only in
`build/standalone/`; that directory is not the Pages artifact and is not
uploaded or deployed. A Pages artifact remains static content, not a Code City
server runtime.

== Current publication path

The pull-request `CI` workflow installs the locked dependency closure, performs
the security audit, type-checks the isolated Node graph, and runs the unchanged
`npm run verify`. It then runs seven additive standalone gates: build, direct
manifest audit, isolated reproducibility, packaged startup, package audit,
signal shutdown, and installed-Chrome packaged-browser evidence. It does not
publish.

On a push to `main`, the `Publish` workflow repeats those gates, creates the
legacy canonical package and publication record, uploads the reviewed `dist`
Pages artifact, and deploys that artifact. The inactive standalone artifact is
verified but not uploaded. The legacy package manifest and publication tooling
continue to own Pages artifact identity and publication evidence; tool versions
remain in the package and lock files.

The workflow's production-evidence job is conditional on its explicit issue-
state eligibility check. When eligible, the collector verifies deployment and
production assets before recording observations. Therefore the workflow defines
a verified evidence path; it does not imply that production evidence is
collected for every merge.

== Accepted target

The target requires server capability for acquisition, analysis, retained
source-result association, and saved investigations. No server node appears in
the current deployment diagram because none is deployed. Platform, process,
storage, access, ingress, network, resource, and deployment choices remain
unresolved.
