= 7. Deployment View

This view records the production nodes, origin, artifact placement, and
runtime-data placement accepted in
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002].
xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR 0004]
accepts the future framework-free TypeScript and Vite static-package contract:
the exact `/code-city/` base and one separately emitted, non-inline,
same-origin ES-module worker. That documented decision is accepted now, but no
shell, dependency, configuration, production artifact, or deployment workflow
exists yet.
xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR
0005] accepts the exact `api.github.com` revision-resolution deployment
exchange.
xref:adr/0006-bounded-selected-revision-retrieval-via-github-tree-and-raw-content.adoc[ADR
0006] accepts worker-originated selected-commit/root-tree exchanges at
`api.github.com` and immutable-commit content at `raw.githubusercontent.com`.
Neither decision creates current product traffic or adds a deployment node or
path. Outside those decisions, this view does not select a Pages source,
action/workflow, application route, deployment mechanism, parser, renderer,
port, schema, or broader worker lifecycle primitive.

The production delivery URL is exactly
`https://felixgeisler.github.io/code-city/`, and requests originating from the
application have the exact production origin `https://felixgeisler.github.io`.
ADR 0004 fixes `/code-city/` as the future package's public base. Adopting this
existing target and base does not adopt its current Pages source,
action/workflow, application route, or deployment mechanism.

== Nodes and origins

[cols="3,5,7",options="header"]
|===
|Node or context |Accepted placement |Boundary

|GitHub Pages delivery node
|The existing public HTTPS target at
`https://felixgeisler.github.io/code-city/`, exact origin
`https://felixgeisler.github.io`.
|Serves trusted static UI and worker artifacts only. It receives no repository
payload, admitted source, metric facts, city or scene data, attempt state, or
credential. It is not a product-data trust boundary.

|Browser UI/presentation main context
|One main context on the user device, loaded from the accepted Pages target.
|Owns input and current-session product state, state and attempt eligibility,
presentation adaptation and cleanup, and the sole atomic publication gate. It
makes no provider or repository request.

|Browser processing worker context
|At most one dedicated context, same-origin with the UI.
|Owns direct anonymous provider interaction and all retrieval, admission,
analysis, and renderer-neutral city processing. Its current-attempt repository
and derived data is transient. It is not an operating-system-process guarantee,
security sandbox, trust crossing, component count, package boundary, or
source-dependency rule.

|Public GitHub
|External to the user device and the sole external information system.
|Resolution and selected-revision retrieval are direct and anonymous from the
processing worker. ADR 0005 fixes resolution at `api.github.com`. ADR 0006 fixes
selected-commit and recursive-root-tree REST at `api.github.com` and sequential
immutable-commit raw content at `raw.githubusercontent.com`, with redirect
refusal, exact URL checks, bounded responses, no credential, and no alternate
origin or path.
|===

No additional Code City application runtime context or deployment node exists.
In particular, M1 has no Code City backend, relay, proxy, serverless function,
server runtime, database, queue, service credential, server-side product state,
product persistence, application-managed persistent cache, or second retrieval
path.

== Artifact and data placement

[cols="3,7,6",options="header"]
|===
|Placement |Present |Prohibited or absent

|GitHub Pages
|Trusted static UI and worker artifacts.
|Repository payload, admitted source, metrics, city/scene data, attempt state,
credential, server runtime, and server-side product state.

|UI main context
|Input draft; current state and status; selected identity where permitted; one
complete city only in `Success`; renderer adaptation resources. State is
current-session only and reload starts empty.
|Provider records, repository requests, raw or normalized source, admitted
modules, parser/analyzer objects, and canonical metric intermediates.

|Processing worker
|Transient current-attempt provider records, paths, raw and normalized source,
admitted modules, counters, metrics, parser/analyzer objects, and
renderer-neutral city-construction intermediates.
|Persisted product/history state, credential, presentation resources, and any
execution, evaluation, import, or dynamic loading of repository data.

|Worker-to-UI handoff
|The selected canonical repository/revision tuple while `Loading`, one terminal
failure outcome, or one complete canonical scene. Canonical building identities
may cross only as inert model keys.
|Raw or normalized source, repository entry content, admitted modules,
parser/analyzer objects, canonical metric intermediates, or a partial scene.
|===

The UI is the sole publication-eligibility gate. It atomically publishes the
complete city and selected identity only for the current eligible attempt and
rejects every stale, replaced, cancelled, partial, or late worker result.
Same-origin UI/worker communication is not a trust crossing. The only logical
trust crossings remain *User → UI main context* and *Public GitHub → processing
worker*, and no user or service credential crosses either boundary.

== Cleanup placement

* Replacement or cancellation immediately revokes the old attempt's
  publication eligibility in the UI and clears identity, city, and
  presentation state according to the accepted state contract.
* The worker applies ADR 0005's resolution cleanup and ADR 0006's retrieval
  abort, feasible body cancellation, handled settlement, reader-lock release,
  post-operation eligibility checks, and complete application-owned cleanup.
  Across all attempts, at most one retrieval/admission request and one raw/hash
  workspace exist; only the latest replacement can start after old work and
  cleanup settle. Any late outcome is ignored by the UI.
* A worker-stage failure stops downstream work and releases transient
  processing references. A presentation failure is owned by the UI, which
  cleans up incomplete presentation resources.
* After a successful complete-scene handoff, worker intermediates do not become
  retained product state and are released. Reload discards all
  application-managed session state.

This placement promises no cleanup latency or secure erasure and does not
redefine provider, browser, operating-system, network, or platform caching or
garbage-collection internals.

== Feasibility gate and deferred deployment detail

ADR 0005 records https://github.com/FelixGeisler/code-city/issues/448[#448]'s
dated documentary/read-only feasibility for direct
anonymous revision resolution from exact origin
`https://felixgeisler.github.io` to `https://api.github.com`. It covers the two
selected paths, redirect refusal, preflights, CORS and response visibility,
anonymous request and rate policy, immutable identity evidence, bounded body
handling, cancellation, and application-controlled release. The observations
are point-in-time evidence only. #453 revalidates the pin and endpoint contract
before implementation, and #460 renews hosted-origin evidence on the final
head.

ADR 0006 records #449's dated exact-origin REST/raw, immutable-byte, Web Crypto,
and rejected-codeload feasibility. The observations are point-in-time evidence
only. #454 revalidates the mechanism before implementation, and #460 renews
hosted final-head REST/raw evidence. A deprecation or `410`, loss of REST/raw
CORS, immutable-SHA exact-byte/hash agreement, pinned API/tree/schema
compatibility, required worker Web Crypto, or bounded-resource feasibility
stops implementation and reopens #449. Reopen
https://github.com/FelixGeisler/code-city/issues/446[#446] when direct-browser
topology feasibility is affected. No origin, endpoint, header, order, cap,
proxy, relay, backend, credential, persistent cache, retry, wait, second path,
or fallback may change silently.

ADR 0004 now owns the accepted shell/build and package constraints.
https://github.com/FelixGeisler/code-city/issues/452[#452] later implements the
initial exact dependencies, walking shell, package, and evidence;
https://github.com/FelixGeisler/code-city/issues/459[#459] integrates the
successful path; and https://github.com/FelixGeisler/code-city/issues/460[#460]
renews canonical production evidence against the final head. Pages
source/action/workflow, application route, and deployment mechanism remain
unselected. ADR 0005 owns the accepted resolution origin and mechanism; ADR
0006 owns selected-revision retrieval/admission at the two named origins; #450
and #451 own analyzer and renderer technology and their deferred limits; #462
owns blocks and conceptual ports; and #463 owns the full accepted-mechanism and
port synthesis. Outside the ADR 0005 and ADR 0006 summaries, this view selects
no parser, renderer, concrete package or source map, port, schema, broader
worker primitive, workflow, route, threshold, or fallback.

xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] remains unchanged and
authoritative for the outer source boundary;
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003]
remains authoritative for the internal graph; ADR 0004 adds only its build/edge
mechanism constraints; ADR 0005 governs resolution; and ADR 0006 governs
selected-revision retrieval/admission. Runtime placement grants no new source
dependency and ADR 0006 adds no node or product-data path.
