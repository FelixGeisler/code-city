= 7. Deployment View

This view is the authoritative implementation-independent deployment
synthesis accepted through
https://github.com/FelixGeisler/code-city/issues/463[#463] and extended by
https://github.com/FelixGeisler/code-city/issues/446[#446]. It links ADR 0002's
production target, browser-only contexts, direct-provider topology, and trust
crossings to ADR 0004's conceptual `/code-city/` static package, ADRs 0005 and
0006's exact GitHub origins, ADR 0007's five same-origin parser assets, ADR
0008's browser-native presentation, and ADR 0009's branch, publisher, and
cutover placement.

ADR 0009's separate branch administration is complete. The remaining accepted
decisions create no current M1 shell, source, dependency, configuration, asset,
package, product traffic, renderer, route, executable Pages workflow, or
application deployment. This view selects no source map, executable schema,
emitted filename, worker-creation timing, transport/cancellation primitive,
preload policy, or test technology.

== Branch and publication migration

=== Historical pre-migration state and completed transition

ADR 0009 records that, before migration, v1 occupied default `main`, M1 occupied
`v2`, no `v1` branch existed, and the target served Antora output from the
legacy `main`-only Documentation workflow. The observed `github-pages`
environment then had one custom `main` policy but reported
`can_admins_bypass: true`. Those remain dated historical observations, not
current authority.

The separately gated administration subsequently preserved commit identities
while renaming old v1 `main` to `v1` and M1 `v2` to `main`. At the sealed
administration baseline, protected/default M1 `main` is
`b0b1a0a4e873b9415d266b67c7adeda913faf655`, locked archival `v1` is
`3ed8407809ea660657d6eeb49579ddb8412932fa`, and no `v2` branch remains. New
work and current repository documentation use `main`; `v1` and `v1.0.0` remain
archival comparison evidence only.

Only `main` may publish `github-pages`. Documentation, Container, and Release
were disabled and read back before the rename. After the default switch their
final API registration state is `deleted` because those workflow files are
absent from new `main`; current CI remains active. The environment now reads
`can_admins_bypass: false` and exactly one custom deployment branch policy
named `main`, resolving only to the M1 line. The existing legacy documentation
remains frozen and cannot be refreshed or used as a fallback. #460 replaces it
with the application; no documentation route, redirect, composite artifact,
second publisher, origin, environment, or preview path is accepted.

== Security invariants

* The only logical trust crossings are exactly:
** `User → UI main context`;
** `Public GitHub → processing worker`.
* Same-origin bridge traffic and GitHub Pages artifact delivery are not logical
  product-data trust crossings.
* Only the resulting M1 `main` may publish production through the single first-
  party Pages path. The archived branch, tags, forks, delivery branches, and
  retired workflows are independently denied by the environment policy, whose
  required read-back is `can_admins_bypass: false` with exactly one custom
  `main` deployment branch policy resolving only to the new M1 line.
* The Pages deploy job has only the required repository-read, Pages-write, and
  OIDC permissions. It introduces no long-lived deployment secret, repository
  or provider credential, external host, preview publisher, or fallback.
* No user or service credential is requested, accepted, read, retained, or
  transmitted.
* Repository metadata, paths, bytes, and source remain untrusted and inert.
  They are never executed, evaluated, imported, or dynamically loaded.
  Repository data cannot construct, alter, or select an asset URL or introduce
  a capability.
* The canonical path's final suffix selects one grammar family only through
  ADR 0007's closed mapping to already-packaged JavaScript, TypeScript, or TSX
  grammars. It never selects an asset URL, plugin, or new capability.
* The UI performs no GitHub/provider request. Pages receives no product data.
* Cross-boundary content remains limited to validated primitive resolution
  evidence; bounded selected-revision records/bytes, with retrieval/admission
  alone creating the complete admitted set; fresh primitive static-syntax
  observations; selected identity, one fixed terminal failure, or one complete
  source-free canonical scene through the bridge; and the two discriminator-
  plus-correlation lifecycle attestations.
* Raw/normalized source, provider objects, admitted modules, parser objects,
  metric intermediates, and partial scenes never reach presentation.
* Building identities remain inert model keys and never become normal-object
  keys, DOM/WebGL names or text, shader content, resource locators, or logs.
* The worker remains only an execution/lifecycle context, not a security
  boundary, sandbox, operating-system process, package, component, or trust
  crossing.

== Stop rules

Stop rather than assume, configure, implement, or deploy if:

* an accepted requirement or ADR contradicts this placement, or a stage,
  failure, cleanup action, retained datum, or one of the 13 exact ports loses
  its accepted owner;
* current repository read-back no longer shows protected/default `main`, locked
  archival `v1`, absent `v2`, strict app-bound checks, active CI, the final
  legacy workflow state summarized above, and a non-bypassable `github-pages`
  environment with exactly one custom `main` policy;
* archived v1 resumes development, release, or publication, or another branch,
  tag, fork, workflow, environment, publisher, origin, route, service,
  credential, preview, or fallback can publish production;
* a proposed response would change commit identity, force or delete a ref,
  synthesize a reconciliation commit, prune/reset protected evidence, weaken a
  gate, or bypass a required check;
* #452's merge could deploy incomplete M1, or #460 could not prove guarded
  reviewed-tree equivalence, merge-commit push verification, explicit exact-
  commit dispatch, complete manifest, production-origin byte equality for
  every artifact, legacy absence, exclusions, and archived overwrite denial;
* implementation would silently select a readiness-owned item above or require
  another request, runtime context, parser, renderer, asset, threshold, timing
  outcome, trust boundary, or weaker security, lifecycle, protection, or
  provenance rule; or
* an ADR renewal or stop condition is met.

Any administration or publication drift blocks delivery and reopens
https://github.com/FelixGeisler/code-city/issues/446[#446]; it is not repaired
by weakening protection or publishing raw private administration evidence.
Runtime, build, provider, parser, renderer, limit, lifecycle, or failure
deviations return to their owning requirement or ADR. A newly discovered
consequential choice is a blocker, not an implementation decision.
