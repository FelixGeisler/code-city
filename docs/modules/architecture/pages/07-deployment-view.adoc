= 7. Deployment View

This view is the authoritative implementation-independent deployment
synthesis accepted through
https://github.com/FelixGeisler/code-city/issues/463[#463] and extended by
https://github.com/FelixGeisler/code-city/issues/446[#446]. It links ADR 0002's
production target, browser-only contexts, direct-provider topology, and trust
crossings to ADR 0004's conceptual `/code-city/` static package, ADRs 0005 and
0006's exact GitHub origins, ADR 0007's five same-origin parser assets, ADR
0008's browser-native presentation, and ADR 0009's branch, publisher, and
cutover placement.

These accepted decisions create no current M1 shell, source, dependency,
configuration, asset, package, traffic, renderer, route, executable workflow,
branch administration, or deployment. This view selects no source map,
executable schema, emitted filename, worker-creation timing,
transport/cancellation primitive, preload policy, or test technology.

== Branch and publication migration

=== Accepted current-to-target transition

At this documentation change's observed baseline, v1 still occupies default
`main`, M1 occupies `v2`, no `v1` branch exists, and the target serves Antora
output from the legacy `main`-only Documentation workflow. The `github-pages`
environment has one custom `main` policy, but its observed read-back reports
`can_admins_bypass: true`. Those are dated pre-migration facts, not a lasting
contract and not a claim that migration has already occurred.

After this ADR's pull request merges into `v2`, the separately gated
administration renames old v1 `main` to `v1`, renames M1 `v2` including that
merge to `main`, makes the latter the default and active integration line, and
leaves no active `v2`. Commit identities and histories are preserved. The
resulting `v1` and immutable `v1.0.0` are archival comparison evidence only;
new work and all current repository documentation use the new `main`.

Only new `main` may publish `github-pages`. The old Documentation, Container,
and Release workflow registrations are disabled before the rename and remain
disabled; current CI remains enabled. The environment read-back reports
`can_admins_bypass: false` and exactly one custom deployment branch policy
named `main`, resolving only to the M1 line. Administrators cannot bypass that
policy, so the environment independently denies `v1`. Existing hosted
documentation may remain frozen until #460, but
it cannot be refreshed and is not a fallback. #460 replaces it with the M1
application; no documentation route, redirect, composite artifact, second
publisher, origin, environment, or preview path is accepted.

=== Protected administration and read-back

The migration occurs only after #446's guarded merge is closed, that merge
commit's `v2` push `verify` succeeds, remote tips match, `v1` is absent, no
pull request is open, and local state is clean. Before any rename, the
administrator snapshots refs and worktrees, disables and reads back legacy
workflow registrations, proves all such runs and legacy deployments are
terminal, fast-forwards local `v2` to the exact merge SHA without prune, and
installs the strict new-main protection on remote `v2`.

The new-main policy requires strict/up-to-date app-bound checks: `verify` from
GitHub Actions app ID `15368` and `delivery/architecture`,
`delivery/testing`, `delivery/requirements`, and `delivery/security` from
Quality Assurance app ID `4599126`. It requires protected pull requests and
conversation resolution, applies to administrators without bypass, rejects
force pushes and deletion, uses zero separate GitHub approving reviews, and
permits the accepted merge-commit method with required linear history false.
The archive policy has no obsolete required check or review gate; it applies
to administrators without bypass, sets `lock_branch` true, and rejects force
push and deletion.

The protected old `main` is renamed to `v1` before protected `v2` is renamed to
`main`; the former default remains protected during the interval. Protection
on new `main`, the `github-pages` environment read-back of
`can_admins_bypass: false`, and its exact one-`main` deployment branch policy
are proved before changing the default. Every remote operation is read back.
Local names and upstreams are
then reconciled without prune or reset, the stale `origin/v2` tracking ref is
removed only after remote absence is proved, and all detached worktree HEADs
must remain unchanged.

A sealed #464 administration packet records redacted before/after refs and
SHAs, default branch, protections and app bindings, environment policy,
workflow registrations and quiescence, runs and deployments, open-pull-request
state, worktrees, and local reconciliation. Its final environment evidence
includes the API read-back `can_admins_bypass: false` and the complete policy
read-back showing exactly one custom `main` deployment branch policy resolving
only to the new M1 line. Its digest is published in #464
before the Requirements readiness attestation. No #464 readiness or later M1
Developer handoff occurs until all state and evidence match ADR 0009. Failure
uses only a proved no-op continuation or exact inverse identity-preserving
rename and captured-policy restoration; no force, delete, synthetic commit,
prune, reset, weakened gate, or required-check workaround is allowed.

=== Build and final cutover ownership

https://github.com/FelixGeisler/code-city/issues/452[#452] owns the exact
source/package map, current-main CI trigger, conformance mechanism, first-party
Pages workflow event and gate, exact action versions, artifact root,
permissions, and production-artifact exclusions. Its merge must not deploy or
replace the hosted documentation.

https://github.com/FelixGeisler/code-city/issues/460[#460] alone explicitly
dispatches production after all prior slices and its exact-head reviews pass.
It proves successful push verification for the guarded merge commit, equality
of that commit's tree to the reviewed head tree without unrelated change, and
the exact dispatched commit and deployment/environment identity. It records a
complete manifest of relative URL, byte length, media type, and SHA-256, then
fetches the entry and every artifact from the exact origin with a deployment-
unique cache-busting query and requires byte-for-byte manifest equality. Every
entry reference must remain beneath `/code-city/`; known legacy assets and all
source, tests, documentation output, source maps, secrets, server artifacts,
and stale v1 assets must be absent. The evidence must also prove the archived
publisher cannot overwrite the deployment. A deployment API commit or
screenshot alone is insufficient.

This path accepts only new `main` as its eventual publisher and #460 as the

runtime/grammar assets become eligible only after the accepted static barrier,
never during provider-capable processing.

== Security invariants

* The only logical trust crossings are exactly:
** `User → UI main context`;
** `Public GitHub → processing worker`.
* Same-origin bridge traffic and GitHub Pages artifact delivery are not logical
  product-data trust crossings.
* Only the resulting M1 `main` may publish production through the single first-
  party Pages path. The archived branch, tags, forks, delivery branches, and
  retired workflows are independently denied by the environment policy, whose
  required read-back is `can_admins_bypass: false` with exactly one custom
  `main` deployment branch policy resolving only to the new M1 line.
* The Pages deploy job has only the required repository-read, Pages-write, and
  OIDC permissions. It introduces no long-lived deployment secret, repository
  or provider credential, external host, preview publisher, or fallback.
* No user or service credential is requested, accepted, read, retained, or
  transmitted.
* Repository metadata, paths, bytes, and source remain untrusted and inert.
  They are never executed, evaluated, imported, or dynamically loaded.
  Repository data cannot construct, alter, or select an asset URL or introduce
  a capability.
* The canonical path's final suffix selects one grammar family only through
  ADR 0007's closed mapping to already-packaged JavaScript, TypeScript, or TSX
  grammars. It never selects an asset URL, plugin, or new capability.
* The UI performs no GitHub/provider request. Pages receives no product data.
* Cross-boundary content remains limited to validated primitive resolution
  evidence; bounded selected-revision records/bytes, with retrieval/admission
  alone creating the complete admitted set; fresh primitive static-syntax
  observations; selected identity, one fixed terminal failure, or one complete
  source-free canonical scene through the bridge; and the two discriminator-
  plus-correlation lifecycle attestations.
* Raw/normalized source, provider objects, admitted modules, parser objects,
  metric intermediates, and partial scenes never reach presentation.
* Building identities remain inert model keys and never become normal-object
  keys, DOM/WebGL names or text, shader content, resource locators, or logs.
* The worker remains only an execution/lifecycle context, not a security
  boundary, sandbox, operating-system process, package, component, or trust
  crossing.

== Stop rules

Stop rather than assume, administer, configure, or deploy if:

* an accepted requirement or ADR contradicts this placement, or a stage,
  failure, cleanup action, retained datum, or one of the 13 exact ports loses
  its accepted owner;
* the pre-step repository, ref, worktree, workflow, run, deployment,
  protection, environment, default-branch, open-pull-request, or exact-SHA
  read-back differs from the captured state;
* the transition would change commit identity, use a force push, deletion,
  synthetic commit, destructive local repair, prune, reset, or unprotected
  active/default branch;
* the target-stage `github-pages` environment read-back does not report
  `can_admins_bypass: false`, or its deployment branch policies are not exactly
  one custom `main` policy resolving only to the new M1 line;
* M1 would use a branch other than resulting `main`, archived v1 would resume
  development/release/publication, or another branch, tag, fork, workflow,
  environment, publisher, origin, route, service, credential, preview, or
  fallback could publish production;
* #452's merge could deploy incomplete M1, or #460 could not prove guarded
  reviewed-tree equivalence, merge-commit push verification, explicit exact-
  commit dispatch, complete manifest, production-origin byte equality for
  every artifact, legacy absence, exclusions, and archived overwrite denial;
* implementation would silently select a deferred item above or require
  another request, runtime context, parser, renderer, asset, threshold, timing
  outcome, trust boundary, or weaker security, lifecycle, protection, or
  provenance rule; or
* an ADR renewal or stop condition is met.

A remote administrative failure permits only a captured-state no-op or exact
inverse identity-preserving rename and policy restoration followed by read-
back. Otherwise stop for human reconciliation. Branch/publication deviations
reopen #446; runtime, build, provider, parser, renderer, limit, lifecycle, or
failure deviations return to their owning requirement or ADR. A newly
discovered consequential choice is a blocker, not an implementation decision.
