= 9. Architecture Decisions

An ADR is used only when a decision is important, durable, and difficult to
infer from the architecture or source. Smaller choices stay with the relevant
page, code, or test.

[cols="2,3,3",options="header"]
|===
|Record |Decision |Why it matters

|xref:adr/0001-core-dependency-boundary.adoc[ADR 0001]
|Core rules are independent from external mechanisms
|Keeps product policy testable and replaceable

|xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002]
|Browser-only runtime on GitHub Pages
|Avoids credentials, backend operation, and persistence

|xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003]
|Explicit core responsibilities and ports
|Prevents accidental ownership and dependency drift

|xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR 0004]
|Framework-free TypeScript shell built with Vite
|Keeps the application surface small

|xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR 0005] and
xref:adr/0006-bounded-selected-revision-retrieval-via-github-tree-and-raw-content.adoc[ADR 0006]
|Direct anonymous GitHub resolution and retrieval
|Provides one immutable input without a backend

|xref:adr/0007-static-syntax-with-pinned-tree-sitter-webassembly-grammars.adoc[ADR 0007]
|Pinned Tree-sitter WebAssembly grammars
|Provides deterministic static syntax without executing source

|xref:adr/0008-browser-native-webgl2-instanced-city-presentation.adoc[ADR 0008]
|Browser-native WebGL2 presentation
|Meets the fixed rendering contract without a renderer package

|xref:adr/0009-m1-main-line-and-github-pages-cutover.adoc[ADR 0009]
|M1 uses `main`; v1 is archival; only `main` publishes
|Keeps one integration line and one production publisher

|xref:adr/0010-canonical-artifact-manifest-and-publication-evidence-contract.adoc[ADR 0010]
|Canonical artifact manifest and publication evidence
|Binds one reviewed package to its protected-main publication run
