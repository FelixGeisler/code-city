= Quality Requirements

Product thresholds, formulas, controls, and proofs remain in the requirements
and executable tests. These scenarios identify where architecture contributes.

[cols="1,2,2,2",options="header"]
|===
|Quality |Scenario |Architectural response |Evidence location

|Integrity
|Provider evidence is malformed, incomplete, redirected, truncated, or changes
identity.
|Bounded gateways fail closed; complete inventory and blob identity checks occur
before analysis; no partial city is published.
|`src/edge/github-*-gateway.ts`, `src/domain/source-admission.ts`, source
retrieval tests

|Determinism
|Equivalent accepted source facts are processed again.
|Canonical ordering, pinned grammars, pure metric/city policies, and closed
payload validation keep result meaning stable.
|xref:requirements:source-and-metrics.adoc[Source and Metrics], domain and
reproducibility tests

|Safety and privacy
|Repository-controlled content crosses provider, worker, or UI boundaries.
|Treat it as data, validate exact shapes, transfer a source-free result, publish
paths as inert text, and expose sanitized failures only.
|xref:requirements:city-and-failures.adoc[City and Failures], controller,
protocol, publication, and package-policy tests

|Atomicity
|An attempt is replaced, cancelled, stale, or fails during presentation.
|Generation gates, staged publication, rollback, and idempotent ownership cleanup
leave either one complete current city or none.
|`src/application/main-controller.ts`, worker-attempt and presenter tests

|Usability and accessibility
|A keyboard or pointer user investigates a current city across supported viewport
sizes.
|Native semantic controls, keyboard selection, visible focus, inert inspection
text, and responsive presentation accompany WebGL.
|xref:requirements:city-and-failures.adoc[City and Failures], semantic and camera
policy tests

|Release reproducibility
|A pull request or main publication is built.
|The locked closure, unchanged canonical build, second-build comparison,
package audit, inactive packaged-browser evidence, documentation build, and
workflow-owned Pages bindings are
verified. Separate mandatory gates also build the inactive standalone artifact,
audit complete manifest closure without rebuilding, compare a second isolated
build byte-for-byte, start and exercise the packaged server/worker/parser, and
verify joined signal shutdown.
|`package.json`, `.github/workflows/`, package, standalone-package, and
publication tests
|===

The accepted target adds availability, confidentiality, retention, recovery,
and capacity concerns for server-owned source and saved investigations. Their
mechanisms and measurable scenarios require the unresolved target design; this
chapter does not invent them.
