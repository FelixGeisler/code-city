= Architecture Constraints

== Current standalone constraints

* The package-supported Node.js runtime hosts one native same-origin
  `node:http` service. Each admitted analysis runs in one dedicated
  `worker_threads` worker. This is not an operating-system sandbox.
* The service is loopback-first. Deliberate trusted-LAN operation is limited to
  public GitHub source. Internet exposure, private repositories, company
  authentication, FLOW, and ADO are not approved.
* Only `--host` defaults. `--port` and all five capacity flags are required.
  No numerical capacity is a product default or deployment recommendation.
* Repository content is untrusted data. It is validated, decoded, and parsed,
  but never imported, executed, built, or tested.
* Supported languages, source admission, processing limits, metric semantics,
  and visual mapping are product constraints owned by the requirements module.
* Syntax analysis uses pinned WebAssembly grammars. Dependency and tool versions
  are authoritative only in `package.json` and `package-lock.json`.
* Temporary source-result association exists only in application process
  memory. There is no Save, reopen, persistence, or recovery.
* Raspberry Pi performance, concurrency, memory, and deployment qualification
  remain pending.

== Package boundary

The canonical `dist/` artifact contains `public/`, private `server/`, private
`parser/`, and one version-1 `package-manifest.json`. Manifest paths are
artifact-relative. The HTTP perimeter serves only verified public records and
returns `404` for the manifest, private files, and unlisted paths.

The browser contains no GitHub provider, raw-source payload, parser runtime,
grammar WASM, browser analysis worker, or fallback analysis path. It uses only
the same-origin session and command routes and keeps temporary interaction
state in memory.
