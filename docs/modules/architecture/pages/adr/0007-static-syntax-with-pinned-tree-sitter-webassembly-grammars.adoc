= ADR 0007: Pinned Tree-sitter syntax

Status:: Accepted

== Context

Metrics need deterministic JavaScript and TypeScript syntax without executing
source. A parser fallback would give the same module two meanings.

== Decision

[cols="1,2",options="header"]
|===
|Choice |Value

|Runtime |`web-tree-sitter@0.27.0`
|JavaScript grammar asset |WASM from `@vscode/tree-sitter-wasm@0.3.1`
|TypeScript and TSX grammar assets |Pinned, locally patched WASM reproduced
from `tree-sitter-typescript@0.23.2` as fixed by issue
https://github.com/FelixGeisler/code-city/issues/577[#577]
|`.js`, `.mjs`, `.cjs` |JavaScript grammar; visible JSX rejected
|`.jsx` |JavaScript grammar with JSX
|`.ts`, `.mts`, `.cts` |TypeScript grammar
|`.tsx` |TSX grammar
|===

For each module:

. Parse the complete normalised source without an old tree.
. Walk the complete tree iteratively and reject errors, missing nodes, recovery,
  or forbidden JSX.
. Only after successful validation, walk it again and emit the
  xref:../05-building-block-view.adoc#data-boundaries[grammar-neutral syntax
  observations] consumed by Metrics.

The parser adapter maps concrete grammar node types and offsets to that closed
observation vocabulary. Metrics alone owns inclusion, executable-unit
ownership, arithmetic, and final facts. No parser node, node name, callback,
diagnostic, source-derived object key, or parser API type crosses the port.

Runtime and grammar WASM are emitted application assets loaded only from fixed
same-origin URLs. At most one source module, parser, tree, cursor, and
observation stream is active. Validation resources are released before
projection resources are created. Ordinary paths release parser resources and processed source before
the next module. Parser work begins only after the provider-drained barrier in
xref:../06-runtime-view.adoc[Runtime View]; hard termination during the static
phase relies on worker-realm disposal rather than per-object cleanup.

Use no fallback parser, query layer, general custom-grammar mechanism,
incremental tree, type checker, linter, dependency resolver, recursive
JavaScript tree walk, parser logging, or source execution.

Issue https://github.com/FelixGeisler/code-city/issues/577[#577] records the
human-approved narrow exception to the former no-custom-grammar restriction.
The human accepted the bounded pinned grammar correction with “OK. Go.” after
being told it changes that restriction. The exception moves only the two
`call_expression` / type-query-call pairs from precedence declarations to
conflicts so valid `importOriginal<typeof import("...")>()` syntax is accepted.
It does not authorize another grammar, a fork, runtime loading, fallback, or a
general patch policy. The separate notice-packaging mechanism was selected
later under delegated Requirements Engineer authority, not by that human
approval.

== Consequences

Grammar versions define accepted syntax. A package, asset, ABI, grammar, or
capacity change requires review. Full-envelope evidence must include dense and
deep grammar-valid modules and prove that no private parser limit narrows the
published envelope. Provenance is recorded in
xref:adr/0007-static-syntax-evidence-appendix.adoc[the evidence appendix].
