= ADR 0007: Static syntax with pinned Tree-sitter WebAssembly grammars

Status:: Accepted

== Context

M1 must derive the exact lexical SLOC, explicit-unit, decision, ownership,
and canonical-fact contract in
xref:requirements:08-fixed-metric-semantics.adoc[Fixed Metric Semantics] from
every admitted JavaScript and TypeScript module without executing repository
source. The admitted envelope is the complete RA-07/RA-08/RA-09 envelope in
xref:requirements:06-source-admission-and-limits.adoc[Source Admission and
Repository Limits]. A recovered or partial syntax tree cannot satisfy the
complete-city-or-none invariant.

xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] keeps parser mechanisms
outside core.
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002]
places parser work in the same-origin processing worker.
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003]
assigns parser translation to the edge-side static-syntax adapter and metric
policy to core.
xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR 0004]
fixes exact `vite@8.2.1`, the `/code-city/` public base, and a separate
same-origin ES-module worker.
xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR 0005]
and
xref:adr/0006-bounded-selected-revision-retrieval-via-github-tree-and-raw-content.adoc[ADR 0006]
fix provider work, resource ownership, cancellation, and cleanup before static
processing.

This ADR selects the parser runtime and grammar assets; their exact behavior,
API and capability boundary; parser-to-core projection; phase-aware worker
lifecycle; the disposition of SP-01 through SP-04; immutable supply-chain and
WASM evidence; downstream evidence ownership; and stop rules. It adds no
package, source, configuration, manifest, executable fixture, parser asset, or
product artifact.

=== Closed suffix-to-grammar and failure contract

Compare the canonical path's final suffix ASCII case-insensitively:

[cols="3,7",options="header"]
|===
|Suffixes |Grammar and additional validation

|`.js`, `.mjs`, `.cjs`
|JavaScript grammar, followed by iterative rejection of every visible node
whose exact type is `jsx_attribute`, `jsx_closing_element`, `jsx_element`,
`jsx_expression`, `jsx_namespace_name`, `jsx_opening_element`,
`jsx_self_closing_element`, or `jsx_text`.

|`.jsx`
|The same JavaScript grammar without forbidden-JSX rejection.

|`.ts`, `.mts`, `.cts`
|TypeScript grammar.

|`.tsx`
|TSX grammar.
|===

The `m` and `c` spellings add no grammar behavior. `name.d.ts` uses the
ordinary TypeScript grammar; there is no declaration-file or `d.ts` parser
mode.

Before producing any semantic observation or metric fact for a module:

. inspect `rootNode.hasError`;
. iteratively inspect the complete tree for an `ERROR` node, any missing
  recovery node, and, for a non-JSX JavaScript family, every forbidden JSX
  node; and
. project only after complete validation succeeds.

Any such failure produces the existing atomic `Metric processing failed` /
`M1-MET-1` outcome. A recovered tree produces no facts, no malformed module is
skipped, and no partial metric set or city is published.

Contextual or static-semantic errors accepted by the pinned grammar do not
fail metric processing. The known accepted examples include top-level
`return`, `break`, and `continue`. Conversely, valid TypeScript 5.9-and-later
`import defer` syntax is rejected by the pinned TypeScript grammar and produces
`M1-MET-1`. These are normative acceptance examples.

M1 promises no TypeScript 7, latest-TypeScript, current-ECMAScript, or future
grammar compatibility and adds no contextual or static-semantic validator.

A trap, allocation failure, or private parser capacity on grammar-valid input
within the accepted RA envelope is a conformance defect. It is not
`M1-MET-1`, an SP result, or an implicit product limit.

=== Safe API, two passes, and cleanup

Parser use is confined to the worker-side parser adapter. The permitted surface
is exactly:

* `Parser.init`, with the fixed `locateFile`, `print`, and `printErr` options
  below;
* `Language.load(Uint8Array)`;
* parser construction, `setLanguage`, `parse(normalizedSource)` without an old
  tree or progress callback, and `delete`;
* `tree.rootNode`, `rootNode.hasError`, `rootNode.walk()`, and `tree.delete()`;
  and
* only the TreeCursor movement/getter subset required for iterative traversal:
  current node type, named/missing status, current field name, start/end
  indices, first-child movement, next-sibling movement, parent movement, and
  cursor deletion.

The following surfaces are prohibited:

* Tree-sitter queries or query cursors;
* recursive JavaScript walking or a generic recursive AST traversal;
* node parent, child, sibling, descendant, or convenience helpers;
* `childWithDescendant`;
* whole-child arrays;
* node text, stringification, tree/debug graphs, or source callbacks;
* parser helper APIs implicated by
  https://github.com/tree-sitter/tree-sitter/issues/5807[tree-sitter#5807];
* old-tree or incremental parsing; and
* parser logging or a progress callback.

Each module uses two iterative passes over one tree:

. a complete fact-free validation pass; then
. a projection pass only after validation succeeds.

At most one source module, parser, tree, and cursor are active at a time. The
validation cursor is deleted before the projection cursor is created. On
ordinary completion or failure, cursor, tree, and parser handles are deleted
in `finally`, and adapter-held source, endpoint, slice, and projection
transients are dropped before the next module. Language modules expose no
deletion operation and are released by worker-realm termination. Hard static
termination has the explicit exception in <<phase-lifecycle>>.

=== Parser/core projection, SLOC, and UTF offsets

Every parser-specific object remains edge-side. Projection validates fields
individually and creates only fresh primitive, core-owned observations held in
arrays, `Map`, or equivalent prototype-safe structures:

* source-ordered explicit-unit observations;
* decorator, computed-name, heritage, and field-initializer regions;
* decision occurrences;
* value-level and type-only observations; and
* lexical exclusion spans.

No parser node, token, comment object, name, diagnostic, callback, getter,
parser object or type, or source-derived object key crosses the static-syntax
port. Core remains the sole owner of conditional `top-level`, unit ownership,
complexity arithmetic, canonical identities and order, and final facts.

The parser receives only normalized source and the already-selected closed
grammar family. The repository path is not passed as a filename, configuration
key, resource locator, or source-derived object key.

Except for fixed trusted runtime and grammar loading, the parser mechanism
performs no configuration discovery, filesystem access, module resolution,
source import or transform, execution, evaluation, DOM access, storage,
telemetry, logging, provider request, or network request.

Lexical SLOC exclusions use exact node types `comment`, `html_comment`, and
`hash_bang_line`. JSX expression-container braces are excluded only when the
expression contains a comment and all remaining content is whitespace. Empty
`{}` remains source. The normalized source string--not node text--distinguishes
whitespace from string, template, regular-expression, and JSX text.

The web binding's indices and columns are UTF-16 code units. For every endpoint
needed by core observations, the adapter must:

. collect only required endpoints;
. sort and deduplicate them;
. validate every range and ensure no endpoint bisects a surrogate pair;
. translate every endpoint in one deterministic Unicode-scalar scan into a
  zero-based, half-open UTF-8 byte offset; and
. release the transient endpoint collection.

A whole-file UTF-16-to-UTF-8 lookup table is prohibited. Acceptance evidence
includes astral characters before and inside explicit-unit spans.

=== Exact Vite imports and runtime initialization

With exact `vite@8.2.1`, use only these fixed asset imports:

[source,text]
----
web-tree-sitter?url

@vscode/tree-sitter-wasm/wasm/tree-sitter-javascript.wasm?url
@vscode/tree-sitter-wasm/wasm/tree-sitter-typescript.wasm?url
@vscode/tree-sitter-wasm/wasm/tree-sitter-tsx.wasm?url

Dynamically import only the build-generated same-origin runtime URL:

[source,javascript]
----
await import(/* @vite-ignore */ runtimeJavaScriptUrl)
----

Initialize with these fixed semantics:

[source,javascript]
----
Parser.init({
  locateFile(requestedPath, scriptDirectory) {
    if (requestedPath === "web-tree-sitter.wasm") {
      return runtimeWasmUrl
    }
    throw new Error("Unexpected Tree-sitter runtime asset request")
  },
  print: noOp,
  printErr: noOp
})
----

`scriptDirectory` is ignored. Matching is exact over the complete string.
There is no basename or suffix match, normalization, concatenation, fallback,
or fetch inside `locateFile`. Any unknown request is a conformance stop, not
`M1-MET-1`.

Grammar bytes come only from their fixed imported URLs and are passed to
`Language.load(Uint8Array)`. Grammar loading never uses `locateFile`.

All emitted URLs are statically addressed beneath `/code-city/`. Repository
data cannot construct, alter, or select an asset URL. Ordinary bundling of the
runtime JavaScript is prohibited because the recorded Vite evidence emits a
browser-external Node shim.

The final artifact contains no Node shim, browser polyfill, older `@vscode`
runtime, unused grammar, query asset, native binding, parser plugin, or
source-derived capability.

The runtime WASM imports exactly these `wasi_snapshot_preview1` functions:

* `fd_write`;
* `fd_seek`; and
* `fd_close`.

`print` and `printErr` are no-ops and parser logging remains disabled. The
pinned glue's `fd_seek` and `fd_close` stubs return `ESPIPE` and `ENOSYS`. No
general WASI host, filesystem, socket or provider fetch, thread, shared memory,
nested worker, or source-derived capability is introduced.

[[phase-lifecycle]]
=== ADR 0005/0006-compatible phase-aware lifecycle

==== Fixed lifecycle attestations

The bridge may carry exactly two additional source-free internal lifecycle
attestations:

* `PROVIDER_DRAINED_STATIC_ENTERED`; and
* `ATTEMPT_DRAINED`.

Each carries only its discriminator plus the existing opaque bridge-generated
attempt/generation correlation. It carries no identity, provider value,
source, admitted module, parser value, metric, scene, diagnostic, timing, or
count.

These are internal lifecycle evidence, not UI outcomes, cryptographic
attestations, or physical teardown guarantees. Existing bridge transports
remain unchanged. The main bridge consumes them; they are never forwarded to
worker-outcome intake, visible state, status, or classification.

==== Provider-capable phase and barrier

Every generation begins provider-capable. No parser runtime import,
`Parser.init`, grammar fetch/load, parse, or traversal may begin before the
barrier.

After successful admission, the worker must:

. retain only the core-owned complete admitted-module handoff;
. settle all ADR 0005/0006 fetch, read, abort, reader-cancellation, rejection,
  JSON parsing, Web Crypto, strict decoding, and normalization work;
. release reader locks;
. clear every `Response`, reader, chunk, provider object, projected inventory,
  hash view, digest, raw/hash workspace, and other provider transient;
. release the global provider request and workspace gates; and
. establish that no provider operation can restart in that generation.

The worker pipeline then posts `PROVIDER_DRAINED_STATIC_ENTERED` and, unless
terminated, proceeds without waiting for acknowledgement to its first dynamic
runtime import, parser-asset fetch/load, `Parser.init`, or parser operation. No
provider operation occurs after the post and no parser operation before it.
Receipt of the matching attestation by the main bridge makes the generation
hard-termination-safe; the bridge may terminate immediately, before the worker
executes its first static operation.

==== Cancellation or replacement before barrier receipt

Before matching `PROVIDER_DRAINED_STATIC_ENTERED` receipt:

. the UI attempt coordinator immediately revokes publication eligibility and
  visible old-attempt state and coalesces replacements to the latest;
. the main bridge posts lifecycle stop and *must not* call `terminate()`;
. the worker pipeline suppresses downstream work;
. provider adapters abort/cancel and settle their exact ADR 0005/0006
  operations and release locks, gates, workspaces, and references in `finally`;
. the pipeline clears admitted modules and unpublished output and posts
  `ATTEMPT_DRAINED`;
. the main bridge marks the generation closing, calls `terminate()` exactly
  once, releases listeners and transport references, and clears its sole
  handle; and
. only after that clearing may it create the latest replacement and dispatch
  the first new provider request.

Required observable order:

[source,text]
----
revoke < provider settlement < lock/global-gate release < ATTEMPT_DRAINED < terminate old < clear handle < create new < first new provider request
----

Replacement delay while provider settlement remains pending is unbounded and
accepted. It creates no timing outcome.

==== Barrier race and hard static termination

Once the main bridge receives matching `PROVIDER_DRAINED_STATIC_ENTERED`, it
uses the static-phase path even when a lifecycle-stop message is queued but not
yet handled by the worker.

Cancellation or replacement then:

. revokes publication eligibility;
. calls `terminate()` on the sole worker without waiting for parser
  acknowledgement;
. clears the handle; and
. only then creates the latest replacement.

Required observable order:

[source,text]
----
provider settlement/global-gate release < post PROVIDER_DRAINED_STATIC_ENTERED < bridge receipt < hard terminate < clear handle < create replacement
post PROVIDER_DRAINED_STATIC_ENTERED < every parser/runtime/asset operation, if any
----

Zero static operations before hard termination is valid. If static work has
begun, termination may occur during any such operation. No cooperative
parser-stop, progress-callback, immediate computation-stop, or browser
teardown-latency claim is made.

==== Ordinary terminal path

On an ordinary terminal path:

. delete the validation or projection cursor as applicable, tree, and parser;
. clear source, endpoint, slice, projection, metric, admitted-module, and other
  core references;
. post only one source-free terminal outcome or one complete canonical scene;
. post `ATTEMPT_DRAINED`;
. let the main bridge apply or reject the terminal business payload through the
  publication gate; and
. after matching `ATTEMPT_DRAINED`, terminate the worker exactly once and clear
  its handle.

`ATTEMPT_DRAINED` means no operation remains and every explicitly releasable
handle, lock, gate, workspace, and reference is settled or released.
Realm-held language modules are released by the following worker termination.

Hard static termination may prevent JavaScript `finally` blocks and parser
`delete` calls from running. Evidence must not claim delete-spy observations on
that path. Realm termination releases parser, language, runtime, source, and
static transients without promising timing, secure erasure, garbage
collection, or operating-system process teardown. Provider work never relies
on hard termination.

==== Ownership and observable non-overlap

[cols="3,7",options="header"]
|===
|Owner |Exclusive lifecycle responsibility

|UI attempt coordinator
|Current attempt, publication eligibility, visible state, and latest
replacement.

|Main bridge
|Sole concrete `Worker` handle, generation correlation, hard-stop gate, and
transport/listener release.

|Worker pipeline
|Stage suppression, phase completion, and core-reference release.

|Provider adapters
|Physical provider resources and ADR 0005/0006 settlement.

|Parser adapter
|Ordinary-path parser handles.

|Worker termination
|Hard static realm release.
|===

“No overlap” means observable call order and at most one bridge-owned usable
worker handle, parser-handle set, provider slot, and raw/hash workspace. It
makes no claim about physical browser or operating-system teardown. The main
bridge's worker-generation gate is transport-resource ownership, not a second
orchestrator.

=== SP-01 through SP-04 and the full accepted envelope

SP-01 through SP-04 are explicitly unnecessary for M1:

[cols="4,6",options="header"]
|===
|Dimension |Accepted disposition

|SP-01 lower static-processing module count
|None. All `4,000` modules permitted by RA-07 reach analysis.

|SP-02 lower per-module processing-content limit
|None. The full RA-08 maximum of `2,097,152` normalized UTF-8 bytes per module
reaches analysis.

|SP-03 lower aggregate processing-content limit
|None. The full RA-09 maximum of `41,943,040` normalized UTF-8 bytes reaches
analysis.

|SP-04 static-processing duration
|None. No timer or elapsed-time result exists.
|===

There is no independent syntax-node, nesting, parser-memory, or allocation
limit. Analysis processes one tree at a time.

SP-01 through SP-04 have no value, timer, clock, cutoff, category, stable code,
precedence, interval, boundary, or T-1/T/T+1 scenario. `Static-processing limit
exceeded` does not exist in M1. The historical `2,000` modules, `1 MiB` per
module, `20 MiB` aggregate, and `30 seconds` proposals are rejected as
uncalibrated.

While no browser failure or lifecycle action occurs, elapsed analysis time
alone leaves the attempt `Loading` and creates no outcome. Any grammar-valid
full-envelope trap, allocation failure, private capacity, or failure to produce
exact facts is a conformance defect that reopens #450; it must not be hidden by
a lower limit, retry, fallback, or different parser.

== Rationale, rejected alternatives, and downsides

Tree-sitter is selected because the pinned browser runtime and grammars support
the closed four-family contract, iterative cursor-only projection, and
evidence at the full accepted envelope. Recorded feasibility includes
grammar-valid input with `100,000` nesting levels without recursive JavaScript
helpers.

Rejected alternatives are:

* *Babel:* recorded valid input at approximately 500 nesting levels throws
  `RangeError`.
* *Lezer:* the evaluated path has hidden stack capacities that do not establish
  the full accepted envelope.

Accepted costs and limitations are:

* 32-bit parser coordinates;
* growing WASM memory with a 2 GiB runtime maximum;
* six retained parse-stack versions internally;
* approximately 3.5 MB of WASM assets;
* version-coupled grammar-to-semantic mapping;
* same-origin runtime and grammar fetches during worker startup or first use;
* worker recreation after every terminal result, cancellation, or replacement;
* rejection of valid newer syntax such as TypeScript `import defer`;
* acceptance of some contextual/static-semantic early errors; and
* exact-pin and evidence-renewal work.

M1 makes no parser compatibility, browser availability, completion-time,
throughput, startup-time, or memory-performance promise.

== Stop and reopen rules

Stop implementation or merge and reopen #450 if:

* any selected runtime, package, asset, version, parser option, API use, grammar
  mapping, hash, generator, ABI, or canonical WASM inventory changes;
* `locateFile` requires anything other than the exact full-string mapping or
  receives an unknown request;
* implementation needs an API outside the permitted cursor-only surface;
* an expected grammar node cannot be mapped to accepted metric semantics;
* selected asset correspondence or immutable provenance cannot be verified;
* an unselected asset, older runtime, Node shim, browser polyfill, native
  binding, parser plugin, query asset, unexpected import, traffic, telemetry,
  or logging enters the artifact;
* fixed asset URLs cannot remain same-origin, statically addressed, and beneath
  `/code-city/`, or repository/source data can select an asset URL or
  capability;
* a grammar-valid full-envelope case traps, exhausts a private capacity, or
  produces incorrect facts;
* either iterative pass, primitive projection, UTF conversion, or ordinary
  cleanup cannot be demonstrated;
* ADR 0005/0006 provider settlement cannot complete before the static barrier;
* either lifecycle discriminator, payload restriction, barrier, drain,
  hard-stop, sole-handle, call-order, or publication invariant cannot be
  demonstrated;
* implementation would require changing ADR 0005 or ADR 0006, another
  dependency, parser, fallback, runtime context, product limit, compatibility
  layer, source-derived capability, or weaker security boundary; or
* #450's 22-file documentation boundary cannot be preserved.

No workaround may be introduced silently. A selected version, asset, API,
grammar, option, hash, ABI, lifecycle, or inventory change revises or
supersedes this ADR. A lockfile-closure-only change that leaves every selected
item and asset unchanged renews ADR 0004 dependency/artifact evidence without
reopening #450.
