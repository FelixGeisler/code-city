= ADR 0003: Core responsibilities and ports

Status:: Accepted

== Context

The core boundary needs clear ownership without turning every class or
function into an architectural component.

== Decision

[source,text]
----
edge ───────► application ───────► domain
  └──────────────────────────────► domain  (capability-local policy only)
----

The reverse directions are forbidden. Driving adapters enter application
ports. Conceptual ports describe capabilities; they are not required packages,
interfaces, classes, or runtime hops.

The blocks are listed in xref:../05-building-block-view.adoc[Building Blocks].
Each product decision has one owner. In particular, the worker pipeline
coordinator alone sequences worker capabilities and suppresses downstream work
after a terminal result. Transport moves bounded values but does not classify
product failures.

== Consequences

Implementation may combine or split files while preserving ownership,
dependency direction, and main/worker placement.
