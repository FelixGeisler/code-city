= ADR 0002: Browser-only M1 runtime and GitHub Pages deployment topology

Status:: Accepted

== Context

The accepted M1 journey is anonymous and current-session only. It needs one
production delivery target, deterministic processing of bounded untrusted
repository data, responsive cancellation and replacement, and atomic
publication of one complete city. The topology must not add a credential,
server-side product-data boundary, persistence, or an undeclared resource
limit.

xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] remains authoritative for
source dependencies. Its conceptual core and edge/adapters sides are not
packages, processes, deployment nodes, or runtime-call directions. This ADR
selects runtime and deployment placement without granting any new source
dependency.

== Decision

=== Topology and production target

* The production delivery target is the repository's existing public HTTPS
  GitHub Pages site at `https://felixgeisler.github.io/code-city/`. Its exact
  production origin is `https://felixgeisler.github.io`.
* The Pages delivery node serves trusted static UI and worker artifacts only.
  It receives no repository payload, admitted source, metric fact, city or
  scene data, attempt state, or credential.
* Code City runs entirely in the user's browser in one UI/presentation main
  context and at most one same-origin dedicated processing worker context. No
  additional Code City application runtime context exists.
* Public GitHub is the sole external information system. Repository resolution
  and selected-revision retrieval go directly and anonymously from the
  processing worker to only the GitHub origins and mechanisms later accepted
  by https://github.com/FelixGeisler/code-city/issues/448[#448] and
  https://github.com/FelixGeisler/code-city/issues/449[#449]. The UI makes no
  provider or repository request.
* The UI/worker split is an execution and lifecycle boundary. It is not an
  operating-system-process guarantee, security sandbox, logical trust
  crossing, component count, package boundary, or source-dependency rule.
* Adopting the existing target does not adopt its current Pages source,
  action or workflow, application route, or build and deployment mechanism.

M1 adds no Code City backend, relay, proxy, serverless function, server runtime,
database, queue, service credential, server-side product state, product
persistence, application-managed persistent cache, second retrieval path, additional
application runtime context, or speculative future extension point.

=== UI/presentation main-context responsibilities

The UI/presentation main context:

* owns the input draft, permitted normalization, and canonical grammar
  validation; invalid input is rejected before worker dispatch or provider
  interaction;
* owns current-attempt identity, observable state transitions,
  replacement/cancellation precedence, and the sole publication-eligibility
  gate;
* applies canonical URL updates without overwriting edits made after
  submission;
* owns presentation adaptation, inert use of repository-derived building
  identities, presentation failure, and presentation-resource cleanup;
* atomically publishes the complete city and selected identity, and rejects
  every stale, replaced, cancelled, partial, or late worker result; and
* owns current-session retention and reload reset, so reload starts a fresh
  empty session and restores nothing.

=== Processing-worker responsibilities

The processing worker:

* owns anonymous repository resolution, canonical identity validation,
  one-time immutable-revision selection, and pinning;
* owns selected-revision retrieval, the sole admission path, actual-data limit
  enforcement, deterministic ordering, metrics, and pure renderer-neutral city
  construction;
* keeps provider records, paths, source, admitted modules, counters, metrics,
  and construction intermediates transient and confined to the current
  attempt; repository data is never executed, evaluated, imported, or
  dynamically loaded;
* owns stage termination, suppression of downstream work, network and
  processing cancellation where the later accepted mechanism permits it, and
  release of transient processing references; UI rejection of late output
  remains authoritative; and
* enforces a deferred worker-side limit only after its owning issue accepts the
  exact value and semantics. Browser memory, request behavior, or renderer
  capacity is not an undeclared product limit.

=== Data flow and cleanup

. Pages delivers only the static UI and worker artifacts over HTTPS.
. The UI sends the worker only a current normalized, syntactically accepted
  submission and lifecycle control. Exact messages, schemas, and ports remain
  deferred.
. The worker communicates directly and anonymously with Public GitHub.
. The worker may return the selected canonical repository/revision tuple while
  the attempt is `Loading`, one terminal failure outcome, or one complete
  canonical scene.
. Raw or normalized source, repository entry content, admitted modules,
  parser/analyzer objects, and canonical metric intermediates do not cross
  into presentation. Canonical-scene building identities may cross only as
  inert model keys.
. Replacement or cancellation immediately revokes the old attempt's
  publication eligibility in the UI and clears identity, city, and
  presentation state as the accepted state contract requires. The worker stops
  feasible work, suppresses downstream stages, and releases transient
  references; any late outcome is ignored.
. A stage failure stops downstream work. Presentation owns cleanup of
  incomplete presentation resources. After a successful complete-scene
  handoff, worker processing intermediates do not become retained product
  state and are released without a cleanup-latency or secure-erasure promise.
. Reload discards all application-managed session state. Provider, browser,
  operating-system, network, and platform caching or garbage-collection
  internals are not redefined.

=== Trust placement

The only logical trust crossings are *User → UI main context* and *Public
GitHub → processing worker*. Every inbound user or GitHub-derived value remains
untrusted and inert. GitHub is authoritative only for canonical repository
spelling and its designated default-branch tip, subject to #448's later
accepted validation.

No user or service credential crosses any boundary or is requested, read,
retained, or transmitted. Same-origin UI-to-worker communication is not a trust
crossing, and the Pages delivery node introduces no product-data trust
boundary.

=== Feasibility stop rule

https://github.com/FelixGeisler/code-city/issues/448[#448] and
https://github.com/FelixGeisler/code-city/issues/449[#449] must each establish
documentary/read-only feasibility for its selected direct anonymous
worker-to-GitHub mechanism from the exact production origin
`https://felixgeisler.github.io`. Together their evidence must cover every
selected endpoint and redirect target, required cross-origin methods, statuses,
body and header visibility, anonymous request and rate-limit policy,
immutable-identity evidence, bounded retrieval and early-stop behavior, and
cancellation and release behavior.

If either issue cannot establish all applicable evidence, that issue remains
unaccepted and #446 must be reopened. No proxy, relay, backend, serverless
function, credential, persistent cache, opaque unbounded response,
automatic-retry workaround, second retrieval path, or other fallback mechanism
may be introduced silently.

This rule selects no endpoint, API, target origin, redirect or request
implementation, retry, retrieval mechanism, proxy, relay, cache, or fallback.

== Rationale

This is the smallest topology that fits the anonymous, current-session-only
journey and the existing public HTTPS delivery target. Direct browser
processing avoids a new server trust or abuse surface, source-data handling or
logging boundary, credential, operations, cost, queue, persistence,
cancellation race, and shared-egress quota concentration.

The dedicated processing context keeps provider and bounded untrusted-source
processing away from presentation, preserves UI responsiveness and an explicit
cancellation/release boundary, and remains compatible with ADR 0001.

== Downside

Every later shell, GitHub, analysis, and visualization choice is constrained to
browser execution. Feasibility depends on exact cross-origin behavior,
redirects, request and anonymous-rate behavior, bounded reads, memory, and
cancellation. Worker communication and lifecycle add serialization and
coordination cost. The worker is not a security boundary, and M1 has no server
offload, shared cache, recovery, or quota mediation.

== Rejected alternatives

* *One static UI execution context.* Rejected because substantial synchronous
  retrieval or processing can block observable cancellation or replacement
  and weakens cleanup isolation.
* *Browser plus a stateless service or backend, including a narrow relay or
  serverless variant.* Rejected because additional cross-origin flexibility
  does not justify another trust crossing, anonymous compute and abuse
  surface, source or logging exposure, runtime operations and cost,
  cancellation race, quota concentration, or pressure for credentials,
  queues, or state.

== Exclusions

* product behavior or a requirements contract;
* a shell, framework, build, packaging technology, Pages source, action or
  workflow, application route, deployment mechanism, SSR behavior, browser
  support matrix, or availability target;
* a GitHub endpoint, API, target origin, request, header, redirect, retry, or
  retrieval mechanism;
* a parser, analyzer, renderer, test tool, dependency, or technology;
* an internal building block, conceptual port, message or port schema, package
  layout, source mapping, worker lifecycle or cancellation primitive, or
  enforcement tool;
* an RA-10/RA-11, SP-01 through SP-04, CC-09, PR-01, or other new value,
  threshold, unit, interval, measurement, or undeclared browser, provider, or
  renderer limit; or
* platform caching, garbage collection, secure erasure, cleanup latency, an
  operating-system-process guarantee, or a worker security boundary.

remain with those issues. ADR 0001 remains unchanged and authoritative for
