= ADR 0008: Browser-native WebGL2 instanced city presentation

Status:: Accepted

== Context

The accepted M1 city contains only fixed axis-aligned building prisms, fixed
opaque colors, one orthographic view, and passive resize. The visualization
mechanism must present every valid complete canonical scene within the accepted
envelope without adding labels, interaction, source-derived active values, a
renderer supply chain, or a fallback. It must also preserve the construction
and presentation failure boundary from
xref:requirements:10-fixed-city-layout-and-presentation.adoc[Fixed City Layout
and Presentation] and the current-attempt atomicity from
xref:requirements:04-functional-requirements.adoc[Functional Requirements].

xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] keeps renderer technology at
the edge. xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR
0002] places presentation in the UI main context and renderer-neutral city
construction in the processing worker.
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003]
assigns the presentation adapter and UI attempt coordinator their exclusive
responsibilities. xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR
0004] selects the future framework-free browser shell. This decision selects
the visualization technology and its exact fixed realization without changing
those boundaries.

== Decision

=== Selection and placement

Use raw browser-native WebGL2 and GLSL ES 3.00, implemented only by the UI-main
presentation edge adapter. The processing worker and canonical city remain
renderer-neutral. The adapter consumes one complete canonical scene for the
current eligible generation; it receives no repository source, admitted
modules, parser or analyzer objects, metric intermediates, or partial scene.

No renderer npm package, add-on, plug-in, external shader, texture, font,
model, asset, loader, controls package, rendering worker, compatibility layer,
or fallback is selected. WebGL1, WebGPU, Canvas 2D, SVG, and every other
renderer are prohibited as fallbacks. The two fixed shader strings in this ADR
are trusted repository-source literals, not externally loaded assets.

=== Source-free projection and failure ownership

The worker-side city constructor authoritatively validates and constructs the
complete canonical model. Invalid, duplicate, incomplete,
empty-at-this-stage, malformed, unsafe, unrepresentable, missing, additional,
or repeated canonical mappings; inconsistent model facts; or inability to
complete the exact model produces only `City construction failed` /
`M1-CITY-1`.

Before creating any WebGL resource, the presentation adapter defensively
projects and validates the complete handoff field by field:

* Every required root, collection, building, vector, color, bounds, and view
  field must be an own data property containing the expected primitive or
  bounded collection value.
* A missing field, inherited value used instead of an own value,
  accessor-backed expected field, sparse or wrong-count collection, wrong
  primitive type, non-finite number, unsafe integer, duplicate identity,
  inconsistent geometry, bounds, palette, order, view, or unrepresentable
  canonical value is an upstream construction-contract breach and propagates
  `M1-CITY-1`.
* Additional own fields outside the canonical contract are ignored without
  becoming control state. Their values and accessors are not evaluated merely
  for diagnostics. This does not permit an additional canonical mapping or
  collection entry.
* `N` equals the complete building count, identities are unique, and
  `1 <= N <= 4,000`.
* Integer geometry and palette bytes require exact equality. Bounds,
  square-shelf placement, identity order, fixed palette membership, target,
  basis, projection values, and the no-interaction policy must agree with
  #444. Only #444's camera-scalar tolerance is permitted.
* Arrays and `Map`, or an equivalent prototype-safe map, are permitted. A
  building identity must never become a property key in a normal object.
* A descriptor or defensive model-validation operation that throws is an
  upstream construction-contract breach and propagates `M1-CITY-1`; no raw
  exception or source-derived diagnostic is exposed.

The adapter never repairs, reorders, clamps, truncates, reconstructs, or
reclassifies malformed canonical data. A model defect or validation throw
creates no WebGL resource, cleans adapter-local staging, and propagates
`M1-CITY-1` unchanged. The bridge transports that fixed outcome without
classifying exceptions. The UI attempt coordinator alone commits the
current-attempt visible state under #441.

`Presentation failed` / `M1-PRES-1` starts only after an already-valid complete
model has passed defensive validation. It covers failure of fixed GPU
representation or allocation, canvas or context creation, returned context
attributes, shader or program establishment, upload, draw, framing, passive
resize, context loss, or another required presentation operation.

Within presentation adaptation, building paths and identities,
repository/source values, URLs, object keys, markup, and diagnostics must never
become DOM text, names, IDs, classes, attributes, WebGL labels, shader text or
defines, resource locators, or log content. The UI coordinator's separately
required canonical repository URL and full commit ID remain governed by #441
and do not enter the presentation adapter.

=== Fixed prism, buffers, and draw

The only mesh is the following unit prism and corner order:

[source,text]
----
0=(0,0,0)
1=(1,0,0)
2=(1,1,0)
3=(0,1,0)
4=(0,0,1)
5=(1,0,1)
6=(1,1,1)
7=(0,1,1)
----

The position buffer contains those eight corners as exactly 24 `float32`
values, or 96 bytes. The outward counter-clockwise index buffer contains
exactly these 36 `uint8` values, or 36 bytes:

[source,text]
----
0,3,2, 0,2,1,
4,5,6, 4,6,7,
0,4,7, 0,7,3,
1,2,6, 1,6,5,
0,1,5, 0,5,4,
3,7,6, 3,6,2
----

The only per-instance representation is one interleaved buffer with a 28-byte
stride:

[cols="4,1,4,1",options="header"]
|===
|Attribute |Location |Representation |Offset
|Target-relative minimum corner |`1` |three `float32` values |`0`
|Dimensions |`2` |three `float32` values |`12`
|Opaque palette RGBA |`3` |four normalized `uint8` values |`24`
|===

Location `0` reads the unit-prism position buffer. At `N = 4,000`, the
instance buffer is exactly `112,000` bytes.

One active presentation owns exactly one linked program, one vertex-array
object, one position buffer, one index buffer, and one instance buffer. Setup
may own the two required shader objects until they are deleted. Each initial or
resize draw issues exactly:

[source,text]
----
drawElementsInstanced(TRIANGLES, 36, UNSIGNED_BYTE, 0, N)
----

There is no per-building WebGL or DOM object, per-building matrix, normal,
texture, framebuffer, material, scene graph, renderer cache, second program,
second VAO, or second draw call.

=== Exact shader literals

The production shader strings are exactly the ASCII lines in the following
blocks joined by LF, including one final LF. They are fixed trusted literals
with no substitution or interpolation.

.Vertex shader
[source,glsl]
----
#version 300 es
precision highp float;

layout(location = 0) in vec3 a_unitPosition;
layout(location = 1) in vec3 a_targetRelativeMinimum;
layout(location = 2) in vec3 a_dimensions;
layout(location = 3) in vec4 a_color;

uniform mat4 u_clipFromTarget;

flat out vec4 v_color;

void main() {
  vec3 targetRelativePosition = a_targetRelativeMinimum + a_unitPosition * a_dimensions;
  gl_Position = u_clipFromTarget * vec4(targetRelativePosition, 1.0);
  v_color = a_color;
}
----

.Fragment shader
[source,glsl]
----
#version 300 es
precision highp float;

flat in vec4 v_color;
layout(location = 0) out vec4 o_color;

void main() {
  o_color = v_color;
}
----

No source-derived text, shader define, second shader variant, lighting, normal
calculation, texture sampling, tone mapping, fog, color interpolation, or
dynamic shader construction is permitted.

=== Canvas and context

Create one detached candidate `<canvas>` and request only `"webgl2"` with
exactly these options:

[source,text]
----
alpha: false
antialias: false
depth: true
desynchronized: false
failIfMajorPerformanceCaveat: false
powerPreference: "default"
premultipliedAlpha: false
preserveDrawingBuffer: false
stencil: false
xrCompatible: false
----

A null context or null `getContextAttributes()` result is `M1-PRES-1`. Returned
behavior-critical values `alpha`, `antialias`, `depth`,
`premultipliedAlpha`, `preserveDrawingBuffer`, and `stencil` must equal the
requested values. The remaining requested values are fixed creation hints or
inactive capability defaults; a returned difference permits neither another
renderer nor another feature.

Use only the default sRGB drawing-buffer behavior; do not opt into Display-P3
or another color space. Device pixel ratio is ignored and effectively fixed at
`1`: canvas backing width and height equal the host's positive integer
`clientWidth` and `clientHeight` exactly. A non-positive or non-integer initial
or changed host size is `M1-PRES-1`.

After initial context creation and every canvas backing-size change, read
`drawingBufferWidth` and `drawingBufferHeight`. Before drawing or publication,
both must exactly equal the corresponding positive integer host `clientWidth`
and `clientHeight` and canvas backing `width` and `height`. A mismatch is
`M1-PRES-1`; it is never clamped or accepted. Camera aspect and viewport use
only the verified-equal drawing-buffer dimensions. Assuming equality without
reading it, or adapting the requested backing size to a mismatch, is
prohibited.

=== Closed WebGL surface and draw state

Every draw re-establishes all of this state:

* opaque white clear color `(1,1,1,1)` and clear depth `1`;
* all color channels writable and depth writes enabled;
* `DEPTH_TEST` enabled with `LESS`;
* `CULL_FACE` enabled with `BACK` and `CCW` front faces;
* blending, dithering, stencil testing, scissor testing, polygon offset fill,
  rasterizer discard, sample coverage, and sample alpha-to-coverage disabled;
* viewport `(0,0,width,height)`, where `width` and `height` are the
  verified-equal `drawingBufferWidth` and `drawingBufferHeight`;
* clear exactly `COLOR_BUFFER_BIT | DEPTH_BUFFER_BIT`; and
* bind the one program and VAO, upload `u_clipFromTarget` with
  `transpose=false`, and issue the one instanced draw.

Production WebGL property reads are closed to `drawingBufferWidth` and
`drawingBufferHeight`. Production WebGL method use is closed to:

* context inspection: `getContextAttributes`, `getError`, and `isContextLost`;
* shaders/program: `createShader`, `shaderSource`, `compileShader`,
  `getShaderParameter`, `deleteShader`, `createProgram`, `attachShader`,
  `linkProgram`, `getProgramParameter`, `getUniformLocation`, `useProgram`,
  `uniformMatrix4fv`, and `deleteProgram`;
* VAO/buffers: `createVertexArray`, `bindVertexArray`, `deleteVertexArray`,
  `createBuffer`, `bindBuffer`, `bufferData`, `deleteBuffer`,
  `enableVertexAttribArray`, `vertexAttribPointer`, and
  `vertexAttribDivisor`; and
* fixed state/draw: `enable`, `disable`, `colorMask`, `depthMask`, `depthFunc`,
  `cullFace`, `frontFace`, `viewport`, `clearColor`, `clearDepth`, `clear`, and
  `drawElementsInstanced`.

No extension is requested, including `WEBGL_lose_context`. No shader/program
info log, debug or diagnostic API, generic state query, readback, framebuffer,
texture, timer, sync, transform-feedback, query, logging, or telemetry API is
used.

After complete-model validation, a null shader, program, uniform, VAO, or
buffer; compile/link status failure; allocation or API throw; drawing-buffer
dimension mismatch; any observed WebGL error; lost context; or failure to
complete the fixed representation, upload, or draw sequence produces
`M1-PRES-1`. Raw WebGL or implementation diagnostics are never shown or
logged.

=== Camera and clipping mechanism

Let #444's exact bounds lengths be `Lx`, `Ly`, and `Lz`, target be `T`, positive
aspect be `a`, and accepted basis be:

[source,text]
----
D = (1,1,1) / sqrt(3)
R = (1,0,-1) / sqrt(2)
V = (-1,2,-1) / sqrt(6)
E_r = (Lx + Lz) / (2*sqrt(2))
E_v = (Lx + 2*Ly + Lz) / (2*sqrt(6))
H = (11/10) * max(E_v, E_r/a)
----

The renderer mechanism is:

[source,text]
----
E_d = (Lx + Ly + Lz) / (2*sqrt(3))
world camera = T + 3*E_d*D
near = E_d
far = 5*E_d
orthographic horizontal half-size = aH
orthographic vertical half-size = H
----

`u_clipFromTarget` maps target-relative coordinates through that basis and
orthographic volume. Centered city depth is within `[-E_d,+E_d]`; camera-space
depth is therefore within `[-4E_d,-2E_d]`, strictly inside clip depth
`[-5E_d,-E_d]`.

Canonical camera scalars are evaluated as JavaScript `Number` values and retain
#444's accepted component-wise tolerance. The uploaded `float32` matrix and
pixels are renderer facts; pixel hashes and screenshot equality remain
non-acceptance evidence.

=== Float-representation feasibility

For normalized module byte counts `B_i`, aggregate `B`, executable-unit counts
`U_i`, and module count `N`, the complete accepted envelope proves:

[source,text]
----
B <= 41,943,040
N <= 4,000
U_i <= 1 + floor(B_i/3)
sum(U_i) <= N + floor(B/3) <= 13,985,013
max X or Z <= sum(U_i) + 2N - 1 = 13,993,012 < 2^24
max Y <= 2,097,153 < 2^24
----

Dimensions are positive integers below `2^24` and therefore exact in
`float32`. After subtracting `T`, every minimum corner and prism endpoint is an
integer or half-integer with magnitude below `2^23` and is also exact in
`float32`. This is a derived feasibility proof, not a new product cap.

Evidence renewal follows the existing issue order without adding a blocker:

* https://github.com/FelixGeisler/code-city/issues/455[#455] renews the
  executable-unit density premise `U_i <= 1 + floor(B_i/3)`.
* https://github.com/FelixGeisler/code-city/issues/457[#457], already a direct
  blocker of #458, supplies full-envelope renderer-neutral canonical scenes
  and renews the resulting maximum-coordinate, half-integer, and
  `float32`-representability bounds.
* https://github.com/FelixGeisler/code-city/issues/458[#458] relies on this
  documentary proof and #457's fixtures while validating the renderer. It
  reads both drawing-buffer dimensions initially and on resize, proves exact
  host/client/backing/drawing-buffer equality before draw or publication, and
  proves mismatch fails as `M1-PRES-1` without clamping.
* https://github.com/FelixGeisler/code-city/issues/459[#459], which already
  depends on #455, #456, #457, and #458, integrates actual base-metric and
  complexity results through canonical construction and presentation.
* https://github.com/FelixGeisler/code-city/issues/460[#460] renews final-head
  hosted and end-to-end evidence, including initial and resized
  drawing-buffer equality and fail-closed mismatch behavior.

A contradiction in the renewed premise, construction bounds, fixtures, or
implementation stops the affected work and reopens #451. It cannot be hidden
by rounding, clamping, truncation, reconstruction, or a private lower capacity.

=== Observer-before-publication and atomic initial publication

Initial presentation follows exactly this order:

. Defensively validate the complete current-generation canonical scene. A
  model defect or validation throw propagates `M1-CITY-1` and stops before
  WebGL.
. Source-freely project the already-valid scene into the fixed representation
  and check generation eligibility before renderer staging.
. Read the host's positive integer `clientWidth` and `clientHeight`; create the
  detached canvas with matching backing dimensions; immediately register one
  `webglcontextlost` listener with `{ passive: true, once: true }`; and create
  the context. Read and verify actual drawing-buffer dimensions, then compile,
  allocate, upload, and draw while detached using those verified dimensions
  for camera aspect and viewport.
. Check for throws, drawing-buffer mismatch, WebGL errors, context loss, and
  generation eligibility after synchronous operations.
. Construct the single `ResizeObserver` with an asynchronous,
  generation-guarded callback and successfully call `observe(host)` while the
  candidate canvas remains detached. Constructor or `observe` failure is
  `M1-PRES-1`; disconnect any constructed observer and dispose the candidate.
  Publication cannot precede successful setup.
. Immediately before final commit, reread host `clientWidth` and
  `clientHeight`. A non-positive or non-integer value is `M1-PRES-1`. If either
  differs from the canvas backing dimensions, update both backing dimensions,
  read and verify drawing-buffer equality, recompute the aspect-dependent
  projection and viewport from verified dimensions, reapply fixed draw state,
  clear, and issue exactly one instanced draw while still detached. Perform
  post-operation checks and check current-attempt eligibility once more.
. In one synchronous, no-yield commit, publish the canvas, current identity,
  and `Success`. A failed or stale candidate never reaches the DOM.

The observer callback is asynchronous and generation-guarded. Observer setup
and the final host reread through commit have no yield; the callback does not
replace the mandatory final reread and cannot publish. An abort after observer
construction disconnects it before idempotent candidate disposal. Attaching
the observer after publication is prohibited because setup failure could then
follow a partial success.

Synchronous WebGL calls are not promised to be preemptible. Cancellation or
replacement still revokes eligibility, and the required post-operation
eligibility check prevents a stale result from publishing. No timer, animation
frame, microtask yield, retry, debounce, or network operation is added to the
commit.

=== Passive resize and context loss

For a changed positive integer host size, the observer:

* uses the same canvas, context, program, VAO, and buffers;
* sets backing dimensions exactly to the latest host `clientWidth` and
  `clientHeight`;
* immediately reads `drawingBufferWidth` and `drawingBufferHeight` and requires
  exact equality with host/client and canvas backing dimensions before draw;
* recomputes only aspect-dependent projection and viewport from those verified
  dimensions;
* reapplies fixed draw state, clears, and issues exactly one instanced draw;
  and
* performs no buffer rebuild, reupload, building reorder, animation, timer,
  debounce, or retry.

Unchanged dimensions cause no draw. Platform observer batching is accepted;
M1 promises only the latest reported host size, not every intermediate resize.
A non-positive changed size, observer callback throw, drawing-buffer mismatch,
context loss, WebGL error, or failed resize draw is `M1-PRES-1`.

The loss listener never calls `preventDefault`; restoration is not enabled.
There is no `webglcontextrestored` listener, restoration path,
extension-induced loss, retry, or fallback.

The current published presentation uses these exact visible transitions:

[source,text]
----
Success
  -- current published WebGL context loss -->
Failure / Presentation failed / M1-PRES-1

Success
  -- required passive-resize presentation failure -->
Failure / Presentation failed / M1-PRES-1
----

* If the current candidate loses context before publication, it fails with
  `M1-PRES-1` and publishes no canvas or city.
* If the current published context is lost, or a required resize render fails
  after `Success`, the UI synchronously enters `Failure` with
  `Presentation failed` / `M1-PRES-1`, retains the current canonical
  repository URL, full commit ID, and input draft, removes the city and canvas,
  and disposes the presentation.
* That post-`Success` failure remains until resubmit or reload. Editing alone
  does not clear it.
* A stale queued loss or resize callback performs only local idempotent
  disposal and cannot change visible state.

=== Cleanup

Normal failure, replacement, cancellation, and reload disconnect the observer,
remove the loss listener and canvas, delete each live shader, program, buffer,
and VAO exactly once, and clear adapter-owned typed data and references.
Successful upload need not retain a CPU render cache. If the context is already
lost, cleanup removes DOM nodes, listeners, observers, and references but makes
no claim that WebGL deletion releases driver resources.

Cleanup is application-owned and exactly once. It makes no secure-erasure,
immediate network/computation stop, driver-release latency, garbage-collection
timing, physical browser teardown, or operating-system-process teardown claim.

=== CC-09 and PR-01

CC-09 city-construction duration and PR-01 presentation duration are explicitly
unnecessary for M1. They have no value, unit, timer, clock, deadline, interval,
cutoff, category, stable code, precedence, threshold, boundary, or
T-1/T/T+1 scenario. Arbitrary elapsed construction or presentation time alone
creates no outcome; while work has produced neither a browser/platform failure
nor a lifecycle result, the attempt remains `Loading`.

M1 makes no completion, startup, frame-time, throughput, latency, or preemption
promise. Feasibility follows from the complete accepted envelope, fixed
resource counts, `O(N)` projection and upload for `N <= 4,000`, one draw call,
and the float proof, not an uncalibrated timer. Actual construction or
presentation failures retain `M1-CITY-1` or `M1-PRES-1`; elapsed time alone is
neither.

== Rationale

Direct instanced WebGL2 satisfies the accepted fixed scene with no renderer
package or selected renderer supply chain. It provides the needed fixed prism
geometry, fixed colors, depth-tested three-dimensional presentation,
orthographic framing, and passive resize while preserving the UI-edge boundary
and one complete-model draw policy.

The implementation cost is explicit WebGL state and lifecycle handling. That
cost is bounded and made reviewable by the exact resources, shader literals,
API surface, draw state, camera mechanism, atomic staging, and cleanup rules
above.

== Consequences and downside

* M1 owns explicit WebGL state, shader/program/buffer setup, drawing-buffer
  validation, resize, context-loss handling, and exact cleanup code.
* M1 has no renderer diagnostic logs, recovery, restoration, retry, alternate
  renderer, or fallback.
* Failure to establish or retain presentation of an already-valid complete
  model produces `Presentation failed` / `M1-PRES-1`, including after
  `Success` for current context loss or required resize failure.
* The one program, VAO, draw-call, fixed-state design is intentionally not an
  extension point for future renderer features.
* Browser compatibility evidence is point-in-time and creates no supported-
  browser matrix or warranty.

== Rejected alternatives

* `three@0.185.1` with `@types/three@0.185.4` adds a broad renderer and type
  dependency closure, including six direct ranged type-package dependencies,
  for capabilities M1 does not use.
* `@babylonjs/core@9.21.2` adds a broad runtime package and abstractions beyond
  the fixed scene.
* `regl@2.1.1` and `twgl.js@7.0.0` add wrappers and supply-chain surface while
  M1 still needs a fixed explicit state contract.
* WebGPU adds a different compatibility and lifecycle boundary.
* Canvas 2D and SVG do not directly realize the accepted depth-tested
  three-dimensional presentation.
* WebGL1, another renderer, a compatibility layer, or fallback would weaken the
  fixed mechanism and failure contract.
