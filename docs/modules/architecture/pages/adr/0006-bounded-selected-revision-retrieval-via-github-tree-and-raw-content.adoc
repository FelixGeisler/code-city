= ADR 0006: Bounded selected-revision retrieval via GitHub tree and raw content

Status:: Accepted

== Context

The accepted M1 journey must consume the immutable repository tuple selected by
xref:adr/0005-anonymous-github-default-branch-tip-resolution-via-rest.adoc[ADR 0005],
retrieve only that revision, apply the exact bounded path, kind, content, and
ordering contract in
xref:requirements:06-source-admission-and-limits.adoc[Source Admission and
Repository Limits], and publish either one complete ordered admitted-module set
or one accepted terminal result. Repository metadata, paths, and bytes remain
untrusted and inert.

xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] keeps GitHub mechanisms
outside the core.
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002]
places direct anonymous provider traffic in the processing worker and permits
no Code City backend, proxy, credential, or persistent product state.
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003]
makes retrieval/admission the sole admitted-module creator while a GitHub edge
adapter owns physical provider resources.
xref:adr/0004-framework-free-typescript-shell-built-with-vite.adoc[ADR 0004]
requires a browser-worker mechanism without an unapproved dependency.
ADR 0005 supplies only the canonical owner/repository URL and selected full
lowercase 40-hex commit; it retrieves no source.

This ADR fixes the complete selected-revision retrieval mechanism, validation
horizons, resource and cancellation policy, timing disposition, evidence
limits, and renewal boundary. It is a documented decision only. This change
adds no product source, provider traffic, fixture, probe, captured payload,
dependency, configuration, workflow, or generated artifact.

== Decision

=== Immutable input, sequence, and sole ownership

Retrieval consumes only ADR 0005's canonical owner/repository URL and selected
full lowercase 40-hex commit. It never resolves or reuses a branch, tag, tip,
ref, or provider URL. In the processing worker, the current attempt performs
exactly this sequence:

[source,text]
----
1. GET https://api.github.com/repos/{owner}/{repository}/git/commits/{commit}
2. Validate the selected commit identity and project its root full 40-hex tree SHA.
3. GET https://api.github.com/repos/{owner}/{repository}/git/trees/{tree}?recursive=1
4. Complete #442 path, collision, submodule, extension, kind, and RA-06 metadata horizons.
5. GET candidate bytes sequentially, in canonical unsigned-UTF-8 identity order, from
   https://raw.githubusercontent.com/{owner}/{repository}/{commit}/{encoded-raw-path}
6. Retrieval/admission alone returns one complete ordered admitted-module set
   or one accepted terminal result.
----

The retrieval/admission capability is the sole owner of `M1-ADM` and RA
classification and the sole creator of admitted modules. The edge adapter
supplies bounded selected-revision records and bytes and owns its physical
request, stream, and hash resources; it creates no independent admission path.
No partial set or intermediate provider result is published.

No SDK or dependency, archive or codeload request, Contents traversal,
REST-per-blob request, Smart HTTP or browser Git, backend, proxy, credential,
persistence, automatic retry, wait, range request, `HEAD`, raw query parameter,
rate probe, fallback, Git LFS or media dereference, second retrieval/admission
path, syntax parsing, source execution, source logging, source-to-UI transfer,
blob/object URL, or provider-returned locator is permitted.

=== Exact REST requests

The commit-object and recursive-tree requests use native worker Fetch with
exactly:

[source,text]
----
method: GET
Accept: application/vnd.github+json
X-GitHub-Api-Version: 2026-03-10
mode: cors
credentials: omit
cache: no-store
redirect: error
referrerPolicy: no-referrer
keepalive: false
signal: the current attempt's AbortSignal
----

The application sets no other header. In particular, it sets no
`Authorization`, cookie, request `Content-Type`, cache-control header,
`Origin`, or `User-Agent`. Browser-controlled headers and CORS preflights are
not additional application paths.

There is no application timeout, automatic retry or wait, fallback endpoint or
version, auxiliary rate request, `HEAD`, range request, credential recovery,
persistent cache, backend, proxy, or second retrieval path.

=== Bounded REST body admission

A commit-object status-`200` body has an inclusive `4,194,304`
post-HTTP-content-decoding-byte cap. Streams of `4,194,303` or `4,194,304`
bytes may continue after end-of-stream; observing byte `4,194,305` fails.

A recursive-tree status-`200` body has an inclusive `8,388,608`
post-HTTP-content-decoding-byte cap. Streams of `8,388,607` or `8,388,608`
bytes may continue after end-of-stream; observing byte `8,388,609` fails. This
cap deliberately exceeds GitHub's documented 7 MB recursive-tree maximum while
remaining an explicit compatibility boundary.

For both bodies, count actual `ReadableStream` chunk bytes before fatal UTF-8
decoding and JSON parsing. Do not rely on `Content-Length` and do not use an
unbounded `response.json()`, `response.text()`, `response.arrayBuffer()`,
`blob()`, or equivalent helper. On cap breach, request response-body
cancellation where feasible, settle stream cleanup, start no later request or
stage for the attempt, and publish no admitted set.

=== REST response and envelope contract

For each REST response:

. Require a normal readable CORS response rather than an opaque response.
. Require `Response.url` to equal the exact constructed request URL.
. Classify status before processing a body and require status `200` to proceed.
  Never parse an error body.
. Require the `Content-Type` media-type essence `application/json`, compared
  ASCII case-insensitively, and either no `charset` or one well-formed
  `utf-8` charset value compared ASCII case-insensitively.
. Decode the complete bounded bytes with fatal UTF-8 and parse exactly one JSON
  value.
. Apply the required own-field and schema rules below.

Every required commit or root-tree identity accepts exactly 40 ASCII
hexadecimal characters, normalizes ASCII `A` through `F` to lowercase, and is
compared only in normalized lowercase form. ADR 0005 already supplies the
selected commit in lowercase. The tree request uses only the normalized
lowercase root-tree identity projected from the commit object.

Absent explicit cancellation or replacement, any REST status, cap, body,
media, UTF-8, JSON, root identity or envelope schema, CORS, network, read, or
redirect failure is `Source admission failed` with code `M1-ADM-1`. On any
failure, request response-body cancellation where feasible and start no later
request or stage for that attempt. Detailed
provider, request, rate, reset, repository-state, and body information is not
displayed or persisted.

=== Own-field, primitive projection, and prototype safety

A required JSON field exists only when `Object.hasOwn(value, field)` is true.
Inherited data never satisfies the schema. Read and project named fields one by
one, performing type and value checks only at their specified horizon. Do not
merge, spread, recursively copy, or assign a provider object or any provider
fields into an application control object. Ignore every additive field,
including own fields named `__proto__`, `constructor`, or `prototype`.

Any lookup keyed by an untrusted raw or canonical path uses an array, `Map`, or
an equivalently prototype-free structure, never a prototype-bearing object
dictionary. A projected inventory record contains only the bounded primitive
path/kind evidence and, where permitted below, a primitive candidate-SHA value
or explicit sentinel. It retains no provider object or nested provider value.

=== Commit and tree root schemas

The commit-object JSON root must be a non-null, non-array object. Its own `sha`
must be a full commit identity that normalizes equal to the selected commit.
Its own `tree` must be a non-null, non-array object with an own full `sha`. No
other commit field is needed.

The recursive-tree JSON root must be a non-null, non-array object. Its own full
`sha` must normalize equal to the requested root tree, its own `tree` must be
an array, and its own `truncated` must be boolean. No inherited field satisfies
any requirement. Additive fields are ignored under the projection rule.

=== Inventory completeness and entry horizon

Count recursive-tree array items as opaque records before inspecting fields:

* the `10,001`st item establishes RA-01 without inspecting that item's fields;
* at most `10,000` items with `truncated: false` is a potentially complete
  inventory; and
* at most `10,000` items with `truncated: true` is incomplete inventory and
  `Source admission failed` / `M1-ADM-1`.

There is no non-recursive subtree fallback. Full JSON parsing is permitted only
after the 8 MiB cap has passed. Project no more than `10,001` bounded primitive
records. Before any raw-content request, release application-owned chunks,
decoded text, and raw or nested provider objects. Introduce no hidden lower
repository limit.

=== Path and kind horizons

For each in-horizon item, only own `path`, `mode`, and `type` fields enter the
path and metadata horizons. `path` must be a string representation accepted by
#442. A missing or malformed path is `Source admission failed` /
`M1-ADM-1`.

`mode` and `type` must be strings establishing exactly one closed pair:

[cols="3,3,4",options="header"]
|===
|Mode |Type |Kind
|`040000` |`tree` |Directory
|`100644` or `100755` |`blob` |Regular file
|`120000` |`blob` |Symbolic link
|`160000` |`commit` |Submodule
|===

Missing, malformed, unknown, or contradictory required mode/type evidence is
`Source admission failed` / `M1-ADM-3`. Provider `size` and `url` are ignored.
Apply #442 path validity, segment-wise NFC identity, collision,
submodule-descendant, extension, kind, RA-02, RA-03, and RA-06 rules exactly and
independently of provider order. Retain a valid raw path separately from its
NFC canonical identity.

Do not access, validate, normalize, or compare an item's `sha` during the path
or metadata horizon. Object SHA is essential only for an allowed-extension
candidate outside a submodule boundary whose closed kind is regular file.
Directory, symbolic-link, submodule, submodule-descendant, and
unsupported-extension regular entries ignore `sha` even when it is absent or
malformed. Therefore a collision governs over kind-source failure, and either
governs over RA-06, without SHA inspection.

Only after the complete metadata horizon passes, project each candidate regular
entry's own `sha` field, one field at a time, as either its primitive string
value or an explicit missing/non-string sentinel. Retain no nested value and do
not perform hexadecimal validation or comparison during projection. Release
the provider root before the first raw request.

When a candidate is reached in canonical unsigned-UTF-8 content order, and only
while #442's content horizon remains open, require the projected SHA to be
exactly 40 ASCII hexadecimal characters, normalize it to lowercase, and retain
that normalized expected blob identity for comparison. A missing or malformed
candidate SHA is `Source admission failed` / `M1-ADM-4` in that canonical
content horizon. A SHA attached to an identity outside a closed content horizon
is never validated and establishes no fact. All #442 horizon and precedence
rules remain unchanged.

=== Canonical raw locator

Construct each raw locator only from the validated owner, repository, selected
commit, and retained raw path. Encode every raw path segment independently from
its UTF-8 bytes. Leave only RFC 3986 unreserved ASCII (`A`–`Z`, `a`–`z`,
`0`–`9`, `-`, `.`, `_`, and `~`) literal; encode every other byte as uppercase
`%HH`; and insert only the already-validated `/` separators. Use the raw path
only for the locator and the NFC canonical path only for identity, collision,
and ordering. An invalid Unicode scalar representation fails before URL
construction.

The canonical request form is:

[source,text]
----
https://raw.githubusercontent.com/{owner}/{repository}/{commit}/{encoded-raw-path}
----

No provider-returned `url`, object URL, blob URL, query parameter, media
locator, or redirect target is used.

=== Exact raw request and response contract

Each candidate regular file receives at most one raw GET in its attempt. Raw
GETs are sequential, follow canonical unsigned-UTF-8 identity order, and total
at most `5,000` per journey. The global no-overlap rule below also applies.

Each raw request sets no application header and uses exactly:

[source,text]
----
method: GET
mode: cors
credentials: omit
cache: no-store
redirect: error
referrerPolicy: no-referrer
keepalive: false
signal: the current attempt's AbortSignal
----

Require a normal readable CORS response, status `200`, and `Response.url` equal
to the canonical serialized request URL. Classify status before body
processing, request response-body cancellation where feasible on failure, and
parse no error body. Ignore `Content-Type`, `Content-Length`, ETag, provider
size, media, and binary claims.

Apply RA-04 and RA-05 to actual post-HTTP-content-decoding stream bytes and the
exact #442 content horizon, observing no more than each applicable maximum plus
one byte. Cancel unread suffixes where feasible and never reread a candidate.

Absent explicit cancellation or replacement, a raw
missing/status/CORS/network/redirect/read failure, missing bytes, missing or
malformed expected blob SHA at its open content horizon, unavailable digest
capability, or hash mismatch is `Source admission failed` / `M1-ADM-4`.

=== Exact raw and hash workspace

Use one application-allocated `4,194,317`-byte backing buffer as the sole
current raw/hash workspace across all attempts. Reserve offsets `0` through
`12` for the longest Git blob header and store at most RA-04 content beginning
at fixed offset `13`.

During streaming, application reachability may additionally hold only the one
current browser-delivered stream-chunk reference. Copy only the bytes still in
the open content horizon into the content region; never copy a complete
delivered chunk merely to bound it. Drop that chunk reference after the
bounded copy and before the next read. If a delivered chunk establishes that
byte `4,194,305` exists, count that RA-04+1 byte without storing it, request
cancellation of the unread suffix where feasible, and never invoke the digest
for that candidate.

When end-of-stream establishes complete content of length
`n <= 4,194,304`, write exactly `blob `, the base-10 ASCII spelling of `n`
with no leading zero or separator, and NUL directly into the reserved prefix,
without a separate header-byte buffer. If that header has length `h`, place it
so that it ends at content offset `13`, then pass only the zero-copy view
`[13-h, 13+n)` to native worker Web Crypto `SHA-1`. The hashed preimage is
exactly:

[source,text]
----
SHA-1("blob " + decimal-byte-length + NUL + exact-bytes)
----

No stale reserved byte enters the view. Do not concatenate or allocate a
second whole-content or whole-preimage application buffer. Zero-copy views and
fixed counters allocate no backing store; Web Crypto internal copies are
outside the application-reachability contract.

The application-allocated raw/preimage backing-store peak is exactly
`4,194,317` bytes. No numeric size is promised for a browser-selected delivered
chunk, but only one such reference is reachable and it is gone before hashing.
At digest settlement, the returned 20-byte SHA-1 result may briefly coexist
with the workspace, so that phase's controlled application-reachable
byte-array backing-store peak is exactly `4,194,337` bytes. Web Crypto internal
copies remain outside the contract. Digest never runs on RA-04+1.

=== Reachability transitions and content integrity

The raw-content lifecycle is ordered as follows:

. Streaming holds the one backing buffer plus at most one delivered chunk
  reference.
. Hashing begins only after stream completion and read cleanup and holds the
  buffer plus one zero-copy preimage view.
. After Web Crypto settles, first recheck attempt eligibility, compare the
  lowercase hexadecimal digest output with the normalized expected blob SHA,
  and drop the digest result and hash view.
. Only on agreement, create a zero-copy content-only view and perform #442's
  strict UTF-8 decode.
. After decode returns, recheck eligibility and drop the raw buffer and content
  view before BOM, NUL, and newline normalization. The decoded value may
  coexist with the raw buffer only at decode settlement.
. Normalization retains only the current decoded or normalized value and
  bounded unpublished success output.

A hash mismatch or revoked attempt never decodes. On hash agreement, apply
#442's strict UTF-8, exactly-one-leading-BOM removal, NUL rejection, and newline
normalization exactly once. Git LFS pointer bytes are ordinary Git blob bytes
and are never dereferenced; a CDN transformation or LFS substitution fails the
hash comparison.

This check reproduces Git object identity consistency only. It is not a
collision-resistance, malicious-provider integrity, or broader security
warranty.

=== Failure, publication, and visible information

The only retrieval/admission classifications remain those accepted in #442:

* REST envelope, identity, cap, inventory completeness, path, CORS, network,
  redirect, or root-schema failure uses `Source admission failed` /
  `M1-ADM-1`;
* required closed kind evidence failure uses `Source admission failed` /
  `M1-ADM-3`; and
* candidate-SHA, raw-byte, digest, strict UTF-8, or normalized-content failure
  uses `Source admission failed` / `M1-ADM-4` at its specified horizon.

RA-01 through RA-09 and `ADM-06`/`ADM-07` retain #442's exact horizons and
precedence. The transport caps and incomplete inventory are not RA limits and
create no category or stable code. Add no provider- or retrieval-specific
visible category. Do not display or persist provider bodies, rate/reset/request
details, repository-state detail, raw or normalized source, or admitted
modules.

Every failure publishes no admitted set or downstream result. Cancellation
remains `Cancelled`; replacement publishes no terminal result. All admission
and RA precedence, current-attempt publication eligibility, and post-selection
identity retention remain exactly as #441 and #442 define them.

=== Request count, quota, and no-overlap policy

A complete successful journey makes four REST core GETs including ADR 0005's
two resolution requests, plus no more than `5,000` sequential raw GETs. Four
REST calls imply `15` otherwise-isolated complete attempts under GitHub's
documented anonymous `60/hour` primary limit only arithmetically, not as an
entitlement. REST quota is shared by the originating IP; preflights and other
GitHub use may consume capacity; secondary limits may apply; and raw controls
are undocumented. Any throttle is terminal. There is no automatic retry or
wait.

Across all attempts, not merely within one attempt, at most one
retrieval/admission provider request and one raw/hash workspace may exist at a
time. ADR 0006 commit-object, recursive-tree, and raw Fetches all consume the
single request slot. The exact `4,194,317`-byte workspace consumes the single
workspace slot from allocation through final release. Request-count maxima are
per journey; overlap exclusion is global.

=== Bounded application-owned reachability

Application-owned reachability is bounded to:

* one current capped REST transformation, with raw chunks removed before JSON
  parsing, decoded text removed after parsing, and raw provider-root,
  response, body-reader, and reader references removed after field-by-field
  bounded projection;
* no more than `10,001` projected inventory records, each subject to #442 path
  horizons and containing no nested provider value;
* the one exact raw/hash workspace and transition policy above, with RA-04+1
  counted but not stored or hashed and no duplicate whole-content or preimage
  buffer;
* overflow-safe counters; and
* only success-eligible normalized modules bounded by RA-07 through RA-09.

Tree provider representations are gone before raw retrieval. Each raw, hash,
and decoded temporary is gone before the next request. When success becomes
impossible, remove accumulated unpublished output while performing only the
bounded work still required by #442 precedence. No application reservoir is
unbounded and no private lower product limit is introduced.

=== Cancellation and replacement cleanup

Cancellation or replacement immediately revokes the affected attempt's
publication eligibility. Abort its active Fetch, request active-reader
cancellation where feasible, handle fetch/read/abort/cancel settlement and
rejections, release an acquired reader lock in `finally`, remove
application-owned chunks, decoded text, provider objects,
response/body-reader/reader references, projected inventory, raw/hash/decoded
workspaces, and unpublished modules, and suppress every later request and
stage of that attempt.

Check eligibility immediately after a non-abortable `JSON.parse` returns, after
Web Crypto settles, after strict decode returns, and between bounded
normalization stages. A late old success, failure, digest, decode, or cleanup
outcome is ignored and cannot publish.

Replacement does not relax global overlap. Coalesce submissions received while
old work settles to the latest submission only; no superseded pending
submission starts provider-facing or retrieval/admission work. Start no such
work for the latest replacement—including a commit, tree, or raw request or
raw/hash workspace allocation—until all old read/cancel operations and
rejections have settled, any already-running `JSON.parse` has returned, any
pending Web Crypto digest has settled, the reader lock has been released, and
all application-owned old-attempt state above has been cleaned up. Then only
the still-current latest replacement may proceed.

The UI publication gate remains authoritative. This decision promises no
cancellation or replacement latency, immediate network or computation stop,
JavaScript-engine or browser reference removal, garbage-collection timing,
secure erasure, cleanup latency, or worker security boundary. A stalled old
settlement may delay replacement provider work without restoring old
publication eligibility or creating a timing failure.

=== RA-10 and RA-11 disposition

RA-10 retrieval duration and RA-11 admission duration are explicitly
unnecessary for M1. Neither has a value, unit, timer, clock, category, stable
code, precedence, interval, cutoff, or boundary. The historical `60,000 ms` and
`10,000 ms` proposals are rejected as uncalibrated network- and
device-dependent outcomes. No RA-10/RA-11 T-1/T/T+1 scenario exists.

A stalled request may remain `Loading` until provider or browser failure, user
cancellation, replacement, or reload. Arbitrary elapsed time alone starts no
timer, changes no state, and creates no category or code. Data, request count
and concurrency, and retained application resources remain bounded; M1 makes
no completion-time promise.

== Rationale

A recursive Git tree supplies one bounded, complete-at-the-selected-root kind
and submodule inventory. Sequential immutable-commit raw requests avoid an
archive parser and preserve #442's canonical content horizon. Native Fetch,
`TextDecoder`, and Web Crypto are already available in the accepted secure
worker setting and allow exact redirect, credential, stream, cancellation,
byte, and cleanup controls without a dependency.

Independent Git blob identity comparison detects a transformed raw response or
Git LFS substitution before source decoding. The fixed workspace bounds
application-owned whole-content storage while still admitting RA-04 exactly.
Global serialization minimizes request amplification, memory peak, and
replacement cleanup races.

== Rejected alternatives

* *Tree plus tar/codeload.* It reduces request count, but the observed codeload
  origin is unreadable from the production origin. It also introduces
  decompression, tar/PAX/path parsing, transformed or unsupported content,
  tree/archive reconciliation, and order-independent reservoir risks.
* *REST blob or Contents traversal.* It amplifies shared anonymous `60/hour`
  use, adds JSON/base64 overhead, encounters the Contents `1,000`-entry
  directory ceiling, and complicates kind and submodule compatibility.
* *Archive-only.* It supplies no independent complete Git kind/submodule
  inventory and permits unbounded unsupported-content streaming.
* *Smart HTTP or browser Git.* There is no usable production-origin CORS path
  without a forbidden proxy, and it adds pack, zlib, delta, parser, and
  dependency surface.
* *SDK.* An SDK does not remove custom body caps, quota, canonical ordering,
  integrity, cancellation, cleanup, or horizon requirements and adds an
  unnecessary dependency.
* *Parallel raw requests, retries, or waits.* They increase amplification,
  rate exposure, application memory, cleanup races, and nondeterministic
  failure timing.
* *RA-10/RA-11 timing limits.* The historical values are uncalibrated
  network- and device-dependent failure outcomes rather than supported product
  promises.

== Downside

A conforming successful journey may make up to `5,000` sequential raw requests
and can therefore be slow or throttled. Raw capacity is undocumented. The 8
MiB cap may reject a provider-valid tree response. Point-in-time CORS, API
version, schema, tree-limit, raw-byte, and browser behavior may drift. These
are explicit terminal or stop conditions, not latency, availability,
capacity, security, or compatibility promises.

== Renewal and stop rule

`2026-03-10` is a fixed version, not a floating alias. A newer release causes
no automatic upgrade. #454 must revalidate the mechanism contract before
implementation, and #460 renews final-head hosted REST/raw CORS and provider
behavior.

Stop implementation and reopen https://github.com/FelixGeisler/code-city/issues/449[#449]
on a deprecation or sunset notice or `410`; loss of REST or raw CORS;
loss of immutable-SHA raw behavior or exact-byte/hash agreement; incompatible
pinned API version, tree limit, schema, or media behavior; loss of required
worker Web Crypto; or loss of bounded-resource feasibility. Reopen
https://github.com/FelixGeisler/code-city/issues/446[#446] when direct-browser
topology feasibility is affected.

Do not silently change the mechanism, version, origin, endpoint, header,
redirect policy, request order, count, or concurrency, cap, dependency,
credential model, retry or wait policy, or fallback.
