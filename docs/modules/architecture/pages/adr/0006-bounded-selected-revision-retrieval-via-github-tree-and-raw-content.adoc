= ADR 0006: GitHub gateway and immutable source retrieval

Status:: Accepted

== Context

Code City must retrieve a complete source set for the selected commit without
cloning a repository, executing source, or accepting incomplete provider data.
Provider responses and repository paths are untrusted.

== Decision

=== Provider boundary

The GitHub gateway is the only component that performs provider requests.

* Construct URLs locally from the repository reference, selected commit, and
  independently encoded path segments. Use only `https://api.github.com` and
  `https://raw.githubusercontent.com`; never follow or reuse a provider-returned
  locator.
* Use native Fetch with CORS, omitted credentials, no referrer, no-store cache,
  redirect refusal, the current attempt's abort signal, and the pinned GitHub
  API version where applicable.
* Require the expected final URL and success status before reading a body.
* Read every body incrementally under a finite adapter-owned cap before strict
  UTF-8 or JSON decoding. REST caps are evidence-sized provider safeguards; a
  breach is provider failure, not another product maximum. The raw cap is
  derived so every source that can normalise to the published per-module
  maximum remains admissible.
* From tree JSON, project only path and kind plus the candidate blob identity
  needed by retrieval. Ignore provider size and provider-returned URLs. Provider
  objects never become application control objects; untrusted keys use `Map` or
  another prototype-free representation.

These transport caps are implementation safeguards, not additional repository
limits. Their derivation and boundary tests belong with the gateway.

=== Retrieval

. Read the selected immutable commit and its root tree through GitHub REST.
. Read the recursive tree and reject truncation, malformed evidence, or an
  identity inconsistent with the selected commit.
. Project path and kind, plus blob identity only for candidates; release
  provider JSON; then apply path and metadata admission in canonical order.
  Provider size and provider-returned URLs are ignored.
. Fetch candidate blobs sequentially from locally constructed immutable raw
  URLs.
. At the edge, stream each bounded raw body, verify its expected Git blob
  identity, strictly decode UTF-8, and return source text to application content
  admission.
. Return one complete, canonically ordered admitted set or one failure.

At most one provider request and one raw/hash workspace are active. There is no
automatic retry, alternate archive, Git clone, partial result, or cache
fallback.

== Consequences

Sequential immutable retrieval minimizes concurrent memory and makes ordering,
integrity, cancellation, and failure ownership explicit. It may require
thousands of raw requests. A production-origin capacity spike must exercise a
near-envelope repository before this mechanism is considered dependable at the
published maximum. Unacceptable latency, throttling, or failure frequency
reopens this decision; it must not silently introduce concurrency, retry, a
backend, or a private lower limit.
