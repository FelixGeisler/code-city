= ADR 0004: Framework-free TypeScript shell built with Vite

Status:: Accepted

== Context

The accepted M1 outcome needs one static browser package for the existing
`https://felixgeisler.github.io/code-city/` target. The package must realize
xref:adr/0002-browser-only-runtime-and-github-pages-deployment.adoc[ADR 0002's]
UI/main-context and same-origin processing-worker placement while preserving
xref:adr/0001-core-dependency-boundary.adoc[ADR 0001] and
xref:adr/0003-m1-core-strata-building-blocks-and-conceptual-ports.adoc[ADR 0003].
Without a shell and build decision, the first implementation would have to
select its language, packaging tool, worker output, public base, dependency
policy, and source-mechanism boundaries while creating the walking shell.

This ADR fixes that decision and its constraints. It does not add or exercise
the selected tools. The repository at this ADR's acceptance still contains no
M1 application source, Vite or TypeScript dependency, shell configuration, or
production artifact. https://github.com/FelixGeisler/code-city/issues/452[#452]
owns the first implementation after the M0 gate;
https://github.com/FelixGeisler/code-city/issues/459[#459] owns successful-path
integration through the package; and
https://github.com/FelixGeisler/code-city/issues/460[#460] owns canonical
final-head production evidence after all M1 dependency and build-input changes.

== Decision

=== Selected stack and version policy

* Author M1 application source as framework-free TypeScript with plain HTML,
  standards CSS, and browser ES modules.
* Select exact `vite@8.2.1` for development and build packaging and exact
  `typescript@7.0.2` for static type checking. These are build tools, not
  runtime UI frameworks. When #452 implements this decision, both enter as
  exact direct development dependencies, no floating direct range is
  permitted, and the npm lockfile is committed.
* Retain the repository policy `node >=24 <25`, `npm >=11 <12`, and
  `packageManager: npm@11.6.2`. Reproducibility evidence must use npm `11.6.2`
  and record the exact Node 24 patch, operating system, and architecture.
* Run TypeScript checking as a separate mandatory gate with `strict`, `noEmit`,
  and `isolatedModules`. A successful Vite build does not substitute for type
  checking.
* Exact-pin every future direct dependency. Any direct-dependency addition or
  change, lockfile-closure change, or patch or minor selected-tool upgrade
  requires its owning implementation issue to renew build and worker behavior,
  actual committed dependency-closure and notice metadata, point-in-time
  vulnerability results, integrity metadata, applicable dated package and
  repository observations, and reproducibility evidence after the change.
  #460 renews the complete evidence against its final head after all M1
  dependency and build-input changes.
* A major selected-tool upgrade requires architecture review. No upgrade is
  implicit merely because npm's `latest` distribution tag changes.
* Selecting TypeScript application source and the TypeScript checker does not
  select TypeScript or its compiler API as the parser or analyzer owned by
  https://github.com/FelixGeisler/code-city/issues/450[#450].

=== Production package contract

* Configure the public base as exactly `/code-city/` for
  `https://felixgeisler.github.io/code-city/`.
* Package one statically addressed, same-origin, dedicated processing-worker
  entry using an ES worker build. Its URL is fixed at build time and is never
  derived from user, repository, provider, or runtime-configuration data.
* Emit the worker as a separate, non-inlined static file. Blob-URL and data-URL
  inline-worker fallbacks are prohibited.
* A clean production build emits only the static entry HTML and its required
  JavaScript ES modules or chunks, CSS, separate worker, and other statically
  referenced assets. It emits no TypeScript source, source map, build manifest,
  test or demo fixture, debug bypass, server or SSR output, or unreferenced
  application payload.
* If dependency review identifies a notice file that must accompany
  distribution, implementation stops until its treatment is explicitly
  approved. This ADR makes no legal determination.
* The built entry opens at the accepted URL, every emitted application asset
  resolves beneath `/code-city/`, and the shell creates no more than ADR 0002's
  one processing worker. Worker creation timing and cancellation and lifecycle
  primitives remain deferred.
* Two clean builds from the same commit, lockfile, and recorded environment
  must produce byte-identical artifact trees: the same sorted relative paths
  and identical bytes for every file. File-system timestamps and other
  non-artifact metadata are not compared. Vite supplies no reproducibility
  warranty. #452 must demonstrate the initial property, and #460 must renew it
  against the final head after all M1 dependency and build-input changes;
  neither owner may assume or reuse a stale result.
* Vite development and preview servers are local tools, not production runtime
  nodes.

The dedicated worker remains ADR 0002's execution and lifecycle boundary. This
ADR does not turn it into a security boundary, operating-system-process
guarantee, trust crossing, component count, or package boundary.

=== Source-boundary placement

TypeScript language syntax may be used across the eventual source strata.
Using the language does not create a source-dependency arrow.

Vite configuration and APIs, Vite client integration, HTML and CSS, and
concrete DOM and Worker mechanisms are build or edge/adapter concerns. No
application-core or domain-core source may:

* import or otherwise depend on Vite, a framework, or concrete DOM or Worker
  mechanism modules;
* instantiate or otherwise depend on concrete DOM or Worker mechanism values;
  or
* expose DOM or Worker mechanism types in core-owned contracts.

The shell and UI-worker bridge remain edge/adapters. Application and domain
source continues to obey ADR 0001 and ADR 0003; runtime placement continues to
obey ADR 0002. This ADR chooses no package or source layout and no concrete
source map. #452 must map the smallest walking shell and enforce all accepted
source rules without weakening those boundaries.

=== Exact exclusions

This ADR adds no:

* UI, state-management, or CSS framework;
* router, CSS preprocessor, or CSS-in-JS;
* service worker, PWA, web-app manifest, or additional application context;
* SSR, backend, proxy, relay, serverless runtime, server runtime, or Node or
  browser-polyfill runtime;
* storage, application-managed persistent cache, or runtime configuration;
* secret or secret-bearing environment variable--Vite `VITE_*` values are
  client-visible;
* CDN or other remotely loaded executable dependency; or
* speculative plugin, extension point, compatibility layer, v1 dependency, or
  undeclared limit.

No browser-support promise is created. A later compatibility requirement that
conflicts with ES modules or module workers must reopen ADRs 0002 and 0004
rather than introduce a fallback.

This ADR selects no GitHub endpoint, request, or retrieval mechanism; parser or
analyzer; renderer; test technology; package or source layout; message or port
schema; worker lifecycle or cancellation primitive; Pages source, action,
workflow, or deployment mechanism; application route; product control; or
resource threshold.

== Rationale

Tagged Vite 8.2.1 material documents static packaging for HTML, CSS, npm
dependencies, a repository-path base, and a separately emitted worker without
imposing a runtime UI abstraction. TypeScript supplies strict static checking
while preserving framework independence. This is smaller than creating bespoke
dependency-copying, import-map, or vendoring machinery and leaves
https://github.com/FelixGeisler/code-city/issues/451[#451] free to select only
the visualization technology M1 needs.

== Downside

The exact-pinned toolchain has a nontrivial locked dependency closure and
platform-specific native packages. Vite and TypeScript have separate
transforms, so both build and type-check gates are required. Exact pins require
deliberate evidence-backed upgrades, and reproducibility is an empirical
project obligation rather than a tool warranty.

== Rejected alternatives

* *Native HTML, CSS, and browser-ESM JavaScript with a copy-only build.* This is
  viable for an initial empty shell, but complete M1 parser and renderer npm
  dependencies would require bespoke copying, import maps, or vendoring.
* *Vite with React and ReactDOM `19.2.8`.* This is technically viable, but adds
  React, ReactDOM, scheduler, JSX and lifecycle semantics, and potentially
  another plugin without an accepted UI need. It would prematurely constrain
  #451.

== Stop and reopen rule

Stop implementation, reopen #447, and revise or supersede this ADR if:

. the worker cannot be emitted and opened as a separate same-origin ES module
  beneath `/code-city/`;
. repeated exact-pinned builds do not produce the byte-identical artifact tree
  defined above;
. a selected resolution, retrieval, parser, or renderer mechanism requires
  SSR, a Node runtime or Node or browser polyfills, remotely loaded executable
  code, another runtime context, framework source in core, or another ADR 0004
  exclusion;
. the actual committed dependency closure has unresolved license or notice
  metadata, a known vulnerability, integrity, package or repository-status, or
  other evidence requiring a human policy decision; or
. implementation requires a secret, service worker, storage, undeclared limit,
  compatibility fallback, or other excluded mechanism.

No alternate bundler, inline worker, CDN import, backend, or other workaround
may be introduced silently.
