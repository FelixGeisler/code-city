= Introduction and Goals

Code City turns source facts from one immutable public GitHub revision into an
interactive city. The current implementation is the standalone M5 system
selected by xref:adr/0014-standalone-server-owned-analysis-runtime.adoc[ADR
0014]: one native Node.js HTTP service owns acquisition and analysis, one
worker thread executes each admitted attempt, and a same-origin source-free
browser owns presentation.

The later whole-core target in
xref:adr/0013-ownership-of-source-acquisition-analysis-and-saved-investigations.adoc[ADR 0013]
adds saved investigations and deeper investigation behavior. It does not imply
a public API, authentication, Internet service, private-source support, storage
technology, or deployment topology.

== Architecture goals

[cols="1,3",options="header"]
|===
|Goal |Architectural response

|Reliable source identity
|Select one immutable revision, validate complete source inventory evidence,
and keep stale attempts from publishing.

|Deterministic analysis
|Keep product algorithms in domain/application code, isolate provider and
parser integration at the Node edge, and apply requirement-owned admission and
metric rules.

|Bounded temporary ownership
|Reserve explicit operator-set capacity before work, keep source-result
association in process memory, join workers before release, and discard state
on replacement, control, session loss, or shutdown.

|Safe presentation
|Expose only manifest-public browser bytes and source-free validated results;
keep server, worker, parser, manifest, and source bytes private.

|Verifiable delivery
|Build one manifest-bound standalone artifact, reproduce every recorded byte,
drive its actual server and browser, upload it with exact run identity, and
retain immutable evidence that the separate retirement notice replaced the
former analyzer before Pages deployment capability was removed.
|===
