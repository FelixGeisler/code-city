= Introduction and Goals

Code City turns source facts from one immutable public GitHub revision into an
interactive city. This architecture describes two different states and never
treats one as the other:

* **Current implementation** is the browser-only application evidenced at
  commit `38e620c915866394ca4967f418eec9d3f6ec979b`.
* **Accepted target** is the server-owned analysis and saved-investigation
  boundary in xref:adr/0013-ownership-of-source-acquisition-analysis-and-saved-investigations.adoc[ADR 0013]
  and the xref:requirements:index.adoc[product requirements]. It is not yet
  implemented.

No server platform, API, storage, access mechanism, or target deployment has
been selected. Those are **unresolved design** areas.

== Architecture goals

[cols="1,3",options="header"]
|===
|Goal |Architectural response

|Reliable source identity
|Select one immutable revision, validate complete source inventory evidence,
and keep stale attempts from publishing.

|Deterministic analysis
|Keep product algorithms in the domain, isolate provider and browser details at
the edge, and apply the requirement-owned admission and metric rules.

|Safe presentation
|Treat repository content and worker messages as untrusted until validated,
then publish one aligned, source-free city atomically.

|Understandable evolution
|Describe the running browser system directly and show the accepted target as a
separate responsibility boundary, not as an amendment sequence.

|Verifiable delivery
|Build one reproducible static package and bind publication evidence to that
package and commit.
|===
