= 6. Runtime View

== Import and analysis

[source,text]
----
User -> Viewer -> Server job -> Source adapter -> Snapshot -> Analyzer
                                      |                         |
                                      +---- private staging     v
                                                        validated city model
                                                                |
                                      durable job <---- artifact store
----

The viewer submits a Git source, source upload, or generated model through the
same-origin API. The server validates authorization and the complete request
before creating private staging or a durable job. Source adapters normalize all
transports into the same read-only snapshot. The analyzer emits facts, evaluates
the chosen mapping, lays out the city, validates the result, and atomically
publishes the artifact.

Jobs have bounded progress and safe terminal errors. Cancellation and shutdown
clean owned staging data. A restart recovers durable completed work and marks
interrupted active work explicitly rather than leaving it active forever.
Repository URLs, credentials, source bytes, and raw analyzer diagnostics are not
part of job records.

== Repository history

A history import selects bounded representative commits from one mainline. Each
selected snapshot is analyzed with the same mapping and converted into stable
identity-based deltas. The resulting evolution bundle is digest-bound to its
baseline model.

The browser gives the bundle to a dedicated worker. Every seek reconstructs the
requested frame from the validated baseline, so results do not depend on prior
playback. Request identities and worker termination prevent obsolete seeks from
publishing stale state.

== Viewer interaction and export

The viewer loads only validated model data. Three.js renders bounded building
batches while the hierarchy, findings, queries, source inspection, and
accessibility views provide nonvisual access to the same entities. Optional
expensive workflows are lazy modules or cancellable workers. Unsupported or lost
WebGL leaves project data and nonvisual exports available.

Image export renders the scene independently from page chrome. Print export
passes the active model and printer profile through the shared print planner,
then serializes STL, 3MF, or a multi-plate bundle locally. Both paths validate
resource and output bounds before publishing a download.

== Publication

[source,text]
----
completed import -> sanitize -> validate -> immutable publication version
                                             |              |
                                             v              v
                                         latest link   permanent link
----

Publishing is an explicit declassification operation. The server removes source
provenance and private workflow data, validates the reduced model and evolution
bundle, and writes independent digest-verified bytes. Republishing appends a
version; it never edits an existing version. Public reads require no repository
credential, while publish, republish, and unpublish remain authorized actions.

== Optional retained source and AI guidance

Retained source is private, opt-in, and stored separately from city and evolution
artifacts. A source request must agree with the completed job, model provenance,
building identity, and indexed file digest.

AI guidance is disabled unless an administrator configures a provider. The
browser requests an exact preview first; a short-lived one-use grant authorizes
only that reviewed context. Provider credentials remain server-side, and Code
City does not persist prompts or responses. Deterministic findings continue to
work without AI.
