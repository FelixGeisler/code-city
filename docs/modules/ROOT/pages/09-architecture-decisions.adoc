= 9. Architecture Decisions

Only decisions that constrain future implementation belong here. Exact protocol
fields, UI structure, and numeric limits belong in schemas, code, and tests.

[cols="1,2"]
|===
|Decision |Reason

|TypeScript monorepo with small native helpers
|Share contracts and orchestration while using trusted language tooling behind
bounded process protocols

|Versioned city and evolution contracts
|Decouple acquisition and analysis from browser, publication, and export

|Static analysis only
|Treat repositories as untrusted data and avoid executing project behavior

|Transport-independent snapshots
|Make folders, ZIPs, hosted providers, and generic Git converge before analysis

|Deterministic layout and serialization
|Support reproducible comparison, caching, history, and physical output

|Durable filesystem jobs before external infrastructure
|Provide restart recovery and modest self-hosting without requiring a database or
message broker

|Same-origin viewer and API
|Keep browser authorization, artifact access, and deployment policy in one clear
boundary

|Explicit credential profiles and outbound policy
|Prevent speculative credential use and separate caller, destination, and
repository authorization

|WebGL 2 with accessible failure
|Use the maintained Three.js baseline while preserving nonvisual capabilities

|Workers are isolation, not trust authorities
|Keep expensive work cancellable and responsive while validating every result
before use

|Printer-profile-driven planning
|Keep semantic roles independent of any particular printer or tool count

|Immutable sanitized publication
|Make sharing deliberate, versioned, revocable, and independent of private import
storage

|Declarative extensions only
|Permit portable customization without creating an executable plug-in boundary

|Single release container
|Keep the supported deployment understandable and portable across AMD64 and ARM64
|===
