= 9. Architecture Decisions

[cols="1,2"]
|===
|Decision |Rationale

|TypeScript monorepo
|Share model and logic across CLI, web, and workers

|Versioned city model
|Decouple analysis from rendering and printing

|Versioned metric mapping
|Keep independent geometry and color choices deterministic, inspectable, and
portable between browser, history, and print

|Static analysis only
|Make untrusted repositories safe by default

|Native language front ends
|Use bounded native Roslyn and TypeScript 7 APIs behind one fact schema

|Dependency overlay
|Use surface-connected endpoints; show directed, bundled routes on demand

|Shared dependency grammar v1
|Share aggregation and placement; use browser arcs and printable raised traces

|External dependency nodes
|Use fixed black boxes without code metrics; cap excess targets as `Others`

|Bounded labels
|Show full browser details, but print stable short codes with a private legend

|Semantic camera bounds
|Make camera presets and image framing independent of transient render objects

|Direct scene PNG export
|Render at an independently bounded GPU resolution and compose only requested
scene annotations, never DOM chrome

|Local directory as canonical input
|Keep offline and remote paths identical after materialization

|Multi-part 3MF
|Preserve aligned parts and their semantic material roles

|Capability-driven printer profiles
|Support arbitrary printer configurations without tool-count assumptions

|Antora with arc42
|Keep architecture concise, structured, and publishable
|===

== CityModel 1.0 compatibility

Readers accept additive optional fields in schema `1.0` and reject unknown
incompatible versions. Legacy dependencies infer `internal` from `targetId`
and `external` from `externalTarget`; explicit `unresolved` edges retain their
`externalTarget`. Dependencies point from consumer to provider. Formula IDs,
normalization caps, normalized values, and clamped or unavailable states remain
part of the model.

The exact original fixed metric mapping remains valid. Readers do not broaden
its formula IDs or caps; a different mapping must use mapping-definition
version `1.0`. New analysis writes the complete built-in Complexity definition
instead of relying on an implicit default. Thus an old model renders as before,
while new and custom mappings are self-describing.

== Mapping and history

Metric mapping consumes analyzer facts and produces geometry, semantic groups,
and provenance before layout. The viewer and print planner consume that same
derived model. They do not maintain independent formula or palette
implementations.

A history analysis resolves one complete mapping before sampling commits and
uses it for every frame. The canonical mapping contributes to the
metric-configuration fingerprint. The legacy history token
`metricMapping: "default-v1"` resolves only to the exact fixed mapping; direct
and wrapped versioned definitions are accepted, and other claims fail closed.
Browser previews do not rewrite immutable history provenance.

== Dependency and label grammar v1

The semantic edge is independent of presentation. Browser routes use elevated
curves joined to explicit surface contacts. Print routes use profile-safe raised
traces on the connected base. Both consume the same deterministic aggregation,
external-node placement, direction, capping, and omission report.

External boxes are infrastructure, not source buildings: fixed geometry, fixed
semantic color, reference counts only. Screen labels are pooled and bounded.
Print uses same-channel codes and a separate repository-relative legend. No
dependency geometry is allowed to make an otherwise disconnected base printable.
