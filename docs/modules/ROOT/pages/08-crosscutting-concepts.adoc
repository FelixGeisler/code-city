= 8. Cross-cutting Concepts

== Metric mapping

Repository = borough; build module = district; source file = building. A
solution is a filter over modules, not a duplicated physical hierarchy.

`SLOC` counts lines containing a non-comment syntax token. An executable unit is
a method, constructor, accessor, local function, lambda, or top-level block.
Nested units are measured separately.

`CC(unit) = 1 + decisions`. Count `if`; `for`, `foreach`, `for...in`,
`for...of`, `while`, and `do`; `catch`; `?:`; each non-default switch arm; and
each `&&`, `||`, or `??`. TypeScript also counts `&&=`, `||=`, and `??=`; C#
counts `??=`, `when` guards, and `and`/`or` patterns.
Do not count `else`, `default`, `return`, `throw`, `await`, or optional chaining.

[source,text]
----
decision_load = sum(CC(unit) - 1)
sloc_n = clamp(ln(1 + SLOC) / ln(1001), 0, 1)
cc_n   = clamp(ln(1 + decision_load) / ln(101), 0, 1)
footprint_side = 3 + 15 * sloc_n^1.5
footprint_area = footprint_side^2
height = 4 + 36 * cc_n
----

The inspector exposes the metric method, raw per-unit CC, SLOC, decision load,
and maximum CC. Building color uses the worst unit: 0-5, 6-10, 11-20, or above
20.

== Dependency routes

`A -> B` means consumer A depends on provider B. TypeScript imports connect
buildings; project and package references connect modules. Repeated references
collapse into one weighted edge and self-edges are omitted.

Every rendered endpoint has a surface contact and a route anchor. A building
uses its roof center for both. A district contact is the intersection of its X/Z
rectangle with the center-to-counterpart ray, on the district top; coincident
centers use -Z. `skylineY` is the maximum top Y of the district base and its
visible buildings. The anchor keeps X/Z and uses `skylineY + 0.35`. An
isolation contact uses key `kind + NUL + stable endpoint ID`: `building` plus
building ID, `district` plus district ID, or `external` plus normalized target.
The overflow endpoint uses key `"external-overflow" + NUL + "v1"`.
Hash UTF-16 code units in order, starting at `0x811c9dc5`; for each unit use
`hash = imul(hash xor unit, 0x01000193) unsigned`. `hash mod 4` selects `-Z`,
`+X`, `+Z`, or `-X`;
`0.08 + hash(key + NUL + "position") / 0xffffffff * 0.84` maps along that edge
on the visible district top. Its anchor also uses `skylineY + 0.35`. An external
node uses its roof center for both. A vertical gateway joins each distinct
contact/anchor pair. Browser curves join anchors; no marker may float.
Arrowheads always point to the provider.

The hidden-by-default overview bundles edges by visible district. Selection
expands incoming and outgoing file routes. Both views rank by weight with stable
identity tie-breaking and report omissions. The overview shows at most 24
bundles; selection shows at most 20 routes per direction. Isolation projects
hidden endpoints to grounded boundary gateways.

== External dependencies

Normalize targets with Unicode NFC and surrounding-whitespace removal; remaining
characters, including case, stay significant. Aggregate reference weight by
normalized target. Show at most 12 nodes. With more than 12 targets, show the
strongest 11 by descending weight, then normalized target in ordinal UTF-16
code-unit order, plus an overflow node; report its target count and weight. The
overflow node has internal kind `external-overflow` and display label `Others`.
It cannot collide with a real target named `Others`.

An external node is a fixed `4 x 3 x 2` city-unit box in X/Y/Z, uses semantic
role `external` and color `#111827`, and has no SLOC or complexity. Place nodes
by normalized target in ordinal UTF-16 order, with `external-overflow` last, on
a connected rear apron:

[source,text]
----
margin = gap = 1
apron_width = max(base_width, box_width + 2 * margin)
apron_min_x = base_center_x - apron_width / 2
columns = max(1, floor((apron_width - 2 * margin + gap)
                       / (box_width + gap)))
column = index mod columns
row = floor(index / columns)
x = apron_min_x + margin + box_width / 2 + column * (box_width + gap)
z = old_base_max_z + margin + box_depth / 2 + row * (box_depth + gap)
----

Rows fill in order. The base widens symmetrically only when `apron_width`
requires it, then extends through the last row plus the rear margin. Each box
sits on the new base top. The +Z apron stays separate from the -Z identity
panel. Viewer and exporter share these exact coordinates.

== Scene labels

The scene owns at most two reusable camera-facing labels: transient hover and
persistent selection. If both reference one entity, render one label. A building
label shows its full filename; its selection details show the full normalized
repository-relative path. District labels show the full district name. External
labels show the full target, while overflow details list its count and weight.

Labels never intercept raycasting or affect scene bounds. Reload and clear reuse
or dispose the two textures; no building, district, or external node owns a
texture. Pointer, keyboard, search, and dependency-list selection use the same
details content.

== Repository exploration

Search matches normalized repository-relative building paths in the loaded
model; it never reads source text or uses the network. Camera focus does not
mutate the model. District isolation is a reversible visibility filter and
keeps the shared base and identity context visible.

== Determinism

Sort inputs, use stable path IDs, and persist formulas and normalization caps.
Pack up to 64 variable footprints with deterministic corner filling; larger
sets use bounded shelves. Configured gaps remain visible streets.

== Privacy

Do not persist source text, absolute roots, credential URLs, or adapter error
details. Default discovery hard-skips `.git`, `.angular`, `node_modules`, `bin`,
`obj`, `dist`, `build`, and `coverage` segments plus generated C# suffixes.
Nested `.gitignore` rules apply; root `.codecityignore` may override them but
cannot override hard skips.

== Threat model

Repository bytes, city models, printer profiles, URLs, logos, and worker
messages are untrusted. Protected assets are source, credentials, host paths,
local files, browser origin data, memory, CPU, and output files.

Repository content is data only. Code City does not run hooks, filters,
scripts, builds, restores, generators, analyzers, or repository plugins.
Snapshots never follow symlinks and admit only analyzer inputs. One analysis
allows 100,000 visited entries, 50,000 retained files, 25,000 source buildings,
2 MiB per file, 256 MiB total, 1,000 diagnostics plus one omission summary, and
300 seconds for snapshot plus analysis.

The self-hosted import endpoint accepts only strict, duplicate-free JSON with
exact object keys. It requires `X-Code-City-Request: 1`, rejects encoded
bodies, caps the body at 32 KiB and five seconds, and closes early rejections
instead of retaining a slow body on a keep-alive connection. Inputs are
validated before private staging or job persistence. Jobs retain fixed progress,
fixed safe error codes, and owned artifact URLs only.

Inbound authorization is an explicit deployment boundary, not an inference
from network location or forwarded identity headers. Without a token file, the
existing trusted-network API remains open. With one, every API operation except
health reads and session bootstrap requires either the fixed-entropy root
bearer or an opaque server-side session. Authorization runs before protected
route body handling, so an unauthenticated slow or unexpected body is closed
without staging, queueing, or endpoint discovery.

The root token is loaded once from a stable, bounded, private regular file
before data-directory mutation. It is never accepted through an environment
value, URL, JSON body, cookie, job, or artifact. POSIX ownership and mode are
verified; Windows requires an explicit ACL-and-ancestry trust attestation.
Presented bearer values are decoded into a fixed 32-byte buffer and compared
in constant time. Failure responses do not distinguish missing, malformed,
duplicate, expired, or incorrect credentials. Shutdown overwrites the loaded
key and clears all in-memory session digests.

Browser storage contains only an opaque, random, bounded-lifetime `HttpOnly`
session capability, never the root token or repository credential. The cookie
uses `SameSite=Strict`, API-only path scope, and `Secure` on every non-loopback
deployment. Existing non-simple mutation headers remain mandatory, including
job cancellation; cookie mutations additionally require the exact configured
same-origin Origin. CORS remains disabled. Health is deliberately anonymous,
cache-free, and contains no authorization or credential-profile state.

Credential profiles form a separate, bounded startup registry. Enabling the
manifest without application-owned inbound authorization fails before the
manifest path is accessed. Exact-shape, duplicate-free JSON binds a stable ID
and display label to one provider, exact repository scopes, and a direct-child
secret basename. Protected directory, canonical path, stable file identity,
ownership/mode or explicit Windows ACL-attestation, link-count, UTF-8,
single-line, count, and byte limits all fail closed. Secret buffers are
overwritten after validation.

The import capability response is an authenticated, no-store redacted
projection, not a credential oracle: only ID, label, and provider cross the
boundary. Scope URLs, usernames, filenames, and secret bytes do not. The
current slice intentionally stops before credential selection and Git
injection, so strict import JSON continues to reject `credentialProfileId`.

Raw uploads avoid multipart parsing and never trust a filename. Exact-shape
metadata reserves one opaque UUID and its declared bytes before the server
creates a private staging directory. The PUT admits exactly one unencoded
`application/json` or `application/zip` body with one matching
`Content-Length`; transfer encoding, concurrent reuse, underflow, overflow,
idle senders, and expired reservations fail closed. Four reservations and
256 MiB of reserved/staged bytes are global hard limits, and quota remains
charged while the upload is queued or running.

The staged body is written once to fixed `upload.bin` with create-exclusive
and, where the platform exposes it, no-follow semantics, owner-only
permissions, portable handle identity checks, payload and directory flushes,
and a second fixed-path identity check. Cleanup waits
until an active writer closes its handle, is idempotent across finalizer and
rollback, and retains quota until removal succeeds. Startup removes abandoned
UUID staging directories. ZIPs are inspected in memory and never extracted:
portable paths, case/Unicode collisions, symlink or file descendants,
compression metadata, CRCs, entry count, compressed, expanded, per-entry, and
analysis deadlines remain bounded. Uploaded city models require fatal UTF-8
and the established runtime validator, then are reserialized through the
artifact store rather than publishing attacker-supplied bytes.

Windows/IIS must place `CODECITY_DATA_DIR`, uploads, and artifacts behind a
service-private ACL even if Generic Git is disabled. Inherited child ACLs must
exclude untrusted identities, and the protected directory entry and canonical
ancestors must prevent untrusted rename, delete, and delete-child access.
Portable Node APIs enforce fixed-path and open-handle identity but cannot prove
or establish those ACL properties.

Generic Git is default-denied at the server boundary. An exact
operator-configured scheme, normalized hostname/IP, and effective port must
match before staging. This origin list is egress control, not per-repository
authorization. In default trusted-network mode every client can invoke the
least-privileged service identity's ambient Git/SSH credentials for any
repository/user at an enabled origin. Enabling inbound authorization gates API
access but does not narrow that service identity's repository scope. Windows
additionally requires an explicit attestation that the data/import ACLs,
inherited child ACLs, and protected canonical ancestry satisfy the
private-workspace contract.

The GitHub adapter accepts only canonical HTTPS `github.com/owner/repository`
URLs. It performs anonymous, no-store requests to `api.github.com`, resolves an
exact 40-digit commit, and fetches only that commit from `codeload.github.com`.
Redirects, credentials, encrypted or ZIP64 archives, unsafe or colliding paths,
and inconsistent ZIP metadata are rejected. API responses are capped at 1 MiB,
archives at 64 MiB, individual ZIP entries at 256 MiB, expanded archive data at
1 GiB, and refs at 256 UTF-8 bytes. All remote work shares the 300-second
default analysis deadline. Ignored content is never inflated. Archives and
source bytes are not persisted or cached.

The generic Git adapter accepts validated HTTPS, `ssh://`, and scp-style
remotes without embedded passwords, query data, fragments, or leading options.
The installed Git client and the user's credential helper, SSH agent/config,
and certificate configuration are trusted local dependencies. Code City
disables prompts, tracing, redirects, unsafe protocols, hooks, filesystem
monitors, maintenance, submodules, and LFS behavior for the operation.

Only an advertised branch, tag, or default `HEAD` is shallow-fetched into a
private bare repository. The advertised object is rechecked before a local
`git archive`; no checkout or remote archive command occurs. Process duration
and output, temporary object storage, archive bytes, and the shared snapshot
limits are bounded. Errors omit Git diagnostics, remotes, refs, credentials,
and temporary paths. The bare repository is removed before source analysis;
no remote or derived-model cache remains.

The temporary parent is part of the Generic Git trust boundary. Parent,
workspace, and canonical-ancestor identities are captured with device/inode
metadata and revalidated around path resolution, measurement, Git use, and
cleanup. POSIX roots are process-owned mode `0700`; ancestors must be owned by
root or the process identity and prevent untrusted entry replacement through
permissions or valid sticky-directory semantics. Zero filesystem identities
fail closed.

Portable Node APIs cannot prove Windows ACL inheritance or directory
delete-child rights. Windows therefore has no implicit Generic Git temporary
parent. `--trusted-workspace-parent` attests that the existing parent's ACL,
and inherited child ACLs prevent untrusted content reads, writes, and creation.
It separately attests that the containing directory and canonical ancestor
entries prevent untrusted rename, delete, and delete-child operations on the
protected path entries; ancestors may otherwise permit read or traversal.
Cleanup atomically moves only the captured workspace identity to a private
quarantine name before recursive removal; mismatched replacements are
preserved, and interrupted removal retries the same captured quarantine.

The bundled Roslyn helper parses syntax only, receives opaque source IDs over a
versioned bounded protocol, and runs once per analysis. It never loads a
solution, project, MSBuild, NuGet, generators, or repository analyzers.

`codecity open` binds only to `127.0.0.1`, validates the exact Host header, and
serves a startup-captured viewer allowlist plus one no-store in-memory model.

CLI input is capped at 128 MiB per city model and 1 MiB per printer profile.
Derived JSON is staged with mode `0600`, atomically renamed, and rolled back on
failure. The viewer uses one explicit-load gateway: 128 MiB model, 1 MiB local
profile, 2 MiB logo, and 30 seconds. It rejects redirects and credentialed URLs,
sends no credentials or referrer, and exposes fetched images only through local
Blob URLs. CSP restricts assets to the application and Blob images; executable
checks permit network primitives only in the explicit gateway and prohibit
bundled telemetry, CDN, upload, frame, or object paths. Print workers have a
60-second watchdog and are terminated on every exit.

Residual risks are platform filesystem races that cannot be removed by portable
Node APIs, browser/DNS behavior below the fetch boundary, and slicer behavior.

== Physical identity

The model may carry an explicit title, version, and relative SVG/PNG logo
reference. Layout reserves a compact plaque joined to the center of the front
edge; the viewer previews it, and the print plan preserves its content and
channel assignment.

The exporter supports the Demo's title, version, printable Code City icon, and
the shared block font below. Arbitrary fonts and logos remain separate work. A
multi-repository city has one main panel. Local paths are never inferred as
printed identity.

Printed building labels use `000` through `ZZZ`. Sort ordinally by repository
ID, district ID, normalized path, and building ID; encode the zero-based index
as three-character uppercase base 36. This covers the 25,000-building model
limit. `auto` adds same-channel raised roof glyphs only when they fit; `off`
omits physical labels. Districts use fitting uppercase text or `D` plus the
three-character index from the equivalent repository ID, path, and district ID
sort. A deterministic companion JSON legend records code, repository ID and
name, district ID and name, building name, repository-relative path, and printed
status/reason. Absolute paths, source text, and legend data never enter 3MF.

Binary STL uses the same validated geometry in stable part order. It combines
all channel parts as one multi-shell mesh with outward unit normals. STL does
not preserve colors, tool assignments, or 3MF metadata; preflight reports this
loss before export. Serialization is capped at 500,000 vertices and triangles
(25,000,084 output bytes).

== Print planning

The city model retains semantic groups without a hardware limit. A printer
profile declares build volume, geometry limits, output formats, configured
print channels, their assignment mechanism, and an overflow policy.
Build volume uses city axes: X width, Y height, Z depth. Export maps city
X/Y/Z to printer X/Z/Y.

Geometry limits resolve legacy four-field profiles into explicit nozzle and
line-width assumptions, symmetric X/Y/Z build margins, wall and gap minima,
raised and recessed feature minima, label and route widths, base thickness,
and maximum model height. Omitted fields use documented conservative defaults;
parsed and bundled profiles expose the resolved values.

[cols="2,3",options="header"]
|===
|Omitted field |Resolved value

|`nozzleDiameter`, `lineWidth`
|`minimumWallThickness`

|`buildMargins`
|`{x: 0, y: 0, z: 0}`

|raised or recessed minimum
|`minimumFeatureSize`

|label stroke
|`minimumWallThickness`

|route width
|maximum of feature size and line width

|maximum model height
|build-volume Y minus twice the Y margin
|===

Line width must be from one through two nozzle diameters. Wall, label and route
widths must be at least one line. Twice each margin must leave a positive build
span; base plus raised-feature height must fit the declared maximum height.

The print planner maps semantic groups onto one or more channels. If groups
outnumber channels, it deterministically merges them, produces monochrome
output, or fails, as selected by the profile. Exporters measure transformed
geometry against profile limits and contain no printer-specific tool count.

Printable dependencies are optional and aggregate district/module relations;
file edges are never printed. V1 uses base-connected raised traces in available
street lanes, capped like the overview. Let `feature` be the larger profile
minimum feature size and minimum wall thickness. Trace height is `feature`;
width is `feature` times
`min(3, max(1, 1 + floor(log2(max(weight, 1)))))`; a same-height arrowhead marks
the provider. Unroutable or capped bundles are omitted with reported count and
weight. Traces do not provide structural connectivity for the base. Detachable
connectors remain calibration artifacts: the generated comparison selects the
integrated raised trace because it needs neither clearance nor loose hardware.

The CLI defaults to `--routes off`; `--routes auto` enables this deterministic
geometry without mutating the city model.

The viewer calls the same format-neutral export orchestration in a module
worker. It terminates the worker on cancellation, transfers exact bytes, and
publishes only local Blob downloads.

Multi-plate layout is deterministic and printer-neutral. `scale` keeps one
plate and stops at the profile-safe feature scale; `tile` keeps the requested
scale and packs complete districts with optional 90-degree rotation. Every
plate has one compact continuous base and a plate number. Plate 1 also carries
the identity plaque. A relevant external target is one fixed-size box on each
affected plate, marked as original once and replica thereafter. Cross-plate
routes are not printed; the bundle manifest records consumer, provider, and
their plate numbers. No artifact may exceed the usable profile volume.

The Prusa XL one-, two-, and five-tool configurations are profiles of the same
model.

The deterministic calibration plate contains a shared base, one marker per
configured channel, and measured coupons for every resolved feature limit.
Its JSON manifest maps coupon IDs and print-space bounds to each measurement.
Profile axes are X width, Y height, Z depth; print axes are x=X, y=Z, z=Y.
Measure wall, gap, raised and recessed references after slicing and printing;
adjust the profile before exporting a full city.
