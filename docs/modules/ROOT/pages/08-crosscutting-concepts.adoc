= 8. Cross-cutting Concepts

== Explainable design-smell overlay

The viewer evaluates the versioned `codecity.design-smells/1` protocol and
rule catalog `1.1.0` in a cancellable worker. Findings are heuristic signals,
never AI advice or quality verdicts: each is linked to its named rule, rule
version, exact language-specific threshold, concrete measured evidence, and
(when available) source line. Available rules cover high-complexity methods,
oversized source files, attributable JavaScript/TypeScript coupling, and
source-file dependency cycles. Per-class size, C# building-level dependencies,
duplicate code, and feature envy remain explicitly unavailable until the
CityModel contains facts that support those claims.

**Analyze** opens on the Design smells panel, before expert configuration.
It provides total and affected-building counts, a 100-row paginated result
window, keyboard-accessible navigation to the affected building, and
text/symbol/shape/severity cues in addition to color. Rule help, filters, and
unavailable-capability explanations remain reachable in a collapsed
**Rules and filters** disclosure so findings stay first. The 3D markers use at most four instanced batches and obey district
isolation. A local, project-scoped browser store records false-positive
suppressions without changing source code or the imported CityModel. Persisted
data and worker messages use strict exact-key validation and bounded sizes;
evaluation caps imported buildings, findings, and suppressions to keep
large-city behavior predictable.

== Optional AI guidance

AI guidance is disabled unless an administrator supplies a version-1
`CODECITY_AI_GUIDANCE_CONFIG` JSON value. It is a server-side adapter: browser
responses expose only a provider ID and label, never an endpoint, credential,
or authorization header. Provider credentials are referenced by an environment
variable name, so the configuration JSON never contains a secret.

[source,json]
----
{"version":1,"enabled":true,"providers":[
  {"id":"local","label":"Local model","endpoint":"http://127.0.0.1:11434/guidance"},
  {"id":"review","label":"Review service","endpoint":"https://ai.example.com/guidance","authorizationEnv":"CODECITY_AI_REVIEW_TOKEN"}
]}
----

The viewer lists the configured providers and the user selects one before a
preview is issued. Remote endpoints must use HTTPS; HTTP is allowed only for
literal `localhost` or an IPv4/IPv6 loopback endpoint. Remote DNS answers are
validated and the selected safe address is pinned for the request; private,
link-local, loopback, mapped-IPv6, and special addresses are rejected. Endpoint
URLs cannot contain credentials, queries, or fragments, redirects are refused,
and only `Authorization`, `api-key`, or `x-api-key` credentials are accepted.
At most 64 providers may be configured.
Each call has a bounded timeout, source and streamed-response size limits,
cancellation on browser disconnect, and a strict provider response contract.

For a selected retained file, type, callable, dependency, or design-smell
finding, the browser posts only a versioned descriptor containing stable IDs.
It never supplies source, ranges, metrics, or evidence. The server validates the
descriptor against the retained city model, re-evaluates smell findings, slices
the recorded exact source range, and derives the transmitted metrics. Declaration
columns count UTF-16 code units, and both endpoints are inclusive, including on
the final line of a multi-line declaration. A valid dependency or finding
without an analyzer-recorded exact range produces an
explicit unavailable preview and no grant; Code City never substitutes guessed
source.
Dependency routes expose this check through **Preview AI guidance**; incoming
routes first bind the context to their actual source building rather than the
currently selected target building.

The server issues a short-lived, opaque, session-bound grant bound to the
provider, import, selected descriptor, exact source, metrics, context digest,
and (for smells) finding digest. Clicking **Send this exact preview once**
consumes that grant atomically; the browser sends neither source nor metrics.
The one-time browser request deadline is the strictly validated provider timeout
plus a fixed ten-second server-preparation and response allowance; even its
70-second maximum remains
below the two-minute grant lifetime. An explicit browser cancellation always
wins immediately.
The provider request includes the selected provider ID, and the provider must
echo that ID together with the context and finding digests. Both server and
viewer reject stale, cross-provider, or otherwise mismatched output.
Suggestions are labelled as optional and cite the selected source line range.
Provider failures leave deterministic findings and source navigation available.

Declaration-level source navigation prepares a preview for the selected type or
callable descriptor. The approval shows and sends only that exact declaration
range; changing the declaration or provider invalidates the displayed grant and
requires a new preview.

Preview creation is an origin-protected `POST`, not a cacheable read. In
trusted-network deployments the server creates a short-lived, `HttpOnly`,
`SameSite=Strict` approval cookie so users remain distinct even when IIS, Azure,
or another reverse proxy presents one shared network address. Forwarded address
headers are not trusted for approval identity. A failed or indeterminate request
invalidates the displayed grant and requires a fresh preview and confirmation.
Guidance operations are coordinated per retained import: deleting that same
import aborts and waits for its active provider call, while reads, guidance, and
deletion for other imports remain independent.

Prompts and model output are not stored. Set `CODECITY_AI_GUIDANCE_AUDIT=stderr`
to enable the built-in administrator audit sink; it emits only provider ID,
selected building ID, byte count, duration, and completed/cancelled/failed
outcome. Audit-sink failures never change a guidance result. Do not put
credentials in URLs, browser configuration, logs, or repository files.

== Metric mapping

Repository = borough; build module = district; source file = building. A
solution is a filter over modules, not a duplicated physical hierarchy.

A metric mapping is data, not viewer-only styling. Mapping definition `1.0`
has a stable ID and name, `built-in` or `custom` provenance with a description,
and independent `footprint`, `height`, and `color` channels. The complete
definition travels with the resulting city model. A preset name alone is not
enough to reproduce a city.

[cols="1,2,2"]
|===
|Channel |Definition |Result

|Footprint
|Metric, formula, normalization, cap, missing-value policy, minimum and maximum
side, and exponent
|Building X/Z size and therefore district packing

|Height
|Metric, formula, normalization, cap, missing-value policy, minimum and maximum
height, and exponent
|Building Y size

|Color
|Metric, formula, normalization, cap, missing-value policy, and an ordered
labelled color scale
|Stable semantic color group shared by browser and print
|===

The supported building metrics are `sloc`, `decisionLoad`,
`maximumComplexity`, and `executableUnitCount`. Geometry and color may select
the same metric or three different metrics. The formula ID is
`metric-value-v1`. Normalization is either `linear-cap-v1` or
`log1p-cap-v1`, always with an explicit positive cap. Missing values either
become zero or fail evaluation according to the recorded `zero` or `error`
policy. Values above a cap are clamped and remain identifiable as clamped in
the legend and inspector.

[source,text]
----
linear_n = clamp(value / cap, 0, 1)
log_n = clamp(ln(1 + value) / ln(1 + cap), 0, 1)
footprint_side = minimum_side
                 + (maximum_side - minimum_side) * normalized^exponent
height = minimum_height
         + (maximum_height - minimum_height) * normalized^exponent
----

Color chooses the first palette entry whose `maximum` contains the normalized
value. Palette maxima are strictly increasing and the final entry ends at
`1`; every entry records a stable ID, label, and color. The inspector and
legend expose the selected metric, raw and normalized values, availability or
clamping state, formula and normalization IDs, cap, missing-value behavior,
geometry range or color scale, and mapping provenance.

`SLOC` counts lines containing a non-comment syntax token. An executable unit is
a method, constructor, accessor, local function, lambda, or top-level block.
Nested units are measured separately.

`CC(unit) = 1 + decisions`. Count `if`; `for`, `foreach`, `for...in`,
`for...of`, `while`, and `do`; `catch`; `?:`; each non-default switch arm; and
each `&&`, `||`, or `??`. TypeScript also counts `&&=`, `||=`, and `??=`; C#
counts `??=`, `when` guards, and `and`/`or` patterns.
Do not count `else`, `default`, `return`, `throw`, `await`, or optional chaining.
`decisionLoad` is `sum(CC(unit) - 1)`; `maximumComplexity` is the greatest
recorded unit CC.

Analyzer-produced executable units may add the backwards-compatible
`codecity.complexity-evidence/1` object. It owns a stable unit identity and,
for declared callables, references the matching
`codecity.source-structure/1` callable identity. Each retained site records
the contributing construct, contribution, and exact inclusive one-based
line/UTF-16-column range of its keyword or operator token. Sites are persisted
in strict source order and do not overlap, so source navigation and a bounded
AI preview can select the recorded token without rediscovering syntax.

`complete` evidence satisfies
`CC(unit) = 1 + totalContribution`, with the retained contributions summing to
the total. `truncated` evidence preserves the same aggregate invariant and
records a positive `omittedContribution`; retained plus omitted contributions
must equal the total. `unavailable` evidence has no sites or contribution
total and carries a reason, so consumers must not reconstruct sites from the
aggregate. An absent evidence object is the readable legacy aggregate-only
case. The TypeScript compiler front end emits evidence for TypeScript and
JavaScript, and the Roslyn helper emits it for C#. The
`csharp-lexical-v1` fallback explicitly reports evidence as unavailable because
it cannot prove stable callable ownership and exact syntax attribution.

Retention is bounded to 256 sites per unit, 4,096 per file, and 250,000 per
model. Serialized evidence is additionally limited to 96 KiB per unit, 2 MiB
per file, and 64 MiB per model. Limits retain the earliest deterministic sites
and mark the affected unit `truncated`; they never silently drop evidence.

=== Curated presets

The preset catalog is versioned and distinguishes an unavailable design from
an invalid definition. Unavailable entries remain visible with a reason; they
cannot be previewed or applied.

[cols="1,1,3"]
|===
|Preset |Status |Meaning

|Complexity
|Available
|Uses the current size and complexity facts; it is the default for newly
analyzed models.

|Maintenance
|Available
|Emphasizes the recorded size, executable-unit, and complexity facts that are
available in a snapshot.

|Print
|Available
|Uses deterministic, discrete print-friendly color groups while retaining the
same geometry contract.

|Dependencies
|Unavailable
|The dependency graph exists, but a reproducible per-building dependency metric
has not yet been added to analyzer facts.

|Ownership
|Unavailable
|No per-building ownership metric is recorded; history author data is
deliberately omitted.

|Evolution
|Unavailable
|History does not yet expose a per-building churn or age metric to the mapping
evaluator.
|===

Custom definitions use the same validator and evaluator as curated presets.
The same model and canonical definition therefore produce the same semantic
groups, geometry, layout, and legend independent of input order.

=== Legacy mapping

CityModel `1.0` readers continue to accept the exact original fixed mapping.
It uses `log1p-cap-v1`, SLOC cap `1000`, decision-load cap `100`,
`sloc-footprint-side-v1`, `decision-load-height-v1`, and
`maximum-complexity-bands-v1`:

[source,text]
----
sloc_n = clamp(ln(1 + SLOC) / ln(1001), 0, 1)
cc_n   = clamp(ln(1 + decision_load) / ln(101), 0, 1)
footprint_side = 3 + 15 * sloc_n^1.5
footprint_area = footprint_side^2
height = 4 + 36 * cc_n
----

Its color bands remain maximum CC 0-5, 6-10, 11-20, and above 20. Readers
reject altered legacy formula IDs or caps instead of interpreting them as a
new mapping. New analysis emits the versioned Complexity definition.

=== History semantics

One resolved mapping definition applies to every sampled commit in a history
analysis. Each frame evaluates that definition against the facts in that
frame; missing-value behavior is therefore evaluated per frame. The canonical
definition contributes to the metric-configuration and result fingerprints,
so cache entries from different mappings cannot alias.

History configuration accepts a direct `1.0` definition, a
`metricMapping` wrapper containing that definition, or the legacy
`metricMapping: "default-v1"` claim. Other string claims are rejected. The
legacy claim resolves to the exact fixed mapping above before analysis.
Evolution replay retains the frame's complete mapping data, rather than
inferring behavior from the current preset catalog.

== Dependency routes

`A -> B` means consumer A depends on provider B. TypeScript imports connect
buildings; project and package references connect modules. Repeated references
collapse into one weighted edge and self-edges are omitted.

Every rendered endpoint has a surface contact and a route anchor. A building
uses its roof center for both. A district contact is the intersection of its X/Z
rectangle with the center-to-counterpart ray, on the district top; coincident
centers use -Z. `skylineY` is the maximum top Y of the district base and its
visible buildings. The anchor keeps X/Z and uses `skylineY + 0.35`. An
isolation contact uses key `kind + NUL + stable endpoint ID`: `building` plus
building ID, `district` plus district ID, or `external` plus normalized target.
The overflow endpoint uses key `"external-overflow" + NUL + "v1"`.
Hash UTF-16 code units in order, starting at `0x811c9dc5`; for each unit use
`hash = imul(hash xor unit, 0x01000193) unsigned`. `hash mod 4` selects `-Z`,
`+X`, `+Z`, or `-X`;
`0.08 + hash(key + NUL + "position") / 0xffffffff * 0.84` maps along that edge
on the visible district top. Its anchor also uses `skylineY + 0.35`. An external
node uses its roof center for both. A vertical gateway joins each distinct
contact/anchor pair. Browser curves join anchors; no marker may float.
Arrowheads always point to the provider.

The hidden-by-default overview bundles edges by visible district. Selection
expands incoming and outgoing file routes. Both views rank by weight with stable
identity tie-breaking and report omissions. The overview shows at most 24
bundles; selection shows at most 20 routes per direction. Isolation projects
hidden endpoints to grounded boundary gateways.

== External dependencies

Normalize targets with Unicode NFC and surrounding-whitespace removal; remaining
characters, including case, stay significant. Aggregate reference weight by
normalized target. Show at most 12 nodes. With more than 12 targets, show the
strongest 11 by descending weight, then normalized target in ordinal UTF-16
code-unit order, plus an overflow node; report its target count and weight. The
overflow node has internal kind `external-overflow` and display label `Others`.
It cannot collide with a real target named `Others`.

An external node is a fixed `4 x 3 x 2` city-unit box in X/Y/Z, uses semantic
role `external` and color `#111827`, and has no SLOC or complexity. Place nodes
by normalized target in ordinal UTF-16 order, with `external-overflow` last, on
a connected rear apron:

[source,text]
----
margin = gap = 1
apron_width = max(base_width, box_width + 2 * margin)
apron_min_x = base_center_x - apron_width / 2
columns = max(1, floor((apron_width - 2 * margin + gap)
                       / (box_width + gap)))
column = index mod columns
row = floor(index / columns)
x = apron_min_x + margin + box_width / 2 + column * (box_width + gap)
z = old_base_max_z + margin + box_depth / 2 + row * (box_depth + gap)
----

Rows fill in order. The base widens symmetrically only when `apron_width`
requires it, then extends through the last row plus the rear margin. Each box
sits on the new base top. The +Z apron stays separate from the -Z identity
panel. Viewer and exporter share these exact coordinates.

== Scene labels

The scene owns at most two reusable camera-facing labels: transient hover and
persistent selection. If both reference one entity, render one label. A building
label shows its full filename; its selection details show the full normalized
repository-relative path. District labels show the full district name. External
labels show the full target, while overflow details list its count and weight.

Labels never intercept raycasting or affect scene bounds. Reload and clear reuse
or dispose the two textures; no building, district, or external node owns a
texture. Pointer, keyboard, search, and dependency-list selection use the same
details content.

== Camera framing and image export

Camera framing consumes semantic bounds, not the render graph. Whole-city
bounds are the union of the effective base, districts, buildings, external
nodes, and identity panel. District focus contains its stable district and
building geometry plus the external nodes that remain visible; a selected
building or external node uses its own model box. Transient highlights, routes,
labels, hidden helpers, and animated removal meshes are excluded, so fixed
orientations produce the same frame and preserved orientations remain stable.

Perspective and orthographic cameras share a target, normalized view direction,
and up vector. Projection switching converts perspective distance to the
equivalent orthographic view height, or back again, so it preserves orientation
and apparent vertical span. Isometric and top-down presets supply canonical
direction and up vectors. Selected-entity and whole-city presets preserve the
current orientation and replace only the target and fitted distance or view
height.

PNG export creates a camera from the requested semantic bounds and aspect ratio,
renders the Three.js scene at the requested pixel dimensions, reads the resolved
default framebuffer, and restores the live renderer state. A transparent export
uses an alpha-capable, non-premultiplied framebuffer. Selected and hover labels
are projected into image coordinates, and the optional caption and semantic
legend are drawn afterward with Canvas2D. This path never rasterizes DOM
controls or panels. A current evolution frame may contribute its ordinal,
commit SHA, and timestamp after playback has stopped and its transition has
settled.

Width and height are integers in `[256, 8192]`, further bounded by
`MAX_TEXTURE_SIZE`, `MAX_RENDERBUFFER_SIZE`, and `MAX_VIEWPORT_DIMS`. Estimated
working memory per pixel is `16 + 8 * max(1, samples)` bytes, where `samples` is
the active framebuffer's reported sample count; the complete estimate may not
exceed 512 MiB. Legends support all 256 model semantic groups plus the bounded
viewer-owned evolution and external entries, and must fit the requested image
at a readable column width. Capability, memory, legend-fit, context-loss,
readback, and PNG-encoding failures are reported without publishing a partial
download.

== Repository exploration

Search matches normalized repository-relative building paths in the loaded
model; it never reads source text or uses the network. Camera focus does not
mutate the model. District isolation is a reversible visibility filter and
keeps the shared base and identity context visible.

== Determinism

Sort inputs, use stable path IDs, and persist formulas and normalization caps.
Pack up to 64 variable footprints with deterministic corner filling; larger
sets use bounded shelves. Configured gaps remain visible streets.

== Privacy

Do not persist source text, absolute roots, credential-profile selectors,
credentials, remote URLs, requested symbolic refs, or adapter error details.
Default discovery hard-skips `.git`, `.angular`, `node_modules`, `bin`, `obj`,
`dist`, `build`, and `coverage` segments plus generated C# suffixes. Nested
`.gitignore` rules apply; root `.codecityignore` may override them but cannot
override hard skips. A resolved immutable commit SHA may be stored as the
generated model's default version.

== Threat model

Repository bytes, city models, printer profiles, URLs, logos, and worker
messages are untrusted. Protected assets are source, credentials, host paths,
local files, browser origin data, memory, CPU, and output files.

Repository content is data only. Code City does not run hooks, filters,
scripts, builds, restores, generators, analyzers, or repository plugins.
Snapshots never follow symlinks and admit only analyzer inputs. One analysis
allows 100,000 visited entries, 50,000 retained files, 25,000 source buildings,
2 MiB per file, 256 MiB total, 1,000 diagnostics plus one omission summary, and
300 seconds for snapshot plus analysis.

The self-hosted import endpoint accepts only strict, duplicate-free JSON with
exact object keys. It requires `X-Code-City-Request: 1`, rejects encoded
bodies, caps the body at 32 KiB and five seconds, and closes early rejections
instead of retaining a slow body on a keep-alive connection. Inputs are
validated before private staging or job persistence. Jobs retain fixed progress,
fixed safe error codes, and owned artifact URLs only.

Inbound authorization is an explicit deployment boundary, not an inference
from network location or forwarded identity headers. Without a token file, the
existing trusted-network API remains open. With one, every API operation except
health reads and session bootstrap requires either the fixed-entropy root
bearer or an opaque server-side session. Authorization runs before protected
route body handling, so an unauthenticated slow or unexpected body is closed
without staging, queueing, or endpoint discovery.

The root token is loaded once from a stable, bounded, private regular file
before data-directory mutation. It is never accepted through an environment
value, URL, JSON body, cookie, job, or artifact. POSIX ownership and mode are
verified; Windows requires an explicit ACL-and-ancestry trust attestation.
Presented bearer values are decoded into a fixed 32-byte buffer and compared
in constant time. Failure responses do not distinguish missing, malformed,
duplicate, expired, or incorrect credentials. Shutdown overwrites the loaded
key and clears all in-memory session digests.

Browser authorization storage contains only an opaque, random,
bounded-lifetime `HttpOnly` session capability, never the root token or
repository credential. Import recovery may additionally retain one validated
job UUID. It does not retain a repository URL, revision, credential-profile
selector, file name or path, source byte, or generated model. The cookie uses
`SameSite=Strict`, API-only path scope, and `Secure` on every non-loopback
deployment. Existing non-simple mutation headers remain mandatory, including
job cancellation; cookie mutations additionally require the exact configured
same-origin Origin. CORS remains disabled. Health is deliberately anonymous,
cache-free, and contains no authorization or credential-profile state.

Credential profiles form a separate, bounded startup registry. Enabling the
manifest without application-owned inbound authorization fails before the
manifest path is accessed. Exact-shape, duplicate-free JSON binds a stable ID
and display label to one provider, exact repository scopes, and a direct-child
secret basename. Protected directory, canonical path, stable file identity,
ownership/mode or explicit Windows ACL-attestation, link-count, UTF-8,
single-line, count, and byte limits all fail closed. GitHub profiles are
bearer-only and accept one ASCII RFC 6750 `b64token` secret line. Azure DevOps
and Generic HTTPS profiles are Basic-only; the visible-ASCII username cannot
contain a colon, and they require a one-line UTF-8 secret.

Startup records each secret's protected path and security-relevant startup
snapshot: file identity, mode and ownership, link count, size, and modification
and change times. It then overwrites the validation buffer. Canonical credential
and public viewer roots must be disjoint; overlap fails before the viewer asset
collector can retain or expose credential files. The collector additionally
guards the canonical path and filesystem identity it actually opens,
revalidates the traversal roots, and rejects directory, manifest, or secret
aliases before body reads.

The import capability response is an authenticated, no-store redacted
projection, not a credential oracle: only ID, label, and provider cross the
boundary. Scope URLs, usernames, filenames, and secret bytes do not. An
authenticated GitHub or canonical HTTPS Generic Git source may contain one
optional, strict `credentialProfileId`. Before staging, the registry requires
that ID to select the correct provider with an exact canonical
repository-scope match. Unknown, wrong-provider, out-of-scope, non-HTTPS, and
origin-denied selections share one fixed rejection.

Each credentialed job reopens its secret and revalidates the startup path and
security-relevant startup snapshot: file identity, mode and ownership, link
count, size, and modification and change times. It exposes the material to one
bounded callback. Protected-read, validation, and callback-scoped mutable
credential buffers are overwritten after use, including failure, abort, or
registry close. The selector remains only in the in-memory request closure, and
at execution credential material is reread only for that bound use operation.
Neither the selector nor that material enters job or artifact persistence; nor
do the remote URL, requested symbolic ref, or source bytes. The resolved
immutable commit SHA may be stored as the generated model's default version.

Raw uploads avoid multipart parsing and never trust a filename. Exact-shape
metadata reserves one opaque UUID and its declared bytes before the server
creates a private staging directory. The PUT admits exactly one unencoded
`application/json` or `application/zip` body with one matching
`Content-Length`; transfer encoding, concurrent reuse, underflow, overflow,
idle senders, and expired reservations fail closed. Four reservations and
256 MiB of reserved/staged bytes are global hard limits, and quota remains
charged while the upload is queued or running.

The staged body is written once to fixed `upload.bin` with create-exclusive
and, where the platform exposes it, no-follow semantics, owner-only
permissions, portable handle identity checks, payload and directory flushes,
and a second fixed-path identity check. Cleanup waits
until an active writer closes its handle, is idempotent across finalizer and
rollback, and retains quota until removal succeeds. Startup removes abandoned
UUID staging directories. ZIPs are inspected in memory and never extracted:
portable paths, case/Unicode collisions, symlink or file descendants,
compression metadata, CRCs, entry count, compressed, expanded, per-entry, and
analysis deadlines remain bounded. Uploaded city models require fatal UTF-8
and the established runtime validator, then are reserialized through the
artifact store rather than publishing attacker-supplied bytes.

Windows/IIS must place `CODECITY_DATA_DIR`, uploads, and artifacts behind a
service-private ACL even if Generic Git is disabled. Inherited child ACLs must
exclude untrusted identities, and the protected directory entry and canonical
ancestors must prevent untrusted rename, delete, and delete-child access.
Portable Node APIs enforce fixed-path and open-handle identity but cannot prove
or establish those ACL properties.

Generic Git is default-denied at the server boundary. An exact
operator-configured scheme, normalized hostname/IP, and effective port must
match before staging. This origin list is egress control, not per-repository
authorization. A selected HTTPS profile is a second independent gate requiring
the correct provider and exact repository scope. In default trusted-network
mode every client can request any repository/user at an enabled origin;
unselected HTTPS and SSH/scp imports may use the least-privileged service
identity's ambient Git/SSH credentials. Selected HTTPS imports isolate ambient
Git configuration and repository credential helpers and use the chosen profile
for repository authentication. Configured proxy and certificate environment
settings remain trusted dependencies. Enabling inbound authorization gates API
access but does not narrow ambient repository scope. Windows additionally
requires explicit attestations for both the private data/import workspace and,
when profiles are configured, the credential files and canonical ancestry.

The GitHub adapter accepts only canonical HTTPS `github.com/owner/repository`
URLs. Anonymous imports remain available. An exact-scope GitHub profile permits
private and internal repository metadata while retaining exact repository
identity validation. Bearer authorization is attached only to exact HTTPS
`api.github.com` requests. A token used for private or internal archive access
needs repository `Contents: read` permission. No credential is placed in a URL.

The adapter resolves an exact 40-digit commit and requests that commit through
GitHub's documented zipball API with redirect following disabled. It accepts
only one `302` to `codeload.github.com` with the exact path
`/\{owner\}/\{repo\}/legacy.zip/\{sha\}`. An opaque query string is accepted,
and the second request sends no `Authorization` header. All other redirects are
rejected. For selected Azure DevOps or Generic HTTPS imports, the adapter
disables inherited system, global, and user Git configuration, clears ambient
helpers, and supplies the exact Basic profile through a bounded
owner-restricted broker for each remote command. The secret never enters a URL,
argument, environment value, Git configuration, repository, or file. Unselected
Generic Git retains its existing ambient credential behavior.

API responses are capped at 1 MiB, archives at 64 MiB, individual ZIP entries
at 256 MiB, expanded archive data at 1 GiB, and refs at 256 UTF-8 bytes. All
remote work shares the 300-second default analysis deadline. Encrypted or ZIP64
archives, unsafe or colliding paths, and inconsistent ZIP metadata are
rejected. Ignored content is never inflated. Archives and source bytes are not
persisted or cached.

The generic Git adapter accepts validated HTTPS, `ssh://`, and scp-style
remotes without embedded passwords, query data, fragments, or leading options.
For unselected imports, the installed Git client and the user's credential
helper, SSH agent/configuration, and certificate configuration are trusted local
dependencies. The installed Git client remains trusted for selected imports,
as do the resolved .NET runtime and configured proxy and certificate
environment settings. Selected HTTPS imports isolate user/system Git
configuration and ambient repository credential helpers. Code City disables
prompts, tracing, redirects, unsafe protocols, hooks, filesystem monitors,
maintenance, submodules, and LFS behavior for the operation.

Only an advertised branch, tag, or default `HEAD` is shallow-fetched into a
private bare repository. The advertised object is rechecked before a local
`git archive`; no checkout or remote archive command occurs. Process duration
and output, temporary object storage, archive bytes, and the shared snapshot
limits are bounded. Errors omit Git diagnostics, remotes, refs, credentials,
and temporary paths. The bare repository is removed before source analysis;
no remote or derived-model cache remains.

The temporary parent is part of the Generic Git trust boundary. Parent,
workspace, and canonical-ancestor identities are captured with device/inode
metadata and revalidated around path resolution, measurement, Git use, and
cleanup. POSIX roots are process-owned mode `0700`; ancestors must be owned by
root or the process identity and prevent untrusted entry replacement through
permissions or valid sticky-directory semantics. Zero filesystem identities
fail closed.

Portable Node APIs cannot prove Windows ACL inheritance or directory
delete-child rights. Windows therefore has no implicit Generic Git temporary
parent. `--trusted-workspace-parent` attests that the existing parent's ACL,
and inherited child ACLs prevent untrusted content reads, writes, and creation.
It separately attests that the containing directory and canonical ancestor
entries prevent untrusted rename, delete, and delete-child operations on the
protected path entries; ancestors may otherwise permit read or traversal.
Cleanup atomically moves only the captured workspace identity to a private
quarantine name before recursive removal; mismatched replacements are
preserved, and interrupted removal retries the same captured quarantine.

The bundled Roslyn helper parses syntax only, receives opaque source IDs over a
versioned bounded protocol, and runs once per analysis. It never loads a
solution, project, MSBuild, NuGet, generators, or repository analyzers.

`codecity open` binds only to `127.0.0.1`, validates the exact Host header, and
serves a startup-captured viewer allowlist plus one no-store in-memory model.

CLI input is capped at 128 MiB per city model and 1 MiB per printer profile.
Derived JSON is staged with mode `0600`, atomically renamed, and rolled back on
failure. The viewer uses one explicit-load gateway: 128 MiB model, 1 MiB local
profile, 2 MiB logo, and 30 seconds. It rejects redirects and credentialed URLs,
sends no credentials or referrer, and exposes fetched images only through local
Blob URLs. CSP restricts assets to the application and Blob images; executable
checks permit network primitives only in the explicit gateway and prohibit
bundled telemetry, CDN, upload, frame, or object paths. Print workers have a
60-second watchdog and are terminated on every exit.

Residual risks are platform filesystem races that cannot be removed by portable
Node APIs, browser/DNS behavior below the fetch boundary, and slicer behavior.

== Physical identity

The model may carry an explicit title, version, and relative SVG/PNG logo
reference. Layout reserves a compact plaque joined to the center of the front
edge; the viewer previews it, and the print plan preserves its content and
channel assignment. Local analysis may resolve exactly one regular, non-symlink
logo file beneath an explicitly analyzed root. A terminated five-second worker
accepts only bounded transparent, single-solid-color SVG or PNG silhouettes and
stores a normalized, canonical one-bit mask of at most 64 by 64 pixels. It
never stores original markup, absolute paths, URLs, credentials, or converter
diagnostics in the city model.

The exporter fits that mask to the main city panel, resamples it to the printer
profile's minimum feature size, and merges it into at most 256 raised
rectangles. The shared printable-city geometry feeds both 3MF and STL. Missing,
unsafe, ambiguous, or unsimplifiable relief uses the fixed Code City icon and
adds exactly one sanitized preflight and manifest warning; an identity with no
logo uses the icon without a warning. Repository logos remain display metadata.
A multi-repository city has one main panel. Local paths are never inferred as
printed identity. Arbitrary fonts remain separate work.

Printed building labels use `000` through `ZZZ`. Sort ordinally by repository
ID, district ID, normalized path, and building ID; encode the zero-based index
as three-character uppercase base 36. This covers the 25,000-building model
limit. `auto` adds same-channel raised roof glyphs only when they fit; `off`
omits physical labels. Districts use fitting uppercase text or `D` plus the
three-character index from the equivalent repository ID, path, and district ID
sort. A deterministic companion JSON legend records code, repository ID and
name, district ID and name, building name, repository-relative path, and printed
status/reason. Absolute paths, source text, and legend data never enter 3MF.

Binary STL uses the same validated geometry in stable part order. It combines
all channel parts as one multi-shell mesh with outward unit normals. STL does
not preserve colors, tool assignments, or 3MF metadata; preflight reports this
loss before export. Serialization is capped at 500,000 vertices and triangles
(25,000,084 output bytes).

== Print planning

The city model retains semantic groups without a hardware limit. A printer
profile declares build volume, geometry limits, output formats, configured
print channels, their assignment mechanism, and an overflow policy.
Build volume uses city axes: X width, Y height, Z depth. Export maps city
X/Y/Z to printer X/Z/Y.

Geometry limits resolve legacy four-field profiles into explicit nozzle and
line-width assumptions, symmetric X/Y/Z build margins, wall and gap minima,
raised and recessed feature minima, label and route widths, base thickness,
and maximum model height. Omitted fields use documented conservative defaults;
parsed and bundled profiles expose the resolved values.

[cols="2,3",options="header"]
|===
|Omitted field |Resolved value

|`nozzleDiameter`, `lineWidth`
|`minimumWallThickness`

|`buildMargins`
|`{x: 0, y: 0, z: 0}`

|raised or recessed minimum
|`minimumFeatureSize`

|label stroke
|`minimumWallThickness`

|route width
|maximum of feature size and line width

|maximum model height
|build-volume Y minus twice the Y margin
|===

Line width must be from one through two nozzle diameters. Wall, label and route
widths must be at least one line. Twice each margin must leave a positive build
span; base plus raised-feature height must fit the declared maximum height.

The print planner maps semantic groups onto one or more channels. If groups
outnumber channels, it deterministically merges them, produces monochrome
output, or fails, as selected by the profile. Exporters measure transformed
geometry against profile limits and contain no printer-specific tool count.

Printable dependencies are optional and aggregate district/module relations;
file edges are never printed. V1 uses base-connected raised traces in available
street lanes, capped like the overview. Let `feature` be the larger profile
minimum feature size and minimum wall thickness. Trace height is `feature`;
width is `feature` times
`min(3, max(1, 1 + floor(log2(max(weight, 1)))))`; a same-height arrowhead marks
the provider. Unroutable or capped bundles are omitted with reported count and
weight. Traces do not provide structural connectivity for the base. Detachable
connectors remain calibration artifacts: the generated comparison selects the
integrated raised trace because it needs neither clearance nor loose hardware.

The CLI defaults to `--routes off`; `--routes auto` enables this deterministic
geometry without mutating the city model.

The viewer calls the same format-neutral export orchestration in a module
worker. It terminates the worker on cancellation, transfers exact bytes, and
publishes only local Blob downloads.

Multi-plate layout is deterministic and printer-neutral. `scale` keeps one
plate and stops at the profile-safe feature scale; `tile` keeps the requested
scale and packs complete districts with optional 90-degree rotation. Every
plate has one compact continuous base and a plate number. Plate 1 also carries
the identity plaque. A relevant external target is one fixed-size box on each
affected plate, marked as original once and replica thereafter. Cross-plate
routes are not printed; the bundle manifest records consumer, provider, and
their plate numbers. No artifact may exceed the usable profile volume.

Below-profile scaling is an explicit, typed exception to fidelity minima, not
to physical print bounds. With acknowledgement, the planner may maximize one
known-valid packing topology below the safe scale. It deterministically records
requested, applied, and minimum-safe scales and an ordered violation for every
affected feature category (`resultingValue` and profile `minimum`). Without
acknowledgement the same request fails before geometry generation.

The Prusa XL one-, two-, and five-tool configurations are profiles of the same
model.

The deterministic calibration plate contains a shared base, one marker per
configured channel, and measured coupons for every resolved feature limit.
Its JSON manifest maps coupon IDs and print-space bounds to each measurement.
Profile axes are X width, Y height, Z depth; print axes are x=X, y=Z, z=Y.
Measure wall, gap, raised and recessed references after slicing and printing;
adjust the profile before exporting a full city.
