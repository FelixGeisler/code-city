= 8. Cross-cutting Concepts

== One semantic model

Repository, module, district, and source-file identities form the city hierarchy.
A versioned metric mapping turns analyzer facts into footprint, height, and color.
The complete mapping and its provenance travel with the city model, so viewer,
history, publication, and print do not reinterpret a preset name independently.

Dependencies point from consumer to provider. Browser routes and printable routes
use the same semantic edges but different presentation geometry. Fine-grained
source declarations and findings remain inspection data; physical export stays
at file and district granularity.

== Determinism and compatibility

Stable identities, canonical input ordering, explicit formulas, and deterministic
layout and serialization make equivalent input produce equivalent output.
Readers validate known model/evolution versions and reject incompatible claims.
Additive optional model data may enrich inspection without changing older core
semantics.

== Untrusted data and privacy

Repository bytes, models, profiles, URLs, logos, worker responses, and extension
data are untrusted. They are parsed as data under byte, count, time, and memory
ceilings. Repository hooks, builds, package restores, generators, analyzers, and
plug-ins are never run. Snapshot paths are normalized and cannot escape their
source boundary.

Source text is absent from city models, print artifacts, legends, jobs, and
publications. Remote URLs, requested symbolic refs, credential selectors,
credentials, local absolute paths, and raw diagnostics are not persisted. An
immutable commit identifier may remain as model provenance.

== Authorization and credentials

Inbound authorization, outbound destination policy, and repository credentials
are separate controls. Authorization decides who may call the private API.
Allowed origins decide where Generic Git may connect. Credential profiles decide
which exact repository one administrator-owned credential may access.

Credentials are never accepted in repository URLs or speculative browser
requests. Provider-specific adapters constrain where authorization is attached,
and credentialed Git operations isolate ambient helpers when a profile is used.
Published snapshots are the deliberate exception to private API reads: anyone
who can reach the deployment may read them.

== Isolation and bounded work

Durable imports run through a bounded queue. Browser analysis, evolution,
extensions, image preparation, and print preparation use dedicated workers or
lazy modules where responsiveness or cancellation requires isolation. Worker
responses are validated as untrusted data before application. Starting newer
work cancels or supersedes older work rather than allowing stale publication.

Hard resource ceilings are part of the architecture. Raising a ceiling is not a
substitute for streaming, structural sharing, instancing, bounded indexes, or
explicit backpressure.

== Explainability and accessibility

Metrics retain formula and normalization provenance. Findings name their rule,
evidence, severity, and unavailable facts and are presented as heuristics, not
quality verdicts. Selection is synchronized between the scene and accessible
hierarchy/result views. Color is supplemented by text and symbols. Rendering
failure has an accessible state and does not discard loaded project data.

== History and immutability

Representative history stores one validated baseline plus identity-based deltas.
Playback is direct-seek and path-independent. Published versions are independent
immutable copies; a latest link selects the newest explicit publication while a
version link remains stable. Import deletion and publication deletion are
separate lifecycle operations.

== Physical export

The print planner consumes semantic groups, coordinates, and a printer profile.
It validates usable volume and feature constraints, maps groups to configured
channels, and either produces a complete plan or fails explicitly. STL and 3MF
serialize the same validated geometry. Multi-plate planning keeps district
placement deterministic and reports omissions; calibration remains an operator
responsibility.
