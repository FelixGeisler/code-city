== Critical passages

[cols="2,3,2"]
|===

|Every transport reaches bounded snapshot analysis; C# and TypeScript facts,

|Analyzer, snapshot, Git, model-validation, and golden tests

|Authorized import to durable artifact
|Requests are authorized before staging; credentials remain isolated; terminal

|The documented launcher imports 100 real GitHub commits, opens 100 frames, and

|Selection, hierarchy, findings, queries, source detail, evolution, capability

|Planning respects profile limits and deterministic geometry; STL, 3MF, plates,

== Verification layers

`npm run verify` is the local structural gate: release identity, type checking,
unit/integration tests, production builds, bundle budgets, and documentation.
CI runs it on Linux and Windows, audits production dependencies, and runs the two
Chromium browser suites separately. Container CI validates the packaged runtime.
The tag workflow repeats release-critical checks before creating a GitHub
release.

The suites favor observable contracts and deterministic barriers over retries or
inflated timeouts. Platform-conditioned tests run on the corresponding Linux or
Windows matrix member. Chromium with WebGL 2 is the automated browser baseline;
other browsers are not claimed as tested 1.0 targets.

== Operator acceptance

Automation cannot validate a particular reverse proxy, filesystem ACL, backup
location, slicer, or printer. Before production use, the operator must run the
clean-deployment, persistence, backup/restore, and print checks in
xref:14-release-and-operations.adoc[Release and operations].
