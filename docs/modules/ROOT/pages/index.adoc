= Code City Architecture

== Purpose

Code City turns a software repository into an explorable 3D city and a physical
model. It helps people inspect structure, complexity, dependencies, and change
without building or executing repository code.

It imports Git repositories, source folders or ZIPs, and existing Code City
models. Syntax-aware analysis supports C#, TypeScript, and JavaScript. Users can
explore the result in a browser, export images or print files, and publish a
sanitized read-only copy.

== System idea

Code City converts every supported source into the same bounded, read-only
snapshot. Language analyzers extract facts without running repository tooling.
A versioned mapping turns those facts into one validated city model. The
browser, history view, publication store, and print exporter all use that model.

Imports run as durable jobs. Expensive browser work runs in cancellable workers.
History records changes to stable model identities. Print planning uses an
explicit printer profile. Publication creates a separate sanitized copy rather
than exposing private import data.

== Constraints

* Repository content is untrusted data and is never built or executed.
* Local analysis and viewing work without a network connection.
* Remote repository access is explicit and restricted by deployment policy.
* The production deployment is one non-root Linux container with persistent
  storage and no required external database or queue.
* Browser rendering requires WebGL 2. Chromium is the automated 1.0 baseline.
* Inputs, processing, stored artifacts, and outputs have hard resource limits.
* Print output must fit the selected printer profile.

== Quality goals

. Explain findings and expose missing information instead of presenting opaque
  quality scores.
. Produce reproducible models and exports from equivalent input.
. Protect credentials and private repository data.
. Remain bounded on modest self-hosted hardware.
. Keep analysis, browser, history, publication, and print consistent by sharing
  one model.
