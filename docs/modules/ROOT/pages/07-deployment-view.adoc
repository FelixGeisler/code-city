= 7. Deployment View

[cols="1,2"]
|===
|Mode |Deployment

|Offline
|Self-contained CLI and static viewer with an export worker

|Raspberry Pi
|One non-root ARM64 container serves the viewer and API and provides a bounded
persistent job queue backed by a mounted data directory

|Hosted
|The same AMD64 container runs on a web host; the initial single process can be
split into web and worker commands later without changing the API or job model

|Enterprise
|CLI or container on a self-hosted build agent

|Documentation
|Antora site deployed by GitHub Actions to GitHub Pages
|===

The initial self-hosted deployment uses `docker compose up --build`, publishes
container port 3000 as host port 8080, and mounts the `code-city-data` volume at
`/data`. It has no mandatory database, message queue, reverse proxy, or cloud
dependency.

Authorization is disabled by default. Publish that trusted-network mode only
on a private network. IP-literal requests and `localhost` are accepted by
default. Set `CODECITY_ALLOWED_HOSTS` to a comma-separated list when clients
use DNS names; other hostnames are rejected to prevent DNS-rebinding access.

Application-owned authorization uses no database or identity provider. Set
`CODECITY_AUTH_TOKEN_FILE` to an absolute private file containing one canonical
32-byte base64url token and set `CODECITY_PUBLIC_ORIGIN` to the one externally
visible HTTPS origin. The configured origin hostname is admitted by the Host
policy; a non-default public port must also occur explicitly in the Host
header. The server then protects the complete versioned API except health reads
and the session bootstrap. The long-lived bearer can authorize automation or
be exchanged for one bounded opaque browser session. Repository credential
profiles must not be configured unless this mode is active.

Set `CODECITY_CREDENTIAL_PROFILES_FILE` to one absolute version-1 manifest path
only after inbound authorization is enabled. The manifest and all referenced
one-line UTF-8 secret files must be direct children of the same private
directory. POSIX requires a process-owned mode-`0700` directory and
process-owned, single-link regular files with mode `0400` or `0600`. Windows
requires equivalent private ACLs and protected canonical ancestry plus
`CODECITY_TRUST_WINDOWS_CREDENTIAL_FILES=1`. Reads are size-bounded and verify
canonical path and file identity before, during, and after opening.

Profiles allow only `github`, `azure-devops`, or `generic-https` and enumerate
exact repositories. GitHub repository identity is case-insensitive after its
canonical public URL is validated. Azure cloud, legacy `visualstudio.com`, and
on-premises forms require one literal penultimate `_git`. Generic HTTPS
normalizes only a valid canonical authority; its raw path, case, uppercase
percent encoding, and terminal `.git` remain exact. The authenticated
`/api/v1/imports/capabilities` projection contains only ID, display label, and
provider.

The current implementation validates and advertises profiles but does not
accept `credentialProfileId` or inject credentials into Git. The Compose file
forwards the manifest path and Windows attestation only; it does not mount
secrets. Supply an explicit read-only private mount owned by runtime UID 10001
and never use environment values, remote URLs, repository files, or Git config
for secret material.

On POSIX, the token file must be process-owned, mode `0400` or `0600`, regular,
non-symlinked, and have one link. Its identity is checked around a bounded
read. Docker mounts must make the file readable only by the runtime UID 10001;
the Compose environment value names the path inside the container and does not
mount a host secret automatically. On Windows/IIS, apply a service-private ACL
to the file and protected canonical ancestry, then set
`CODECITY_TRUST_WINDOWS_AUTH_TOKEN_FILE=1`. Portable Node APIs cannot verify
that ACL. Raw secrets are not accepted in environment variables. Rotate the
file through a restart, which also revokes all sessions.

The Node server remains HTTP internally. Azure Web App and IIS normally
terminate external TLS. A credential-enabled Raspberry Pi deployment likewise
needs an HTTPS terminator; unauthenticated trusted-LAN mode does not. Bind or
firewall the backend so only the terminator can reach it, preserve the external
Host, and do not treat `Forwarded`, `X-Forwarded-*`,
`X-MS-CLIENT-PRINCIPAL`, or Windows identity headers as authorization. Any
future trusted-proxy identity mode needs a separate backend-isolation trust
boundary. Redact `Authorization`, `Cookie`, and `Set-Cookie` from ingress and
platform logs.

Upload reservations share the same trusted-network or configured authorization
boundary as the rest of the API.
The server admits at most four reservations and 256 MiB of staged data across
reserved, receiving, queued, and running uploads. Individual city-model and
ZIP bodies are limited to 128 MiB and 64 MiB respectively. Unused reservations
expire after five minutes; body idle and total deadlines are 30 seconds and ten
minutes. Staging is owner-private beneath `CODECITY_DATA_DIR/tmp/imports`,
contains only a server-chosen fixed filename, and is swept during startup.
Size and concurrency limits are intentionally hard deployment safety limits,
not client-controlled analysis options.

Windows/IIS deployments must protect `CODECITY_DATA_DIR` for uploads and
artifacts even when Generic Git is disabled. Its ACL and inherited child ACLs
must admit only the service identity and trusted administrators. The data
directory entry and canonical ancestors must also prevent untrusted rename,
delete, and delete-child access. Code City uses create-exclusive files and
portable fixed-path/handle identity checks, but cannot create, repair, or prove
these Windows ACL guarantees.

Generic Git imports are default-denied. Set `CODECITY_ALLOWED_GIT_ORIGINS` to a
comma-separated list of exact origin-only URLs such as
`https://dev.azure.example,ssh://git.example:22`. There are no wildcards;
scheme and effective port are part of the match. The Compose file forwards this
variable with an empty default.

This allowlist is egress control, not per-repository authorization. In default
trusted-network mode, every Code City network client can request any
repository/user at an enabled origin and invoke the service identity's ambient
Git credential helper, SSH agent/configuration, and trusted CAs. Enable Generic
Git only when every network client is authorized, or enable the application
authorization boundary, and grant the service identity only the minimum
repository access it needs.

For Azure Pipelines, prefer the already authorized local checkout:

[source,yaml]
----
steps:
  - checkout: self
    persistCredentials: false
  - powershell: >
      npm run cli -- analyze "$(Build.SourcesDirectory)"
      --output build/city-model.json
----

The convenience `analyze-git` flow uses the agent's installed Git credential
helper, SSH agent, and enterprise certificate configuration. Do not place
credentials in the remote URL. Configure SSH host keys and the agent for
non-interactive access first; HTTPS enterprise CAs must already be trusted by
Git.

On Windows, provision a dedicated workspace directory before using
`analyze-git`, restrict its ACL and inherited child ACLs to the Code City
service identity and trusted administrators, and protect its canonical
directory entry plus every ancestor from untrusted rename, delete, and
delete-child rights. Then pass it with
`--trusted-workspace-parent <directory>`. This flag explicitly attests those
deployment properties; Code City does not create the directory or repair its
ACL. Ancestors may remain readable or traversable; their protected child entries
must not be replaceable or removable by untrusted identities. Do not point the
option at a generally writable `%TEMP%`, shared build directory, or upload
directory.

For the Windows/IIS server endpoint, set
`CODECITY_TRUST_WINDOWS_GIT_WORKSPACE=1` only after applying the same controls
to `CODECITY_DATA_DIR`, its `tmp/imports` descendants and inherited child ACLs,
and protected canonical ancestors. A non-empty Git-origin allowlist makes
Windows startup fail unless this explicit attestation is present.
Outbound-origin approval does not imply filesystem trust.

On POSIX, an explicit workspace parent must already exist, be owned by the
effective process user, and have exact mode `0700`. The implicit OS temporary
directory remains available only when Code City can verify stable filesystem
identities and a protected canonical ancestry; unsafe environment overrides
fail closed.
