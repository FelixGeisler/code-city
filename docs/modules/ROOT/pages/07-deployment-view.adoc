= 7. Deployment View

== Supported shape

[source,text]
----
Browser --HTTP/HTTPS--> Code City container --optional--> Git providers
                              |
                              +--> /data (private persistent volume)
                              +--> administrator secret files (read-only)
----

The supported release artifact is one non-root Linux container for AMD64 and
ARM64. It serves the viewer and API, runs one bounded job queue, and stores jobs,
artifacts, optional retained source, and publications under
`CODECITY_DATA_DIR` (`/data` in the release image). It needs no external database,
message broker, CDN, or telemetry service.

A reverse proxy may terminate HTTPS, but proxy identity headers are not
application authorization. Preserve the external Host, isolate the backend, and
redact authorization and cookie headers from logs.

== Trust modes

The default is convenient trusted-network mode: the API is open to clients that
can reach it. Bind or firewall this mode to a private network.

For broader access, configure a private `CODECITY_AUTH_TOKEN_FILE` and exact
`CODECITY_PUBLIC_ORIGIN`. The root token can authorize automation or be exchanged
for a bounded browser session. Health remains public. Credential profiles are
allowed only inside this authorization boundary.

`CODECITY_CREDENTIAL_PROFILES_FILE` names an administrator-owned manifest whose
secrets are private files, not environment values or browser inputs. Profiles
are provider-compatible and scoped to exact repositories. Generic Git is
separately default-denied until `CODECITY_ALLOWED_GIT_ORIGINS` lists exact
origins. An unprofiled Generic Git import may use the explicitly configured
service identity; profiled HTTPS imports isolate ambient repository credentials.

The server validates protected files and directories as far as portable APIs
allow. Windows deployments require explicit trust attestations after an
administrator applies private ACLs. These attestations do not create or repair
ACLs.

== Data boundaries

* `/app` is immutable and root-owned in the release image.
* `/data` is writable only by the unprivileged runtime identity and must be
  included in cold backup, retention, and deletion policy.
* Authorization and repository secret files are mounted separately, read-only,
  with restrictive ownership and permissions.
* Source retention is disabled by default. Enabling it makes `/data` contain
  private repository source.
* Published model/evolution bytes are intentionally public, but remain sanitized
  and separate from imports and retained source.

== Deployment modes

[cols="1,2"]
|===
|Mode |Use

|Local development
|`npm run viewer:dev` starts the real viewer and API on loopback with private
local development data

|Self-hosted container
|Recommended production shape on a workstation, server, or Raspberry Pi-class
ARM64 host

|Build agent / CLI
|Analyze an already authorized checkout and emit artifacts without running the
shared server
|===
